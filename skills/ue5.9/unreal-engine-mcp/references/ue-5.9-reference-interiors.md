# 按照片搭建可编辑室内关卡

适用于把建筑或室内参考图做成 UE 关卡，包含可移动的道具、可调材质和可复看的参考机
位。以下 MCP 路线在 UE 5.9 Preview CL 60351404 的窗边厨房验证过。首先在目标工程
的 Asset Registry 按用途、类和项目命名查找模型，核实候选的尺寸和材质槽。为缺少的
部件建模，保留可复用的成品资产。

## 在细化前验收灰模

1. 先摆围护、窗洞、台面孔口、柜体体块和设备占位，放置真实 PlayerStart 与参考相
   机。保留决定通道和遮挡的高度、碰撞与枢轴。统一灰材质写在**关卡组件**上。用一
   张独立地图分离摆设、锅具和植被，同时排除这些物体的碰撞。
2. 从参考相机拍一张灰模图，检查窗洞、台面、上下柜的位置。在游戏 world 以项目实际
   角色沿通道走到远端、掉头并走回，逐段读位置、控制器和落地状态。用角色胶囊朝阻
   挡方向扫掠，记录命中组件、距离和法线，再检查对应网格的简单碰撞。灰模通过后可
   沿用这套相机、行走路点和结构基准做细化。
3. 已经细化的工程也可回测。在本例的独立灰模地图中保留了 27 个结构或设备模块，移
   除了 31 个模块。初测仍在过道中途遇阻。合并成一个网格的三条台面挡水条具有横跨
   通道的自动凸壳。只为候选地图复制这个静态网格，用其 900 个三角形做精确查询碰
   撞。重载后，角色从 X=20 cm 走到约 235 cm 并回到入口，全程受控、落地。该值来自
   已完成设计的灰模回测。新项目宜在装饰建模前运行同样的检查。

## 从照片确定空间与机位

先取一个可信的实物尺寸作比例基准，例如台面深度。照片上标出不同深度的结构交点，如
远处窗框四角、中景台面转角和近处柜门底角。植物叶尖、反光和圆锅底部的轮廓适合做低
权重的辅助点。记录原图尺寸与裁切，按同一画幅先摆墙、窗洞和柜体，用第一张 UE 渲染
与原图并排看。单图无法唯一确定尺度，推算出的进深和画外布局按设计估值交付。

窗框和近景家具同时偏向一侧时，先核对相机位置、朝向及水平 FOV。远处窗框已对齐、只
有前景不合时，再查通道宽度、物件枢轴或摆位。厨房收窄过道时平移了右侧整排柜体，保
留台面深度，并将炉架、锅身、锅盖成组平移，使圆锅保持圆形。局部开孔与嵌入件共用尺
寸，例如台面孔口、槽沿和盆底，窗洞、玻璃和窗框。

### 用像素误差复核相机

有世界坐标与照片对应点时，可用
[离线机位拟合脚本](../scripts/fit_reference_camera.py)。输入为 UTF-8 JSON。下例
是可运行的模拟数据。单位为 UE 厘米，X 向前、Y 向右、Z 向上。像素从左上像素中心
`(0,0)` 起算，`fOV` 为水平视场角（度）。初始机位须朝向标出的地标。

```json
{
  "imageSize": [800, 600],
  "camera": {"location": {"x": -10, "y": 2, "z": 105}, "rotation": {"pitch": -1, "yaw": 1, "roll": 0}, "fOV": 94},
  "points": [
    {"name": "windowTL", "ueCm": [400,-80,200], "photoPx": [319.5,199.5]},
    {"name": "windowTR", "ueCm": [400,80,200],  "photoPx": [479.5,199.5]},
    {"name": "windowBL", "ueCm": [400,-80,100], "photoPx": [319.5,299.5]},
    {"name": "worktop",  "ueCm": [200,50,70],   "photoPx": [499.5,359.5]},
    {"name": "skirting", "ueCm": [160,-40,0],   "photoPx": [299.5,549.5]},
    {"name": "handle",   "ueCm": [300,60,160],  "photoPx": [479.5,219.5], "weight": 0}
  ]
}
```

在本技能目录执行 `python scripts/fit_reference_camera.py anchors.json`。拟合需要
NumPy、SciPy 和至少四个不同、未全部共线的正权重点。只标正对相机的一面墙，前后移
机位和改变焦距都能得到相同画面。补一个更近或更远、偏离画面中心的地标可提供深度约
束。加 `--evaluate-only` 可仅用 NumPy 检查给定机位，权重为 0 的点只做独立检查。
`offsetPx` 是预测减标注的横纵像素差。脚本固定模型尺寸和相机滚转，采用居中、方形
像素的透视投影。移轴、明显镜头畸变或偏心裁切需另行校正。

将候选机位保存在关卡中。通过 `LevelToolset.AddToSceneFromClass` 放置
`/Script/Engine.CameraActor`，将输出的位置、旋转写入 actor 的世界变换。用
`ActorToolset.GetComponents` 找到 CameraComponent，按实时属性 schema 设置
`fieldOfView`、`aspectRatio=原图宽/高` 和 `bConstrainAspectRatio=true`。保存该地
图，回读变换、水平 FOV 和画幅。用这个相机实渲后，再去对照原图的遮挡和轮廓。

拟合误差下降时，再看未参与拟合的交点。远窗稳定、柜门接缝仍偏时，锁定已保存机位，
分别标出接缝两侧的门角。调整局部模块后，在 UE 实渲图上复量原先未用于定尺寸的把手
或轮廓，并注明仍无法判读的位置。
[机位与柜体的独立复测](ue-5.9-reference-camera-qa.md)

## 分件导出与原生摆放

1. 按关卡中需要单独移动或换材质的部件确定模块，选择便于摆放的局部枢轴。导出已摆
   好的场景 GLB 供交付，同时导出局部原点的模块 GLB 供 UE 建资产。摆位表分别记录
   网格名、局部包围盒、材质槽名，以及每个实例的标识和 UE 厘米坐标下的变换。同一
   把椅子的多个实例可以引用同一个网格。用一个有明确朝向的部件先核实单位、轴向和
   枢轴。
2. 读取 `StaticMeshToolset.ImportFile` 的实时 schema。在自有候选资产目录首次导入
   模块版时，使用绝对 `sourceFile`、`bCombineMeshes=false`、
   `bReplaceExisting=false`，按需打开材质和纹理导入。按返回的 `refPath` 和 Asset
   Registry 中的资产类对应网格、MI、纹理。用完整对象路径区分同名资产。
3. 对照摆位表检查网格的 `GetBounds`（局部空间）和 `GetMaterialSlots`。用
   `LevelToolset.AddToSceneFromAsset` 放置模块，按摆位表施加一次世界变换。对悬
   挂、嵌入和台面物件设置 `bSnapToGround=false`。保存返回的 actor 路径，重跑时先
   在目标地图核对已存在的实例和网格引用，防止重复放置。
4. 保存指定包。在自有编辑器查清 dirty 包后，用 `LoadLevel` 的
   `unsavedChangesPolicy=Fail` 切至另一张地图再载回。重新查找实例，核对文件夹、
   世界变换、组件的 `staticMesh` 和 `overrideMaterials`。将网格
   `staticMaterials` 中的槽名与实际材质对象逐一对照预期引用，组件有意覆盖的槽按
   关卡设计校验。重导入后色泽变化时查
   [导入材质实例](../../unreal-material-artist/references/ue-5.9-material-mcp.md#reimported-gltf-material-instances)。

程序化模型保留建模源和摆位表。可复现性可在独立目录重建后对比场景 GLB、模块 GLB、
贴图和清单。对确定性导出器，可直接比较文件哈希。比较导出和 UE 三角数时记录 LOD
与 Nanite 状态，区分源网格和渲染用替身。

再次导入前，用旧源、修订源、编辑器实采值生成差异预览，标出源更新、关卡手调和冲
突。选定需要修复的 MI 字段，重读后保存，再跑同一计划检查写入次数。摆位、插槽和组
件覆盖保留在审核表中。[重导入命令与实机范围](ue-5.9-reimport-reconciliation.md)

## 检查光照、碰撞与行走

- 用窗格在地面上的投影判断**主光方向与阴影软硬**，固定曝光后再平衡窗外、室内补光
  和柜底灯。窗玻璃、窗框和背景分件，便于查出遮住主光的网格。主机位检查构图，近景
  检查金属槽沿、釉面反射和接触阴影。显式 Lit 抓图过曝或画幅异常时，从已保存的相
  机复拍。
  [固定曝光与相机画幅](ue-5.9-canvas-generation-render.md#固定曝光与相机画幅)
- 用 `LevelToolset.TraceWorld(start, end)` 检查**碰撞**。在该构建，命中返回沿线
  距离，未命中的解包结果为 `null`。对地板、墙和台面取预期命中的射线，沿过道取预
  期畅通的射线。对带孔台面，分别向下测台面与孔心，用各自的 `起点 Z − 命中距离`
  得到高度。如果孔心也落在台面高度，分别检查源模型的开孔和覆盖孔口的碰撞体。
- 需要**第一人称通行**时，在入口留出角色胶囊的空间并设置 PlayerStart。在自有测试
  实例启动 PIE，从游戏 world 读项目角色、控制器、位置与
  `is_moving_on_ground()`。角色胶囊可以检出单条射线测不到的过道净宽或出生点问
  题。结果注明实际走过的路段和运行方式。

用同一相机做灯光 A/B 时保留手动曝光、画幅、渲染分辨率和后处理。以独立编辑器的
pilot 对象路径及 MRG 返回的相机姿态、FOV 和输出尺寸核实机位。先重复拍一张基线，
检查暗边、过曝和诊断文字，再单独改一组参数。可从地面窗影同一条扫描线比较明暗过渡
和能否辨出窗棂，从炉台近景比较墙面的暖色与锅身高光。实测太阳光源角度从 0.67° 调
到 1.25°，窗格边缘柔化且横档可辨。2.5° 候选使横档过淡。两只烟机灯从各 75 lm /
3350 K 改为 135 lm / 2950 K，固定墙面区域平均红、绿、蓝分别增加约 7、5、2 个 8
位灰阶。

釉面砖、石英台面和不锈钢分别检查近景与主机位。需要测帧时间时，转到实际渲染的独立
包，使用同一路线、相同输出设置并记录每帧采样。
