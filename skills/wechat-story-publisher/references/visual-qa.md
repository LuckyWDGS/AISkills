# 人物动作、气泡与透明度复核

用于漫画成品、多人互动和用户反馈后的全篇复审。以当前导出的最终图片为对象，保留画风和合理的简化；不要为凑问题把正常的侧身、遮挡或透视改坏。

## 检查材料与尺度

- 查看全部最终页，而非只查曾报错的页。整页看关系，局部看连接，连续阅读看动作与道具状态。
- 局部图从当前文件重新截取，保留肩、肘、躯干或接触物的上下文。单独放大一只手，无法证明它接在正确人物身上；插值放大也不会补出原图没有的细节。
- `qa_preview.py` 会从当前成品生成 `crops/`（每个气泡与 `review_regions` 带上下文）和 `narrow/`（390px 本地模拟）；把手、交接点、关键道具写进页表的 `review_regions`，就不会漏截。
- 另外按目标阅读宽度查看完整一页，例如 390px 的本地模拟，并注明实际尺寸。缩略联系表、局部放大和实体手机测试各有范围，不相互替代。
- 记录页/格、人物或区域、观察、处理及最终文件版本/哈希。看不清的关键部位标记待查，不能据此判“正确”；无字底图通过也不代表加完气泡后通过。

## 逐人追踪肢体与动作

| 检查对象 | 看图方法与常见问题 |
| --- | --- |
| 双臂归属 | 沿每人的“肩 → 上臂 → 肘 → 前臂 → 腕 → 手”分别追踪；检查袖口、身后藏手、胸前残留手、交叉手臂和相邻人物重叠。仅数到两只露出的手仍可能有第三条手臂。 |
| 手与手指 | 看拇指所在侧、掌背朝向、手指分叉/融合、腕部折角和抓握方式。遮住或握住的手指不必五指全露；关键是可见结构与遮挡能解释，而非机械计数。 |
| 头颈与视线 | 将脸朝向与颈部落点、双肩、胸背和骨盆方向一起看。回头可伴随转肩；警惕脸转向身后而颈部/躯干仍完全反向、下巴接错位置、头漂在衣领外。 |
| 站坐与行走 | 看支撑脚/座面、重心、膝脚方向及四肢摆动能否共同完成动作。避免为了让脸对着读者，制造倒走、腿互穿或不可能的扭身。 |
| 动作与物体接触 | 检查手指是否实际够到按钮、手机由哪只手支撑、钥匙在谁的掌中、手是否落在桌面、包带是否连接肩和包体；区分“靠近/犹豫”“按下”“已松手”等剧情阶段。 |
| 交接与连续性 | 物品递出、接到、放下、背起之后，所有权与位置须随动作更新。关键道具除颜色外，也核对轮廓/尺寸和数量；不要让人物一直背着包却再次领取同一个包。 |
| 同页分格换景 | 将格间的地点、朝向和道具状态连起来读。已经离场或完成交接后又出现原场景时，要能判断是回去、换机位还是回忆，避免无过渡的镜头让动作顺序倒置。 |
| 叙事界面 | 剧情依赖付款、时间或提示状态时，确认画面或配文确实呈现对应结果，不能用空白屏幕或准备操作的动作代替“已完成”。选用可读界面、清楚图标或必要配文，避免堆放无法辨认的小字。 |

清楚的多肢、错接、穿模、反向扭颈或错误交接需要修复。画风简化和被合理遮住的部位按画面判断；无法确认时扩大上下文或查看底图，不把猜测写成已验证缺陷。

## 逐句核对气泡

1. 先从对白/页表确认“谁在何格说这句话、对谁说、在动作前还是动作后”，再看成图。不能按哪个位置空就把气泡放给最近的人。
2. 气泡尽量靠近说话人，尾巴方向应清楚指向其头部附近或明确的声源区域，并与相邻人的头、手和气泡区分。尾巴不必碰到嘴，但不要指向无关人物、关键道具或下半身，也不要为了连接而横穿他人的脸。
3. 同格多人时逐条检查“气泡 → 尾巴 → 人物”；人物标签可辅助辨认，不能弥补尾巴错指。电话、通话器、画外音明确标注来源，不能被误读为画面里另一个人开口。
4. 按实际阅读顺序读一遍：上到下、同层通常左到右。问句在前、回应在后；尾巴、框体和文字留在所属分格，避免跨格串话或多条尾巴交叉。
5. 在完整一页和窄屏下检查：不遮脸、关键手势/按钮、交接点和叙事文字；不裁字、不贴边，不出现单字孤行或标点起行。文字多时优先换行、移位或调整框形，不能一味缩小字号。

`compose_bubbles.py` 只按页表排版：说话人和尾巴指向写错了，脚本照样画得很整齐。对话归属错误优先改页表中的 `box`/`tail` 后重新合成；仅当人物位置或画面本身无法支持对白时才修底图。移动一个气泡后重新看全页的阅读次序、遮挡与留白。

平台可能在发布时另加账号水印。根据当前平台预览或已发布样本确定避让区域，不把对白、尾巴和关键手势放在该处；不能照搬某一篇的固定坐标。回读草稿未出现水印时，记录这一差异，避免把草稿像素一致当作发布后可读性的保证。

## 透明度与文字分别验收

- 对需要透底的气泡，框体与尾巴采用一致的半透明填充，文字保持清晰的不透明颜色。不要把整个文字层一起降低 opacity，造成字也发灰；多次叠加尾巴/框体时留意接缝和局部变深。
- `compose_bubbles.py` 已按上述方式合成（框体与尾巴共用蒙版、文字最后不透明绘制），并报告每框的填充不透明度、背景纹理和最低对比度；告警 `textured_background_shows_through` 或 `low_contrast` 时按下文逐框调整。
- 区分“不透明度”和“透明度”。例如 alpha 160/255 表示约 63% 不透明、37% 透明，只是一个可试值，不能固定为所有画风的标准。
- 实际查看浅色墙面、深色衣服和高纹理背景上的气泡：能看出底图，又能轻松读字才算合适。参数存在不等于合成正确；只在空白墙面测试也不足以验证复杂背景。
- 逐框根据背景调整位置、填充或局部对比度。若透底导致花纹穿字，先避开复杂纹理或增加该框不透明度；不为追求统一数值牺牲可读性。用户要求透底时，不把全篇改成实心白框。
- 最终 PNG 可以是 RGB 或 alpha 全满：半透明气泡已经与底图合成后，仍然有透底效果。应比较叠加前后区域和实际像素，不能仅凭最终文件有无 alpha 通道判断气泡是否透明。

## 修复与回归

先修影响人物归属、动作因果和阅读的明确错误。排版问题局部调整；肢体/姿态问题用必要的角色与场景参考修底图，明确两条手臂各自的动作、遮挡和接触关系。只写“不要多手/不要扭头”的负面词不能代替空间说明与成品复核。

每次修复保留旧版，复看改动区域以外的脸、手、服装、道具和邻近气泡，防止局部修手新增一只手或修头改变人物身份。再看改动页、受影响邻页与全篇关键动作链，并重建对应窄屏预览。

审核结论绑定实际检查的版本/哈希。图像尺寸、渲染参数和哈希校验只能验证技术状态，不能证明解剖或对白正确。改图后更新清单、阅读器和发布包；若已存草稿，更新原草稿并按 [上传与回读](visual-and-draft.md#上传与回读) 重新验证，旧远程一致性结论不能继续用于新图。

复查时先重新核对平台状态。若作品已由用户发表，区分线上版本、待用校样与后续制作规则；本地校样不自动覆盖已发内容，也不能把旧的“待发表”记录继续当作当前状态。
