# 账号数据复盘

用于“看看公众号数据”“方向要不要调”“复盘最近几篇”。复盘只读取后台数据：不改草稿、不删除、不发布、不改设置。登录、扫码由用户完成；用户说已在某个浏览器登录时，就用那个浏览器。

## 取数顺序

入口名称以当次后台实际界面为准；下面是数据所在的位置，不是固定坐标。

1. **首页**：账号名称、总用户数、昨日阅读/分享/新增关注，以及页面上写明的统计时间。先核对账号名称是不是要复盘的那个号。
2. **发表记录**：全部近期内容的标题、发表时间、状态（已发表/已删除）和列表上的实时计数。已删除的内容也要记下，它们会影响“发了几篇”的口径。
3. **数据分析 → 内容分析**：选定时段的阅读总人数、流量来源占比（推荐、公众号消息、聊天、朋友圈、主页、搜一搜、其它）和各篇阅读人数。
4. **单篇详情**（内容分析列表里每篇的详情）：阅读人数、平均阅读时长、新增关注、分享、收藏、留言、阅读渠道构成、性别/年龄/地域画像；普通文章另有完读率。阅读人数太少时后台不展示画像，照实记“未展示”。
5. **用户分析**：粉丝有一定数量后再看净增和来源；粉丝只有个位数时略过并说明。

单篇详情通常在新标签页打开；逐篇读完再回到列表，避免漏篇。

## 口径

- 发表记录列表是近实时计数，内容分析和单篇详情通常只更新到前一天。同一篇两处数字不同是正常的，两个数字和各自的统计截止时间都记录，不要合并成一个。
- 发表时间在不同页面可能差一天（群发通知日期与统计日期），以发表记录为准并注明。
- 图片消息（故事图文）没有完读率，用平均阅读时长配合页数判断读者大致停在哪里；普通文章才对比完读率。不要拿两种内容类型的同一个指标直接比高低。
- 发表不满 24 小时的内容只记“已发表、数据未稳定”，不参与比较。发表满 7 天的数字才作为该篇的结论值。

## 每篇一行的记录

记录写在内容项目里（没有内容项目时先问用户放哪），不写进技能仓库。每次复盘追加，不覆盖旧记录：

| 字段 | 说明 |
| --- | --- |
| 观察时间 / 数据截止 | 什么时候看的，后台写的数据更新日期 |
| 标题 / 发表时间 / 类型 / 状态 | 类型分故事图文、普通文章等；状态含已删除 |
| 发表天数 | 观察时距发表几天 |
| 阅读人数 | 分别记列表计数和详情计数 |
| 平均阅读时长 / 完读率 | 没有的填“无” |
| 新增关注 / 分享 / 收藏 / 留言 | 0 也要写 |
| 渠道构成 | 推荐占比和其余主要渠道 |
| 题材标签 | 自己定的少量标签，例如场景、有无对手、有无反转；同一套标签前后一致 |

另记一行账号级数据：总用户数、时段阅读总人数、流量来源占比。

## 多少数据才能下什么结论

- **单篇或两三篇的差异**：只能提出假设，例如“有明确对手的故事阅读更高”。写明样本数。
- **同一类至少 8–10 篇、各满 7 天**：才比较题材、标题写法或发布时间；比较中位数而不是只看最高的一篇。
- **阅读几乎全部来自推荐**：单篇阅读量主要反映平台分发，波动很大，不能据此断言某题材好或账号被限流。
- 不把阅读高低归因到单一因素（标题、封面、发布时间往往一起变了）。

## 方向判断怎么写

按“观察 → 假设 → 建议”分开写，并先回答用户真正的问题：方向要不要调。

1. **观察**：只写后台数字能支持的事实，含样本量和口径。
2. **假设**：对差异的解释，标明待验证，以及需要哪些后续内容来验证。
3. **建议**：区分现在就能做的（例如末页给出关注理由、同类故事建合集、停掉表现和定位都不符的内容类型）和需要攒数据再定的（换题材、换风格）。

先找最短的短板再提建议：有阅读没关注是转化问题，改选题解决不了；没阅读才是点开问题，看标题和首图；有阅读但停留很短，看前几页能否兑现标题。

数据不足以支持调整时，直接说“现在不调”，并给出下次复盘的时间点和届时要比较什么。下次复盘先读上一次的记录，对比同一篇满 7 天后的数字，再看新增内容。
