# AI 视频提示词导演

## 目标

把一个明确的剧情节拍转成模型能执行、用户能直接复制的单段提示词。优先让模型理解“谁在什么位置，对谁做什么，为什么做，谁说什么”，再补充风格和氛围。提示词不是形容词越多越好，而是职责越少、关系越明确越稳定。

## 人类创作优先（2026-09-01）

项目级细则见 `剧本库/00_共用创作规范/人味化创作与提示词标准.md`。本 Skill 只在故事、人物和导演选择已经成立后负责编译执行指令，不能用“电影感、真实、治愈、情绪拉满”等抽象词补上编剧缺口。

- 先写人物在当下知道什么、想让谁做什么、害怕承认什么，以及这次交流或行动让关系改变了什么；再写镜头。
- 对白要有具体对象、当场目的、潜台词和听者处理，不把剧情摘要伪装成人物说话；随机眨眼、点头、走路和看手机不能冒充表演。
- 视觉细节要来自人物处境、地点使用痕迹、时间、地域或动作，不用堆“高级、电影、氛围、震撼”制造审美；每个镜头只保留一个真正需要观众看见的画面重点。
- 交付前做“去掉镜头术语”测试：如果只剩台词、停顿和反应时人物不像彼此认识或互相影响，先回到剧本层重写，不能继续加提示词。
- 需要模型执行时仍保留空间地图、动作终点、声音归属和尾帧，但把这些字段压缩到必要程度，让正文服务具体事件，而不是看起来像一张自动生成的检查表。
- 不要让连续段落无意识复用“同一机位、同一左右站位、同一环境声、轮流说话”的模板；下一段必须有注意力、行为或关系上的真实变化，否则回到分集和场次层重写。
- `SHOT/UNIT/PANEL`数量、参考映射、哈希、风险标签和fallback服务制作协作，不是观众体验；复制区只保留模型执行所需的最小信息。
- 尾帧不应每次只写“呼吸、眨眼、画面冻结”；优先停在一个有余味的具体状态，例如未松开的手、没有收回的目光、被打断的动作或已经改变归属的道具。

## 跨电脑使用与质量底线

本目录是项目随 Git 同步的提示词导演 Skill。另一台电脑可能没有把它安装成系统 Skill，但只要仓库已拉取，就必须直接读取本文件；不能因为系统没有自动发现它，就退回只有一句动作概述的通用提示词。`AGENTS.md`、本文件、项目工作流、空间调度规范和 AI 镜头风险清单共同构成跨电脑创作入口。

当用户说“继续下一段”“生成提示词”或“直接复制”时，最低交付标准不是字数，而是可执行字段齐全：

- 先在复制区外给出 `generation_mode`、主空间锚点、最小参考集合、每份参考的单一主要职责和冲突处理；项目默认 `generation_mode: multimodal_reference`，不默认首尾帧模式；
- 复制代码块不写参考图上传顺序、稳定 ID、临时 `@图`、语义参考映射或冲突表，直接从画面内角色、画外声音/对象和不出场人物开始；画面内有两个及以上角色时，每个角色必须独占一个项目符号行，不用分号合并在同一行；
- 先确定时间、地点、光线和本段唯一剧情目标；
- 先建立空间地图：固定参照、镜头朝向、轴线、屏幕位置、深度、身体朝向、视线目标和物体运动路线；
- 每个时间块写清景别/机位、人物站位、动作起点→动作→可见结果、视线、表情、道具状态和声音；
- 每句对白绑定唯一说话人、听话人、身体朝向、视线目标和声源区域；没有画内对白时，若观众需要理解行为目的，加入指定角色的第一人称内心独白，并写明嘴唇闭合、不做口型；
- 每次景别、轴线或空间变化写明计划内硬切；最后至少 1.5 秒固定稳定尾帧；
- 复制区只放模型需要的角色、时空、镜头、动作、对白/独白、声音和连续性约束，不放集数管理、参考图上传绑定、`@图`、验收记录或后期工作流；总长度不超过 7000 字。

“他坐着哭”“他拿起手机”这类没有人物职责、动作目的、声音归属或可见结果的概述，不满足本 Skill；应继续细化，直到观众能看懂人物为什么做这件事以及正在对谁说话。

## 全模态多参考默认与生成前预检

本项目默认使用 `multimodal_reference`：场景图、人物图、对象图、动作图、风格图、参考视频和参考音频可能同时存在，但它们不是“越多越稳”。空间错误先按参考竞争诊断，不先加长提示词。

### 1. 只选一个主空间锚点

每个 `UNIT` 只允许一个 `dominant_spatial_anchor`，它负责最终画面的构图、主体数量、相对位置、镜头朝向、路线和纵深。优先级按本段目标选择：

- 需要复用真实连续画面时，可选上一段真实事实帧或干净的同场景合成图；
- 需要建立新地点时，可选没有文字/多格布局的真实场景图或干净场景动作图；
- 没有可靠图片时，用完整 `space_map` 作为文字主锚点，不用多张彼此不同的场景图共同投票。

其他参考只能支持身份、局部外观、动作节奏、风格或声音，不能再次定义整张构图。若两张图都想规定人物左右、车辆距离或镜头角度，保留与本段目标最接近的一张，另一张删除或裁成只含其职责的局部参考。

### 2. 最小参考集合与一参考一主要职责

按“没有它会不会导致剧情事实丢失”筛选素材：

| 参考类型 | 唯一主要职责 | 默认是否需要 | 常见污染 |
|---|---|---|---|
| 场景/连续性复合锚点 | 空间、构图、路线、纵深 | 每个 `UNIT` 最多一个主锚点 | 把路人、文字、车辆位置带成剧情事实 |
| 角色身份 | 指定可见角色的脸、发型、身形、服装 | 只给可见且身份关键角色 | 多人拼图复制出多人；背景改写场景 |
| 对象身份 | 汽车、三轮车或关键道具的外形 | 外形对剧情重要时才加 | 抢占构图、复制对象、汽车与三轮车融合 |
| 动作/参考视频 | 动作方向、节奏、身体力学 | 仅文字动作测试失败或动作特殊时 | 把参考中的人物、路线和机位一起带入 |
| 风格 | 色彩、材质、光感 | 基础空间和动作稳定后才加 | 带入新的场景、人物、服装或镜头 |
| 音频 | 音色、对白或声音事件 | 与视觉参考单独登记 | 图片身份被误当成声音身份 |

“一参考一主要职责”不表示复合事实帧里只能有一个元素，而是它只能被指定为一个最高职责，且没有第二张参考在同一层与它竞争。

### 3. 参考冲突矩阵

每次生成前在代码块外填写；冲突为“高”时先删、裁、换干净图或拆 `UNIT`：

| 竞争组合 | 典型错误 | 处理 |
|---|---|---|
| 场景 × 角色 | 场景路人替换主角、角色背景改写地点 | 场景只留空间；角色图裁成单人干净身份图 |
| 场景 × 对象 | 单独汽车/三轮车图抢占场景位置或彼此合体 | 主锚点统一规定两者位置；对象图只锁局部外观，非必要删除 |
| 角色 × 动作 | 动作参考的人脸、衣服或性别覆盖角色 | 动作参考裁掉身份，或只保留低身份信息的动作视频 |
| 对象 × 动作 | 模型搞错谁移动、路线和接触点 | 文字只指定一个运动主体；复杂物理过程拆前/结果状态 |
| 风格 × 任何事实参考 | 风格图带入新人物、新建筑或新道具 | 风格后加、低职责；能用文字表达就不上传 |
| 音频 × 视觉身份 | 画外声变成画内人物，或错人说话 | 单独写 `audio_reference_map`、说话人、听话人、声源和嘴唇状态 |

### 4. 提示词只补“参考没有说明的变化”

全模态提示词重点写动作起点→过程→结果、谁看谁、谁对谁说、对象沿哪条路线移动、镜头如何观察以及结尾停在哪里。不要重复描述参考图已经锁定的脸、背景和风格，也不要试图用更长文字同时服从两张互相矛盾的图。

硬 `first_frame/last_frame` 只是用户明确选择时的特殊模式，不是项目默认。选择硬首尾帧后才做接口互斥和端点兼容检查；没有明确选择时，首状态、尾状态和稳定尾帧只是导演/剪辑合同，不代表必须上传首尾图。

## 平台提示词路由

先根据用户当前请求和最近一次明确选择决定适配层：

- 明确说MiniMax/H3：读取H3适配器。
- 明确说豆包/Seedance：读取Seedance适配器。
- 同时提到H3与Seedance但没有指定本次目标，或只说“继续/生成提示词”而最近上下文无法唯一判断：先问“这次要生成H3类提示词，还是豆包Seedance类提示词？”
- 最近一次已明确“后续都用Seedance”或“H3”时可以沿用，直到用户切换；不要每段重复询问。

平台路由只改变最后的模型提示词语法和参考交付，不改变原始剧本、人物关系、场次、空间地图、动作脊柱、15秒时间线或资产真源。

## MiniMax H3 平台适配（按需）

MiniMax H3 的官方基础/全参考格式和中文案例经验统一收敛在 `references/minimax-h3-prompt-adapter.md`。使用时保留平台无关导演包，再编译H3适配层；不能让单个平台语法反向改写原始剧本、人物真源或项目稳定资产ID。

- 先判断`T2VA / I2VA / FL2VA / L2VA / reference generation / video continuation / video editing / audio reuse / audio reference`的实际关系；上传了图片或视频不等于自动选择硬帧、续写或编辑。
- 平台未明确时，项目常用手动全模态生成仍走平台无关中文实用稿。目标明确为MiniMax H3普通自由文本入口时，走H3实用稿；目标明确为MiniMax H3“全参考/全模态参考”模式时，默认编译`subject_definitions / summary / retention_analysis / detailed_description / overall_soundscape / non_diegetic_music`六段原生结构，不要求用户再说一次“原生格式”。
- H3原生`<Subject N> / <Picture N> / <Video N> / <Audio N>`是单次平台语义标签，不取代`CHAR-* / ENV-* / PROP-*`稳定ID，也不等于用户界面的临时`@图`。普通“直接复制”提示词继续不代管上传编号。
- H3有声镜头给每位实际发声者分配稳定`(S1)/(S2)`；视觉角色标签与说话人ID分开。说话人ID必须出现在发声动词和`<d>`之前，不能在台词之后补编号。中文台词写成`<d>[Chinese] 准确台词。</d>`，人物身份、表演方式、听话人、身体朝向和视线目标放在`<d>`外；画外旁白后立即写对应画面人物嘴唇闭合。
- 声音拆成逐镜同步声音、`overall_soundscape`环境/物理/非语言声音和`non_diegetic_music`观众侧配乐三层；完整对白不在soundscape重复，角色能听见的电视/电话/现场音乐不写成观众侧配乐。
- 运镜按“类型 + 方向 + 必要的幅度 + 必要的速度 + 最终构图”表达；中等幅度/正常速度没有叙事价值时省略。每个切镜仍需增加信息并写`cut_reason`。
- H3失败先按对白、参考、动作、镜头、动态或声音模块定位，一轮只修改一个问题块；不要同时重写角色、动作、运镜、声音和全部参考，导致无法判断哪条指令生效。

该适配只提升提示词和验片计划，不授权网页上传、API或CLI提交视频任务。

## 豆包 Seedance 平台适配（按需）

Seedance官方能力、自然中文案例、版本边界和排错规则收敛在`references/seedance-prompt-adapter.md`。豆包内置版本可能与字节Seed研究页、火山引擎API异步更新；版本专属能力影响任务时先读当前界面，无法确认再询问。

- Seedance使用自然中文导演稿，不使用H3的`(Sx)`、`<d>`、`subject_definitions`、`<Subject>/<Picture>`或六段英文结构。
- 普通Seedance复制区必须从`画面内角色：`开始，多角色一人一行；随后写画外声音/对象、不出场人物、时空目标、空间地图、时间块、对白声音和连续性约束。
- Seedance项目硬偏好是`multimodal_reference`：有起始图、结束图或上一段尾帧时，也默认把它们作为普通参考、连续性事实或剪辑端点，不自动改成首尾帧插值。只有用户对本次任务明确说“使用硬首尾帧/首尾帧模式”时才启用；仅说“参考这两张图”“保持开头结尾”不算授权。
- Seedance多模态参考在代码块外维护最小参考集合、唯一主空间锚点和“保留/排除”对；豆包临时`@图片/视频`及上传顺序由用户操作，不进入普通复制稿。
- 中文对白使用角色名称明确绑定说话人、听话人、朝向、视线、语气和听者闭嘴反应；有声能力未从当前豆包界面确认时标记`post_audio`，不假设提示词可以解锁音频。
- 视频编辑使用“只改变什么/必须保持什么”，视频延长写源视频末状态→连续路径→新终点；仅参考动作或运镜的视频不误写为待编辑原片。
- 失败时先按参考、动作、对白、镜头、端点、音频或平台语法定位，一轮只改一个层；发现H3语法时删除并恢复Seedance自然中文格式。

## 视觉资产生成门：设计了，就负责锁定

当本 Skill 或 Codex 为剧情新增会反复出现、会转身/反打、会被交互或承担证据的角色、固定场景、车辆和关键物体时，不能只写文字设定后直接进入“生产就绪”的视频提示词。按 `视觉资产锁定与三视图规范.md` 主动完成：

1. 建立 `CHAR-*`、`ENV-*`、`PROP-*` 或既有规则兼容的稳定 ID 与文字 brief；
2. 生成候选参考套图并做跨视角验收；角色用正面/严格侧面/背面，固定场景用主建立/反向/路线视角，车辆或关键物体用前/严格侧/后和必要交互细节；
3. 保存源参考、候选套图和干净单视图，登记来源、职责、版本、状态和 SHA-256；
4. 用户确认前标记 `pending_user_confirmation`，不能把 AI 推断的脸、鞋、背面、门窗或物体结构写成用户事实；
5. 用户确认后才升级为 `locked`，再从资产包里为当前 `UNIT` 选择最小干净参考，不默认上传多格设定板。

固定场景不是人物，不能机械使用“正侧背”。如果用户只有一张真实地点或真实物体照片，未拍到角度的 AI 扩展只能是派生候选；精确结构影响剧情时，先请用户补拍或调整镜头避开未知区域。画外声音角色、一闪而过的模糊路人和无剧情作用的普通小物不强制生成完整套图。

当前项目对参考图片/设定资产的生成责任与视频 API 边界分开：可以主动准备并生成必要参考图，但未经用户重新授权不得提交、轮询或下载视频任务。

## 复制提示词的固定开头

用户需要根据人物名称自行关联参考图，因此复制区不代管平台 `@图`、上传顺序、临时编号或语义参考映射。参考计划放在代码块外；代码块固定从三组角色/对象清单开始：

唯一格式例外：目标明确为MiniMax H3“全参考/全模态参考”原生适配时，代码块外仍先用“一角色一行”列出可见角色和稳定ID→临时H3标签映射，代码块内则按官方格式从`subject_definitions`开始。该例外不允许把临时`@图`、文件路径或项目稳定ID塞进原生代码块，也不改变普通平台、H3自由文本或Seedance提示词的固定开头。

```text
画面内角色：
- 程序员：约28岁中国男性……；本段动作/对白职责……
- 普通同事：成年中国男性……；本段动作/对白职责……
画外声音或对象：家人，只通过已接通电话声音出现，不露脸。
不出场人物：老板、女性HR、其他同事、客户、伴侣和清晰路人。
```

规则：

- 只列本段真正需要看到、听到或作为明确行为对象的人物；画外声音不写成画面角色。
- 画面内有两个及以上角色时，在`画面内角色：`下一人一行，用`- 角色名：身份与本段职责`格式；这一行就是人工核对角色数量和绑定对应参考图的最小单元。单个可见角色也可沿用同样格式以保持一致。
- 每个画面人物给出稳定身份、年龄段、外形、服装和本段职责；不在同一提示词里用“他、她、对方”替代角色名。
- 明确“谁是动作发起者、谁是接收者、谁在听、谁不说话”。多人只保留剧情必须的人数。
- 不出场的人物要写明不出现、不发声，防止模型自动补入老板、HR、家人、伴侣、清晰路人或拥挤人群。

## 15 秒提示词的写作流程

### 0. 先区分主交付和失败降级

当用户要求“生成一个 15 秒镜头/视频”时，最终复制代码块必须本身连续覆盖用户要求的完整时长，例如 `0.0–15.0 秒`。`SHOT`、`UNIT`、`BRIDGE` 是导演规划和风险审计层，不是默认的生成任务数量；不能把 `0.0–2.8 秒`、`2.2–5.0 秒` 等内部片段分别写成主复制提示词后交付给用户。

完整时长提示词可以在内部包含计划内切镜、同轴切换和声音桥，但必须从开头写到稳定尾帧。只有完整时长版本因口型、人物数量、物体融合或模型能力失败时，才在主复制块之外提供 `fallback_split`；降级片必须写清成片时间、职责和剪辑端点，不能取代主交付，也不能把失败退路写成“最终复制提示词”。

### 1. 先锁定时空和唯一目标

在角色清单后，用一两句建立独立的时间、地点、光线和本段唯一目标。例如“月底最后一个工作日下班后，程序员站在公司玻璃门外，拿出手机但尚未拨通；本段不进入家庭电话”。不要写“承接上一帧”“接上一段”“下一段”“第三集第四段”等制作管理语句；只有用户明确提供真实首帧且要求严格承接时，才把首帧事实写成当前画面的外观，不要求模型猜上一帧。

### 2. 写全局人物和道具锁定

只锁本段需要的内容：

- 程序员：约 28 岁中国男性，偏瘦，短黑发，细框眼镜，深灰色连帽卫衣、浅蓝色内搭、深色长裤；需要时写黑色双肩包、手机、电脑等道具。
- 其他人物：写清普通同事、老板、家人或伴侣在本段是画内人物、画外声音还是完全不出现；不要给临时配角添加没有剧情用途的姓名、身份和设定。
- 场景：具体到公司开放办公区、出租屋床边、玻璃门外雨棚等，不用“某处”“那里”。
- 道具：写明谁持有、从哪里拿出、何时交接、最后停在哪里；无品牌物品不出现 Logo、价格、订单号、二维码或可读文字。
- 统一外观：跨镜头保持脸型、发型、身形比例、核心服装、道具状态、光线方向和色调稳定。

### 3. 按时间码逐镜写

每个时间块都必须回答以下问题，不留给模型猜测：

```text
时间码：0.0–3.0 秒
镜头：景别、机位、角度、构图、焦点和唯一主要运镜。
画面人物与站位：谁在画面左/右/前/后，面对谁，人与人的距离。
动作：动作起点 → 一个主要动作 → 可见结果；写清手和道具的归属。
视线与表情：看向谁或看向什么，表情用可见的眼神、嘴角、肩膀、呼吸、吞咽等表现。
场景与道具：背景只保留必要元素，写明道具状态。
声音与对白：说话人 → 听话人：具体台词；同时写清其他人是否闭嘴倾听。
```

动作必须有终点。例如不要写“程序员走过去”，要写“程序员从左侧工位站起，走到右侧同事桌边并停在桌边，双脚不再移动”。递接物品必须写“拿住—伸出—接触—释放—保持”，避免手部穿模。一个镜头只安排一个主要交互；复杂交接、遮挡、转身或越轴时，拆成更窄的时间块或明确硬切。

### 4. 让观众听懂行为目的

如果仅有动作会让观众不知道人物为什么这样做，优先加入一条短画内对白或一条清晰的第一人称内心独白；不要为了“热闹”凭空增加台词。

#### 因果与人物认知门

任何动作、质问、决定或情绪爆发在进入时间码前，都先写完下面这条链：

```text
触发证据 → 人物实际知道什么 → 当前具体目的 → 采取什么行动 → 期待谁/什么回应 → 失败后产生什么结果
```

- 人物不能根据尚未看见、听见、被告知或合理推断的事实采取行动。先确认 `trigger_evidence` 和 `knowledge_state`，再写台词与动作；缺一项标记 `causal_motivation_gap`。
- 台词必须服务人物当下目的，不只是替编剧解释剧情。检查现实中的人为什么现在开口、想让谁做什么、对方回应后准备怎么处理；说法像剧情摘要、无来由发问或没有实际诉求时标记 `human_dialogue_logic` 并重写。
- 情绪强度必须由可见失败累积触发：证据出现、尝试沟通、无人回应、结果恶化，随后才允许提高音量或爆发。不能先安排愤怒表演，再倒推一个理由。
- 画外对象可以承担已确认的因果方向，但必须通过人物视线、手势、已知前段事实或画内台词让观众读懂；不能只在导演说明里写“他已经知道”。

例如程序员不能一到停车区就无缘无故喊“谁的三轮车”。完整链应是：已经看见自己的汽车被剐蹭 → 已从监控确认眼前三轮车造成碰撞 → 想找车主协商处理 → 先看受损汽车方向、再看三轮车 → 朝附近能听见的区域说明撞车原因并找车主 → 无人回应后再采取下一步。汽车若与三轮车同画面会融合，可保留为画外因果对象，但“撞了我的车”和“出来处理”不能从台词中删掉。

- 画内对白写成“程序员对普通同事说：‘今天是我最后一天了，给你买杯奶茶。’普通同事看着程序员回答：‘怎么突然请我喝奶茶？’”。必须绑定说话人和听话人，使用清晰自然的普通话，口型与台词同步；禁止把台词分配给错误人物。
- 台词要短，留出动作建立、听者反应和尾帧停留。不要让两个人同时长篇说话，不要用未命名的“画外人”发声。
- 内心独白必须写明“程序员第一人称内心独白”，并明确“这是画外心声，不是画面内对白；程序员嘴唇闭合，不做口型；其他人物不说这句话”。内心独白只属于指定人物，不能被同事、老板或家人代说。
- 部分平台（如豆包 Seedance 1.x）原生音频是口型同步式、不支持“嘴唇闭合却出声”的心声，此时二选一：把内心判断改写成**画内低声自言自语**（张嘴、口型同步、不对任何人说），或让心声走**后期配音（`post_audio`）**；不要写进提示词要求平台生成无口型旁白。Seedance 2.0 原生音频已支持文字引导的画外音/旁白（voiceover，不绑口型），无人物环境片的旁白可直接写进提示词；画外音（旁白）与画内对白（人说话）的区分与写法见 `references/seedance-prompt-adapter.md` 的“五之补三”。
- 电话场景写清声音归属和听话人：例如“家人通过手机听筒对程序员说……；家人不露脸；程序员看向手机并回答……”。未接通时不能生成家人声音、铃声或对话。
- 必须生成声音时要正面写“生成清晰的画内普通话人声/电话声音，台词完整可辨，口型同步”；同时保留纸杯、脚步、衣料、键盘或城市底噪。若目标平台经过验证不生成音频，提示词不能假装解决能力问题，应在分镜外标记为需要开启音频或单独配音。

#### 人味与情绪颗粒度门 v1

普通双人生活戏、关系戏和共同决策戏在进入时间码前，除因果链外再填写：

```yaml
thought_trigger: "此刻让人物心里动一下的具体人、话、声音或物"
private_judgment: "人物实际怎么理解这件事；尚未说出口的判断"
subtext: "这句话下面真正担心、试探、体谅、嘴硬或期待的是什么"
spoken_intent: "人物现在开口想让对方知道、回答或采取什么行动"
listener_processing: "听者先听见什么，停顿/视线/呼吸如何变化，再怎样回应"
embodied_detail: "与思考绑定的一个身体动作或道具动作，不是随机动画"
emotional_delta: "交流后人物或关系比开口前改变了什么"
```

- “更多对白”不是堆字。普通双人戏优先形成一次完整交流回路：A有触发地开口 → B有可见消化 → B回应、追问或有意义地沉默 → A/B关系产生一个变化。只有“一句说明 + 对方机械点头”时，标记`dialogue_underwritten`。
- 每句台词既服务当场目的，也保留一点人物立场和潜台词。不要让角色轮流念剧情摘要；可以使用“要不……”“其实……”“算了”“你真想去？”等自然口语，但不为追求生活感添加无意义口头禅。
- 听者不是背景。台词之间必须留出可见的处理过程，例如视线从物体回到说话人、先吸气却没立即回答、手停住后收回、嘴角想笑又压住。听者完全没有消化过程时标记`listener_reaction_missing`。
- 微动作必须由思考驱动：犹豫才停手，试探才观察对方，松下来才呼气，嘴硬才避开视线。随机眨眼、无原因点头、反复看手机和无意义走路不能冒充情绪颗粒度。
- 沉默可以比对白更有温度，但必须写明“为什么不说、听见了什么、沉默后关系如何变化”。沉默没有原因和结果时标记`human_presence_missing`。
- 15秒生活对话常可容纳2–4句短自然话，但这只是预算参考，不是硬配额。先保证自然语速、听者反应和最后1.5秒稳定；纯动作、危险、驾驶、哭泣、环境建立或已由前段对白说清目的的镜头可以少说。
- 角色本应当场说出口的情绪不要偷换成内心独白；真正难以说出口、且画面需要让观众听见的私人判断才使用第一人称心声。

不合格：伴侣说“去大同吧”，程序员点头，两人转身。

合格：伴侣先看被挡住的路线，压住失望后试探“那要不换个地方？”；程序员听见她不是责怪自己，肩膀松一点，反问或明确回应；伴侣确认后才转身。台词、停顿和转身共同完成关系变化。

### 5. 明确剪辑和尾帧

模型不会可靠地替用户完成多镜头剪辑。每次镜头变化写“在 X 秒做一次明确、干净的计划内硬切”，不要写“自动变焦到特写”或“无缝变成另一个地点”。

- 15 秒段默认优先使用固定机位或单向轻微运动；适合本项目的常用切点是 `5.5 秒` 和 `10.5 秒`，但只有故事确实需要时才使用，不为凑数量硬切。
- 每个切点前后都重新写人物、站位、道具和场景，不让模型猜切后关系。切点不超过剧情需要，默认最多两次计划内硬切。
- 最后 `13.5–15.0 秒` 或至少最后 `1.5 秒` 固定稳定尾帧：只保留自然呼吸、一次轻微眨眼或已完成动作，不新增对白、人物、道具、运镜、拉焦或换场。
- 结尾只停在本段目标完成后的可见状态。例如“同事拿着奶茶，程序员仍站在桌边”或“手机仍未拨通”；不要提前写离开公司、家人出现或下一剧情。

## 空间调度协议 v1：把“对着谁、在哪里、怎么过去”写成硬字段

在四层提示词编译器之外，每个新 `SHOT/UNIT` 都要通过空间调度协议。详细模板见当前剧本项目根目录下的 `04_进度管理/空间调度与连续动作规范.md`。

### 空间地图

先写三套关系：

1. **世界坐标**：门、桌、屏幕、车位、立柱、入口等稳定参照；
2. **屏幕坐标**：画面左/右、前/后、深度层，以及镜头从轴线哪一侧观察；
3. **关系坐标**：谁面对谁、谁看向谁、谁发起动作、谁接收结果、声音从画内还是哪一侧画外传来。

“旁边”“那里”“走过去”“对着画外”都不能单独作为空间指令。人物和道具必须写成“唯一身份 + 世界位置 + 屏幕位置 + 朝向 + 视线目标 + 动作路线 + 结束位置”。汽车与三轮车等实体还要写清数量、独立轮廓、固定/移动状态和相互间距。

### 对话与视线

画内对白用“说话人 → 听话人 → 身体朝向 → 视线目标 → 台词 → 听者反应”；画外对白用“声音来源区域 → 听话人 → 听话人的视线转向”。先用主镜头建立地理关系，再做反打；同一对话组默认保持 180 度轴线同侧，越轴必须用中性角度、可见运动或计划内硬切重新定向。

“画外声音”不是“内心独白”。前者是空间里的角色对明确对象说话，后者是指定角色的心理声部；两者必须分别标注 `dialogue_owner`、`listener`、`sound_source`、`voiceover_owner` 和嘴唇状态。用户要求角色当场表达时优先画内对白，不能为了规避口型把情绪偷换成心声。

### 物体与碰撞

碰撞、物体消失、遮挡换手等物理因果先拆成“接触前稳定关系 → 动作/接触过程 → 结果证据”。生成不稳定时默认 `split_UNIT + planned_cut + post_edit`：例如汽车保持静止、三轮车沿明确路线移动，接触点由遮挡/声音/剪辑连接，下一镜单独展示车损；不能在一个任务里同时要求风、车辆接触、车损变化、监控文字和人物对白。

### 动作脊柱与反发呆门

每个 15 秒段先写“意图 → 准备 → 执行 → 可见结果 → 反应/下一决定”。每个时间块至少新增一个动作结果、道具状态、关系信息、因果线索或声音意义；如果连续两个时间块只有“继续站/继续看/继续发呆”，先标记 `low_information_density`，补有结果的微动作、反应或短对白，不用任意增加人物和地点。纯停顿必须写明触发原因和停顿结束时产生的变化。

### 切镜平滑规则

切镜的平滑来自端点匹配和声音桥接，不来自模型自动换镜。使用 `same_frame_handoff`、`match_on_action`、`planned_cut` 或 `cutaway_insert` 明确边界；换地点、换轴线、换主体数量、换景别家族或防止实体融合时，优先计划内剪辑。只有用户明确选择硬首尾帧时，才在同空间、同主体数量、相近景别/轴线和相邻动作之间做插值。

## 镜头和画面稳定规则

- 每个镜头写景别、角度、视线轴、焦点和一条主要运镜；主体动作复杂时镜头固定，镜头运动复杂时主体只做一个清晰动作。
- 画面优先中景、中近景和手部插入；需要表现人物关系时锁定左右位置、面对方向和镜头轴线。
- 画面必须写“主体清楚、焦点稳定、动作连续、帧间清晰”，并禁止运动模糊、拖影、重影、融帧、低清噪点、脸部变形、手指畸形和随机换场。
- 不要让模型承担精确合同、电脑代码、手机联系人、字幕、价格、Logo 或二维码。除非文字是已核验的剧情证据，否则写成不可读的屏幕色块、无品牌文件夹或纯色纸杯，并禁止乱码、水印和广告。
- 不要用梦境溶解、闪回叠影、自动蒙太奇或突然增加镜头解释心理；把心理翻译为可见停顿、视线、呼吸、肩膀和手部动作。

## 复制区的输出边界

用户说“直接复制”“继续下一段”时，先在代码块外给出精简的全模态参考计划，再输出一段完整提示词。复制内容只写模型需要知道的角色、时空、镜头、动作、对白/独白、声音和画面约束；不要写稳定资产 ID、语义参考映射、文件路径、集数、段号、导演说明、平台临时上传顺序、上一帧/下一段、后期工作流或验收记录。

复制区直接从角色/对象清单开始，随后按 `0.0–15.0 秒`时间码展开；空间地图写最终应出现的关系，不写它来自哪张参考。保持正向描述优先，必要的禁止项放在末尾集中写一次。最终提示词控制在用户平台 `7000` 字以内，目标留在约 `2500–5500` 字；超长时先删重复形容词、重复禁用词和制作管理话，不删角色归属、动作终点、对白说话人、听话人、切点和尾帧。

## 提示词编译器 v2：四层结构与复杂度预算

把导演意图编译成模型任务时，按以下四层组织；不要把四层互相重复：

1. **状态层**：只写不会在本段随时间变化的事实——人物身份、服装、空间、光线、道具归属、镜头轴线和画面人数。静态锁定写一次，后续用“保持不变”指向它。
2. **行为层**：只写可观察的动作链——动作起点 → 一个主要动作 → 可见结果。每个时间块只推进一个主要动作和一个情绪变化，不用“崩溃、释然、感觉天塌了”替代身体表现。
3. **声音层**：先区分三种声音再写——**画外音/旁白（voiceover，画面无嘴、无听话人，Seedance 2.0 可文字引导、不绑口型）**、**画内对白（人说话，口型同步，写“说话人 → 听话人”）**、**内心独白（指定人物第一人称画外心声，嘴唇闭合、不做口型）**。分别绑定声音来源、听话人和嘴唇状态；未验证的音频、口型和混音能力标记为 `post_audio`，不要让它成为画面成立的唯一条件。旁白/对白/独白不可混写，细则见 `references/seedance-prompt-adapter.md` 的“五之补三”。
4. **剪辑层**：只写真正需要的计划内硬切、同帧承接和尾帧固定。硬切前后重新确认景别、轴线、人物位置和道具状态；尾帧只保留已完成动作后的自然呼吸、轻微眨眼或极小幅度情绪反应。

如果本段使用真实地点图片，在代码块外把它登记为场景参考；只有它被选为 `dominant_spatial_anchor` 时，提示词中的空间地图才按其可见结构写。照片中的路人身份、站牌文字、广告或其他未核验内容不进入剧情事实，角色身份和声音身份另行登记。

### 复杂度预算

默认一条 15 秒生成任务最多承担：

- 一个主要空间区域；
- 一组稳定的画面人物；
- 一条主要镜头路径；
- 一个主要道具关系；
- 一个情绪变化；
- 不超过两次可见硬切，且每次硬切都有 `cut_reason`。

对动作密度增加一条生产门：不是每秒都要动，但每个约 1.5–3 秒的时间块都要有可见动作、声音事件或信息结果；“刻意停顿”必须写出原因。提示词迭代时一次只增加一个变量（主体动作、镜头动作、环境动作、声音或风格），先确认基础动作成立，再增加下一变量。

如果一段超过这个预算，优先增加 `UNIT` 或改成后期计划内剪辑，不要继续堆形容词和禁止词。单个时间块尽量只安排一个新动作；复杂交接、遮挡、转身、越轴、长对白或音画同时变化，应拆成更窄的时间块。

### 信息密度与内心独白规则 v1

稳定性和信息密度是两种不同的预算，不能因为担心模型乱跳，就让三个时间块只重复“人物站在同一个地方”。在一个 15 秒段内，默认以 `3–4 个有意义的 story_beat` 作为目标而不是硬配额，例如：建立状态 → 动作发生并产生结果 → 反应/关系信息 → 必要的第一人称心声或尾帧落点。

- 每个相邻时间块至少新增一种 `information_delta`：新的可见动作结果、道具状态、人物关系信息、情绪变化、因果线索或声音意义。若连续两个时间块只是“继续看、继续站、继续走”且没有新结果，就合并、压缩或改写。
- 同一地点不等于低密度。可以使用稳定的“微地理路线”增加信息：入口/桌边 → 关键道具 → 手部或屏幕证据 → 人物反应 → 结果停留；但每次景别变化都必须服务一个具体信息，不用随机推拉和角度替换填空。
- 当本段没有画内对白，且观众无法仅靠动作理解“他为什么做”或“这一步对他意味着什么”，默认提出一条 `2.0–3.5 秒` 的指定角色第一人称画外心声候选。心声只说一个短意图/判断，不复述画面、不总结整集；程序员嘴唇闭合、不做口型，音频不稳时标记 `post_audio`。
- 不是每段都强行加独白：纯情绪释放、明确的物理动作或已经由画内对白说清目的的段落，可以用呼吸、环境声和反应代替。但分镜必须明确记录“有声对白 / 第一人称心声 / 无语言声音”三者之一，不能无意遗漏声音层。
- 15 秒的推荐检查节奏是 `0–3 秒建立并出现钩子；3–8 秒完成主要动作；8–11.5 秒给结果或反应；11.5–13.5 秒给关系/内心意义；13.5–15 秒稳定尾帧`。这是审查尺，不是要求每段机械切成五镜。
- 如果为了达到信息密度必须引入第二地点、第二组人物或两个以上复杂动作链，先拆成下一段或后期计划剪辑；不要把“高密度”误写成“高复杂度”。
- 信息增量不只来自新动作和新物体。人物改变理解、听出潜台词、犹豫后改口、从防御转为信任、从附和转为主动提议，也属于有效`information_delta`；优先用这类关系变化增加人味，再考虑添加新镜头。

### 音乐母题与 BGM 衔接（连续短剧）

连续短剧每集拆成多个 15 秒段分开生成，BGM 若各段各配会"对不齐"。做法是给整集（或整季）定一个**统一音乐母题**，每段只在母题内做情绪微调：

- 母题只锁四个不变量：调性（常用小调）、速度（慢，约 60–72 BPM）、主乐器（如一架音色偏旧的钢琴）+ 一层很轻的铺垫（低音弦乐/合成器长音）、留白密度（音符稀疏）。
- 每段 BGM 按剧情走情绪曲线：留白建立 → 轻紧张动机 → 悬置 → 高点 → 淡出；结尾停在"未解决单音/低鸣"做约 1–1.5 秒淡出，不硬切。
- 下一段用同一母题从轻处重新进入（同调性、同主乐器），情绪切换只靠"声部变化"完成，不换主乐器、不换调性。
- 观众侧配乐（BGM）与画内对白、环境声分层：BGM 音量低、不盖台词，画面内人物"听不见"。
- 手动配乐对不上节拍，常见原因是选了"满铺/带鼓点"的音乐；选"稀疏、留白、慢速"的更容易卡点。

### 状态锚点与动作锚点

- 有主空间锚点时，只把锚点中的已核验可见事实作为起始状态，并把提示词重点放在后续动作；不要重新描述一套与锚点冲突的脸、背景和构图。
- 没有可靠主空间锚点时，先用一两句建立独立的可见起始状态；不要要求模型猜测“上一段最后是什么样”。
- 上一段真实尾帧可以作为全模态普通连续性参考，也可以只作为剪辑事实；除非用户明确选择硬首帧，不自动把它升级成 `first_frame`。
- 任何时间块都要写出动作终点，例如“手机贴在右耳并保持不动”“杯子交到同事手中并保持”“眼泪沿脸颊留下泪痕”。只有起点没有结果的动作不算可生成指令。

### 正文密度与删减顺序

提示词精致不等于更长。正文优先保留：角色归属、站位、动作终点、视线、道具持有、声音归属、硬切点和稳定尾帧。需要压缩时按以下顺序删减：

1. 重复的“电影感、真实、高清、自然、连贯”等形容词；
2. 在多个时间块重复出现的背景形容词；
3. 重复的禁止项，合并为一段末尾约束；
4. 与本段目标无关的风格和心理解释。

不要删掉人物名称、左右/前后位置、动作起点和结果、说话人与听话人、嘴唇状态、计划内硬切和最后 1.5 秒尾帧。

### 推荐复制模板

代码块外先交付：

```yaml
generation_mode: multimodal_reference
dominant_spatial_anchor: "稳定资产 ID / 无图时写 text_space_map"
minimum_reference_set: ["稳定资产 ID + 单一主要职责"]
reference_conflict_matrix: "scene/character/object/action/style/audio 的竞争结论与删减"
audio_reference_map: "声音身份、说话人、听话人和声源；与图片身份分开"
```

复制代码块内只放：

```text
画面内角色：
- 角色A：……
- 角色B：……
画外声音或对象：……
不出场人物：……

时间与地点：……
本段唯一剧情目标：……
空间地图：固定参照……；镜头朝向/轴线……；人物屏幕位置/深度/身体朝向/视线目标……；对象数量/固定或移动状态/路线/结束位置……
全局保持：人物外观、画面人数、空间、光线、轴线、道具归属和焦点稳定。

0.0–X秒：
镜头与站位：……
本时间块新增信息：……
动作脊柱（意图 → 准备 → 执行 → 可见结果 → 反应/下一决定）：……
视线与表情：主体看向明确的人/物/画外区域……
声音与对白/内心独白：说话人 → 听话人；身体朝向、视线目标、声源区域和嘴唇状态……

X秒：计划内硬切/同帧承接：切前状态 → 切后状态；只写必要变化。

X–13.5秒：按同样字段写动作链。
13.5–15.0秒：固定尾帧；只保留自然微动，不新增信息。

画面连续性约束：把必要的角色、道具、文字、人物数量和换场约束集中写一次。
```

输出前做两次检查：第一遍检查剧情语义是否让观众看懂“谁对谁做什么”；第二遍检查模型是否只需要执行一个空间、一个镜头路径和一条动作链。若第二遍不通过，先减少事件、角色或运镜；只有完整时长版本确实失败时，才把拆片作为代码块外的 `fallback_split`，不能直接把拆片当成主交付。

## 交付前自审

- 开头是否列出了画面人物、画外声音/对象和不出场人物？
- 本段是否有约 3–4 个有效信息增量，且没有连续两个时间块只重复同一状态？
- 若无画内对白，观众是否能理解行为目的；若不能，是否加入了一条短的指定角色第一人称心声？若不加，是否明确记录了原因？
- 是否明确写出 `generation_mode: multimodal_reference`，并把硬首尾帧保留为用户明确选择的例外？
- 是否在复制区外选出唯一 `dominant_spatial_anchor`、最小参考集合和一参考一主要职责，并完成 scene/character/object/action/style/audio 冲突表？
- 本段是否新增了必须锁定的角色、固定场景、车辆或关键物体；若是，候选套图、干净单视图、稳定 ID、状态和验收是否完成？未完成时是否明确标为非生产就绪？
- 是否误把固定场景套图写成人物式正侧背，或把 AI 推断的真实地点/真实物体未知角度冒充事实？
- 如果存在真实地点参考图，是否只把已核验空间事实写进空间地图，且没有把参考映射、平台编号、路人或文字塞进复制区？
- 是否有空间地图：固定参照、屏幕位置、深度、轴线、身体朝向、视线目标和物体路线？
- 每个物体是否有唯一数量、轮廓、固定/移动状态和结束位置；汽车、三轮车、手机或文件是否有独立职责？
- 每个时间块是否写清人物、站位、动作、视线、表情、场景、道具、说话人和听话人？
- 是否存在“他、她、对方、那里、对着画外”等会造成身份、目标或方向歧义的代词？
- 每句对白是否写清身体朝向、视线目标和声源区域；画外对白是否明确听话人，且没有被误写成内心独白？
- 每句对白是否绑定唯一说话人和听话人，且有足够口播时间？内心独白是否标明第一人称、归属人物和闭嘴不做口型？
- 若目标为MiniMax H3，是否为每位实际发声者分配并复用唯一`(Sx)`；`<d>`内是否只有语言标签和准确台词，人物身份、动作、语气、听话人和视线是否留在外部？
- 若目标为MiniMax H3，逐镜同步声音、`overall_soundscape`和`non_diegetic_music`是否分层；是否没有在soundscape重复完整对白或把画内音乐误写为观众侧配乐？
- 若目标为MiniMax H3全参考原生格式，是否只在平台适配层使用`<Subject>/<Picture>/<Video>/<Audio>`标签，并保持它们与项目稳定资产ID、临时`@图`绑定互不替代？
- 若目标为豆包Seedance，代码块是否从`画面内角色：`开始，且没有混入H3的`(Sx)`、`<d>`、六段英文或`<Subject>/<Picture>`标签？
- 若目标为豆包Seedance，是否保持`multimodal_reference`默认；即使有首图/尾图，是否仍作为普通参考、连续性事实或剪辑端点，除非用户本次明确要求硬首尾帧？参考的保留/排除、对白自然语言绑定和当前界面音频能力是否清楚？
- 是否明确时间、地点和本段唯一剧情目标，且没有把新地点、新时间或新人物藏在动作里？
- 如果用户要求完整 15 秒，主复制块是否从 `0.0 秒` 覆盖到 `15.0 秒`；是否把 `SHOT/UNIT` 的内部时间误交付成短片提示词？
- 角色数量、左右站位、道具持有状态和光线方向是否在切镜前后保持一致？
- 是否显式写出每个硬切和最后至少 `1.5 秒`稳定尾帧，并且没有把“尾帧状态”误当成默认硬尾帧上传？
- 是否避免品牌、精确文字、字幕乱码、水印、随机新增人物、乱换场、穿模、模糊帧和新剧情？
- 是否在不增加复杂度的前提下提供了能让观众理解行为目的的对白或内心独白？
- 是否存在“发呆”却没有触发原因、停顿结束点或信息结果？有则标记 `low_information_density` 并改写。
- 每个关键行动和台词是否通过“触发证据 → 人物认知 → 当前目的 → 行动 → 期待回应 → 失败结果”的因果与认知门？人物是否说了现实中此刻会说、且能推动对方回应的话？不通过则标记 `causal_motivation_gap` / `human_dialogue_logic`，先修剧情逻辑再润色提示词。
- 普通双人/关系戏是否通过“触发 → 私人判断 → 潜台词 → 开口目的 → 听者消化 → 回应或有意义沉默 → 情绪/关系变化”的人味门？若只剩动作指令、剧情说明和机械点头，标记`human_presence_missing` / `dialogue_underwritten` / `listener_reaction_missing` / `subtext_missing`后重写。
- 每个微动作是否能回答“人物为什么此刻这样动”；删除这次动作后若不影响人物思考、关系或信息，就把它视为动画填充并删掉。

失败时按顺序降级：先检查输出到底服从了哪份参考；删除或裁掉竞争参考并重新指定唯一主空间锚点；再减少事件和人物、固定镜头、拆分交互、把景别或地点变化改为计划内硬切、把不可靠的文字/音频/字幕移出模型职责。不要只继续堆叠“电影感、真实、连贯、高清”等形容词。
