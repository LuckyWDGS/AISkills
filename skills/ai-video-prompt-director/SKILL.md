# AI 视频提示词导演

把一个已确定的内容节拍编译成模型能执行、用户能直接复制的提示词。职责越少、关系越明确越稳定；形容词补不了编剧缺口。

## 边界

- **本Skill管**：动作、空间、参考职责、声音归属、镜头衔接、复制正文，以及按实片偏差修提示词。
- **上游**：观看承诺、选题、原创方向、制作授权来自douyin-ai-creator-lab的`pilot_brief`，或用户/项目剧本。缺故事或观看承诺时回上游，不用提示词补。
- **下游**：实际生成、剪辑、配音和验收记录由执行方完成（Muse流程在creator-lab）。本Skill只判断偏差属于哪一层、提示词怎样改。提示词设计不授权提交视频任务。
- 输入检查与`prompt_package`格式见[交接合同](references/handoff-contract.md)。

## 1. 判断任务类型，只读需要的参考

| 情况 | 读取 |
|---|---|
| 有可见人物、对白、关系或动作交互 | [人物戏写作](references/character-drama.md) |
| 庇护所、空房间、治愈/环境片、物件小事件、无人旁白 | [环境片导演与实片反馈](references/environment-pilot-and-review.md) |
| 有参考图/视频/音频，或出现空间串场、切镜跳变 | [参考与空间](references/spatial-and-reference.md) |
| 新增会反复出现的角色、固定场景、车辆或关键物体 | [视觉资产锁定](references/asset-lock.md) |
| 继续某个内容项目，或需要知道默认时长/字数/切点 | [项目偏好与项目文件](references/project-preferences.md) |
| 交付前 | [自审清单](references/checklist.md) + `scripts/lint_prompt.py` |

人物戏规则不自动套给环境片；环境片不为通过人物模板补造人、嘴型或关系戏。

## 2. 选输出档位

按请求自动选，用户指定时以用户为准；判断不了就用标准档，不为档位追问。

| 档位 | 何时 | 交付 |
|---|---|---|
| 快速 | 只要一段提示词，无参考或参考单一，简单环境镜头 | 一句假设说明 + 复制正文 |
| 标准（默认） | 有参考图、多角色、对白或指定平台 | 代码块外参考计划（锚点、最小集合、保留/排除、音频归属）+ 复制正文 + lint结果 |
| 生产 | 已授权代做成片、连续多段、系列资产或修片 | 标准内容 + 生产单元划分、`fallback_split`、验片重点、资产状态 |

快速档也不能省：说话人与听话人、动作终点、稳定尾帧、平台语法不混用。

## 3. 平台路由

| 判断依据 | 适配层 |
|---|---|
| 明确说MiniMax/H3（含全参考、首尾帧、原生声音） | [H3适配器](references/minimax-h3-prompt-adapter.md) |
| 明确说豆包/Seedance（含编辑、延长、多模态） | [Seedance适配器](references/seedance-prompt-adapter.md) |
| 已选Muse或其他网页工具、底层模型不可见 | 平台无关中文导演稿，记模型unknown；不猜引擎，不追问H3/Seedance |
| 用户最近已明确“后续都用X” | 沿用，直到用户切换 |
| 以上都无法判断 | 只问一次：“这次用H3、豆包Seedance，还是写平台无关中文稿？” |

平台只改变最后的语法和参考交付，不改变剧本、人物关系、空间地图、动作脊柱、时间线或资产真源。只加载当次平台的适配器，两种语法不混用。

## 4. 编译流程

1. **定唯一目标**：人物戏写清谁对谁做什么、为什么；环境片写清观众本段发现什么、为什么现在展示。目标不成立就回剧本层。
2. **参考计划**（代码块外）：唯一`dominant_spatial_anchor`、最小参考集合、每份一个主要职责和保留/排除、冲突审计、音频归属。默认`generation_mode`见项目偏好；硬首尾帧只在用户本次明确选择时启用。
3. **四层编译**，各层不互相重复：
   - **状态层**：本段不变的事实——人物身份与服装、空间、光线、道具归属、轴线、画面人数。写一次，后文用“保持不变”。
   - **行为层**：可观察的动作链，起点 → 一个主要动作 → 可见结果；每个时间块一个主要动作和一个情绪变化。
   - **声音层**：先分三类再写——**旁白**（画面无嘴、无听话人）、**画内对白**（口型同步，说话人 → 听话人）、**内心独白**（指定人物第一人称，嘴唇闭合）。分别绑定声源、听话人和嘴唇状态；平台能力未核的标`post_audio`，不让它成为画面成立的唯一条件。
   - **剪辑层**：只写需要的计划内硬切、同帧承接和稳定尾帧；硬切前后重写景别、轴线、人物位置和道具状态。
4. **平台编译**：按适配器改写语法和参考交付。
5. **自检**：运行`python -X utf8 scripts/lint_prompt.py <文件> --platform <...> --type <...> --duration <秒>`，再看[自审清单](references/checklist.md)中脚本覆盖不到的项。脚本报错先修；警告由人判断。

## 5. 复制区边界

这是唯一定义，适配器和参考只链接这里。

- **只放**模型需要的：角色/对象清单、时空、目标、空间地图、时间块（镜头、动作、视线、对白/独白/旁白）、声音和末尾一次性的连续性约束。
- **不放**：稳定资产ID、`@图`、上传顺序、文件路径、hash、集数段号、“承接上一帧/下一段”、导演说明、验收记录、后期工作流。这些放代码块外。
- 人物戏从`画面内角色：`开始，多角色一人一行（H3全参考原生稿例外，从`subject_definitions`开始）。环境片沿用户为该系列选定的格式，但仍要包含有无人物、旁白归属、空间、运镜、自然过程、切点和尾段。
- 正向描述优先，必要禁止项末尾集中写一次。字数上限按当前入口，默认值见项目偏好；超长先删重复形容词、禁止词和管理话。
- 空间地图写最终应出现的关系，不写它来自哪张参考。
- 用户要完整时长时，主复制正文覆盖完整时长；内部`SHOT/UNIT`不能冒充主交付。拆片只作代码块外的`fallback_split`。委托制作成片时，可按平台上限和剪辑意图规划多个单元，最终交真实完整影片。

## 6. 实片回来以后

拿到`review`的`unresolved`后，先定位层：参考 / 空间 / 动作 / 镜头 / 声音 / 平台语法；一轮只改这一层，保留上一版比较。降级顺序：查输出服从了哪份参考 → 删或裁竞争参考 → 减事件和人物 → 固定镜头 → 拆交互 → 地点或景别变化改计划内硬切 → 文字、字幕、不可靠音频移出模型职责。不要靠堆“电影感、真实、连贯、高清”修。各平台的排错表在适配器里，环境片的实片偏差表在环境片参考里。
