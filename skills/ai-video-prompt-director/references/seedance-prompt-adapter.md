# 豆包内置 Seedance 提示词适配参考

## 何时读取

用户明确说“豆包生成视频”“豆包内置Seedance”“Seedance提示词”，或Seedance成片出现参考串场、动作不连贯、对白错人、镜头不服从、画面像PPT、首尾状态跳变时读取。

本页只是平台适配层。目标、因果、空间地图、参考竞争、动作脊柱、稳定尾帧和复制区边界以主`SKILL.md`及[人物戏](character-drama.md)、[参考与空间](spatial-and-reference.md)为准；默认值见[项目偏好](project-preferences.md)。MiniMax H3任务读H3适配器，两种语法不混用。

## 版本与能力

豆包内置版、字节Seed研究页和火山引擎API可能异步更新，账号和地区也可能不同。凡是时长、参考数量、编辑、延长、有声输出等影响任务，先看当前界面；看不到再问用户，不凭模型名猜永久能力。下表是唯一的版本能力记录，其他段落只引用它：

| 能力 | 1.x（含1.5 pro） | 2.x（2.0 / 2.5） | 依据 |
|---|---|---|---|
| 原生有声 | 有；口型同步式，只给画面内张嘴的人发声，无独立旁白音轨 | 音画一体：语音、环境声、BGM可同时生成 | 1.x火山文档、1.5 pro研究页；2.x火山文档（均访问2026-08-31） |
| 文字引导旁白（不绑口型） | 不支持，只能后期配音 | 支持，含多语言旁白 | 第三方资料＋本项目2026-09-04无人环境片实测出声（界面标2.0） |
| 有人画面中的闭嘴心声 | 不支持；改画内低声自言自语或`post_audio` | 可按旁白写法尝试，验片核嘴唇是否不动；**未经本项目实测**，不稳就`post_audio` | 推断 |
| 最长时长 | 以界面为准 | 2.5研究页称最高30秒；项目默认仍按单段时长偏好 | Seed 2.5研究页 |
| 首帧 / 首尾帧 | 支持 | 支持 | 火山文档 |
| 图片/视频/音频组合参考 | 文档未列 | 支持 | 2.x火山文档 |
| 视频编辑 / 延长 | 文档未列 | 支持 | 2.x火山文档、2.5研究页 |

来源：[Seedance 1.5 pro](https://seed.bytedance.com/zh/seedance1_5_pro)、[Seedance 2.5](https://seed.bytedance.com/zh/seedance2_5)、[火山Seedance 2.x文档](https://docs.volcengine.com/docs/6492/2595411?lang=zh)、[火山Seedance 1.x文档](https://docs.volcengine.com/docs/6492/2165104?lang=zh)。官方多模态与编辑提示词案例都使用自然中文。

原生音频会占用模型能力，常见画面质感、背景音或表现力下降：无语音时画面好，有语音时语音好但画面可能降。画面优先时用“纯画面生成＋后期配音”两步方案——提示词不带台词、心声和口型，声音全部后期加；这是任何版本都稳的兜底。

## 一、先判断任务模式

| 模式 | 使用条件 | 提示词重点 |
|---|---|---|
| 文生视频 | 没有参考图/视频 | 主体、场景、一个主事件、镜头路径、结果和声音 |
| 首帧图生视频 | 一张图明确锁定0秒构图 | 不重写整张图；写从首帧开始的新动作、环境变化、镜头路径和终点 |
| 首尾帧 | 仅用户本次明确要求，且两端兼容 | 写可见中间变化和怎样落到尾帧，不拿它代替多镜头剪辑 |
| 多模态参考 | 项目默认；图片/视频/音频提供人物、场景、物体、动作、运镜、风格或声音 | 每份参考一个最高职责，同时写保留与排除；首图/尾图也可作普通参考或剪辑端点 |
| 视频编辑 | 要直接改变源视频的风格、环境、主体或局部状态 | “只改变什么、必须保持什么”；源视频才是被编辑对象 |
| 视频延长 | 从源视频结尾继续 | 源视频末状态 → 唯一连续路径 → 新的结束状态 |

上传了视频不等于“视频编辑”：只提供走路节奏或运镜时，它仍是动作/镜头参考。有两张端点图、需要稳定尾帧或“从A到B”也不等于首尾帧；仅说“参考这两张图”“从这个画面开始、停在那个画面”仍按多模态参考规划，需要时用计划内剪切。

## 二、参考计划（代码块外）

```yaml
seedance_surface: doubao_built_in / volcengine / unknown
seedance_version: 界面可见版本 / unknown
generation_mode: multimodal_reference
dominant_spatial_anchor: 唯一场景或连续性锚点
minimum_reference_set: []
reference_retention_exclusion: {}
reference_conflict_audit: {}
audio_capability_status: 界面已确认 / 待确认 / post_audio
```

豆包UI中的临时`@图片/视频`和上传顺序由用户最终操作，不写进普通复制正文；正文用“程序员、伴侣、老家客厅、唯一手机”等稳定语义名称。官方2.x案例会写“参考图1/参考视频”，本项目为跨平台稳定改为代码块外映射，正文写最终语义关系。

每份参考的保留与排除：

- 人物身份：保留脸、发型、身形、服装；排除原背景、姿势、机位、手中物和其他人物。
- 场景：保留建筑、材质、光线方向、通道和纵深；排除路人、可读文字、广告和非剧情物体。
- 物体：保留外形、颜色、部件和交互区域；排除背景、摆位和动作路线。
- 动作视频：保留方向、节奏和身体力学；排除演员身份、服装、场景、物体外形和原镜头（除非镜头也是明确职责）。
- 运镜视频：只参考方向、幅度、速度和节奏；不复制原主体、剧情和场景。
- 音频：说明是复用内容、参考音色/语速，还是只参考节奏；不让音频凭空生成新人物。

## 三、复制正文结构

Seedance用自然中文导演描述，不使用H3的`subject_definitions`、`(Sx)`、`<d>`、`overall_soundscape`或六段英文结构。人物戏：

```text
画面内角色：
- 程序员：身份、外观、服装、本段动作与对白职责。
- 伴侣：身份、外观、服装、本段动作与对白职责。
画外声音或对象：……
不出场人物与对象：……

时间与地点：……
本段唯一剧情目标：……
空间地图：世界参照、镜头轴线、左右/深度、朝向、视线、对象路线和结束位置。
全局保持：人数、身份、服装、道具、光线、轴线和焦点稳定。

0.0–X秒：镜头、动作起点→过程→结果、视线、说话人→听话人和声音。
X–Y秒：……
13.5–15.0秒稳定尾帧：……

声音与对白：按人物名称汇总准确台词、听者和环境声；界面无有声能力时标记后期。
画面连续性约束：人物数量、道具唯一性、文字/UI、换景、穿模和尾帧约束集中写一次。
```

环境片用用户选定的格式，示例见[examples/environment-film.md](../examples/environment-film.md)。时长、画幅、分辨率、版本、是否生成音频属于界面设置，写在代码块外；只有界面没有对应控制或用户要求一体化时才简洁写进正文。

## 四、对白、旁白与声音

只有界面当前明确支持并开启音频时，原生对白/音效才是模型职责；否则保持动作和听者反应成立，标`post_audio`。能力按上方版本表判断。

**画内对白（人说话）**

- 不用`S1/S2`和`<d>`。用角色名称写：“程序员面对伴侣、看着她的眼睛，用克制自然的普通话说：‘我想试试。’”
- 每句写说话人、听话人、身体朝向、视线目标、语言、语气和听者闭嘴反应；保持说话人面部清晰不被遮挡。
- 多人对话默认不重叠：上一人说完、听者消化后，下一人才开口。
- 画外对白写清声音来自画外哪个区域、听话人转向哪里；画外角色不因发声自动入画。
- 台词放不下时缩短或跨段，不用加速口播。

**旁白（画外音）**——适用于纪录片解说、广告配音、环境片旁白等一切画面无嘴的声音：

```text
全程温柔治愈的中文女声旁白，画面内没有任何人物和口型，旁白与画面同步推进。
开篇0–4秒，旁白：「末日孤岛，暴雨下个不停。」（画面描述……）
中段4–12秒，旁白：「十二座庇护所，各自亮着一盏灯。」（画面描述……）
收尾12–15秒，旁白：「你的星座，藏在哪一座？」（画面描述……）
```

- 写“旁白”而不是“对白/台词”，并写“画面内没有任何人物和口型”，防止模型补出一张嘴。
- 旁白分段与画面节拍对齐，一句一个beat；15秒约两句，不超时。
- 指定语言、性别、语调比只写“加一段旁白”更稳。
- 旁白与对白不混写。版本不支持旁白又必须AI直接出声时，把内心判断改写成画内低声自言自语（张嘴、口型同步、不对任何人说）；不把应当场说的话偷换成旁白。

**其他声音**：环境声、动作声、电话/电视等角色能听见的声音与观众侧配乐分开描述，不让模型同时承担过多混音层。BGM写进提示词时注明“观众侧配乐、画面内人物听不见”，音量低、不盖台词、不满铺。多段统一配乐的做法见[项目偏好的音乐母题](project-preferences.md#连续短剧的统一音乐母题某短剧项目验证过的做法)。

## 五、动作、运镜、剪切与长时段

官方自然中文案例的共同点：先风格/场景，再主体动作、镜头变化和明确结果。项目补足空间和因果：

- 动作写“起点→过程→可见结果”，例如“右手拿住杯子→抬到嘴边→喝一口→杯子离开嘴唇并停在胸前”，不只写“喝茶”。
- 一个时间块一个主要动作和一个情绪变化；主体动作复杂时镜头固定。
- 运镜写景别、方向、速度、跟随对象和最终构图，例如“镜头沿人物左侧平稳跟随三步后停住”。
- 明显换地点、轴线、人数或景别家族时用计划内切镜，切后重写空间关系。

**30秒（仅2.x且界面支持）**：只在“切开反而更伤”时用——必须连续的完整对话或走位、段落边界本身就是最大风险、一个场景信息量约20–25秒。结构不变，时间码扩到0–30，约5–6个节拍；仍只承担一个主要空间、一组人物、一条主镜头路径；最后1.5–2秒稳定。不稳定时拆回两个同构图单元剪辑。15秒仍是默认的可控、可修复单元。

## 六、编辑与延长

- **多模态参考**：素材只是参考，不是待编辑原片；提示词描述目标成片最终应出现什么，先做参考竞争审计。
- **视频编辑**：“只改变A，保持B/C/D不变”，例如“只把源视频转为水墨风，人物、环境、道具和运镜关系保持”。逐项列出改变和保留，不只写“参考这个风格重做”。
- **视频延长**：写源视频最后可见状态、声音状态、镜头方向、新动作起点和新的稳定终点。多个参考视频只在端点兼容时连接，不让模型猜中间缺失的空间。

## 七、排错矩阵

| 失败 | 先判断 | 只改这一层 |
|---|---|---|
| 角色或场景跟错参考 | 哪份素材同时定义身份、空间或姿势 | 删除/裁切竞争参考，重写保留与排除；不先加长正文 |
| 生成像图文板/PPT | 是否上传了多格分镜、标题卡或只有风格词 | 换干净参考；增加连续的主体/物体/光线变化 |
| 动作乱或跳变 | 是否塞了多个动作，缺中间和结果 | 减少动作，补起点→过程→结果；固定镜头 |
| 对白错人 | 是否只写引号，没有说话对象和听者反应 | 用角色名重写完整说话关系；其他人闭嘴；不加H3标签 |
| 画外声长出人物 | 是否没有声源区域或误传画外角色图 | 删不出场人物参考，写画外区域、听话人和嘴唇状态 |
| 旁白被绑到一张嘴 | 是否写成“对白”，是否没写“画面内无人物无口型” | 改旁白写法；版本不支持则后期配音 |
| 镜头不服从 | 是否只有“电影感/高级运镜” | 补方向、速度、幅度、跟随对象和最终景别 |
| 首尾帧突然换景 | 两端是否不同空间、人数、轴线或姿势差异过大 | 改计划内剪切或重做兼容端点 |
| 没声音或口型不稳 | 界面是否真的支持/开启音频，台词是否超时 | 先确认版本与开关；缩短台词或后期配音 |
| 有声后画质下降 | 是否让原生音频承担了对白 | 改“纯画面＋后期配音” |
| 与H3格式混杂 | 是否出现`S1`/`<d>`/`subject_definitions` | 删除H3语法，恢复自然中文 |
| 一次修改后无法复盘 | 是否同时改了参考、动作、运镜和声音 | 回到上一可用版本，一轮只修一层 |

## 八、Seedance增量检查

通用项见[自审清单](checklist.md)；这里只列Seedance专属：

- 界面版本和能力已知；未知时只用共同能力，没有做版本专属承诺。
- 保持`multimodal_reference`默认；首尾帧只在用户本次明确要求时启用，起始/结束图默认作普通参考或剪辑端点。
- 没有H3的`(Sx)`、`<d>`、六段英文或`<Subject>/<Picture>`标签（lint会查）。
- 每份参考有保留与排除；没有上传图文板、多格联系表或无关角色。
- 旁白与对白分开写；旁白写了“画面内无人物无口型”；版本不支持的声音已标`post_audio`。
