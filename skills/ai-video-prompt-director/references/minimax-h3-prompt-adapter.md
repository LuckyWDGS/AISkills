# MiniMax H3 提示词适配参考

## 何时读取

仅在目标模型或平台明确为 MiniMax H3、用户提到 H3 全参考/首尾帧/原生声音，或 H3 成片出现对白错人、参考串场、镜头不服从、声音层混乱时读取本页。

普通平台无关分镜继续以主 `SKILL.md` 为准，不必加载本页。本页只负责导演和提示词适配，不授权提交视频任务。

## 不改变的项目硬规则

- 项目默认仍是 `multimodal_reference`，不是硬首尾帧。
- 每个生成单元仍只选一个 `dominant_spatial_anchor`，先删参考竞争，再改提示词。
- 平台稳定资产 ID、文件路径、SHA-256、上传顺序和临时 `@图` 继续留在复制区外。
- 用户要求完整 15 秒时，主交付仍连续覆盖 `0.0–15.0秒`，最后至少 1.5 秒稳定。
- 人物因果、人味门、空间地图、180 度轴线、动作起点到结果和听者反应仍先于平台语法。
- H3 原生格式是平台适配层，不替代原始剧本、人物锁定、场次文件或平台无关导演包。

## 一、先判断 H3 任务关系

不要因为上传了图片或视频就自动改变任务类型。先按实际用途判断：

| 关系 | 使用条件 | 提示词重点 |
| --- | --- | --- |
| `T2VA` | 没有硬画面端点，从文字建立完整音画时间线 | 初始构图、一个主事件、动作结果、镜头和声音 |
| `I2VA` | 一张图片是 0 秒真实首帧 | 图片负责初始状态；提示词写动作启动、连续发展和结果，不重新发明构图 |
| `FL2VA` | 用户明确选择首尾帧，且两端兼容 | 写首帧→可见中间变化→逐步缩小差异→准确落到尾帧；优先单镜头 |
| `L2VA` | 一张图片只锁定最终画面 | 从兼容的前状态开始，写人物、物体、镜头和场景如何逐步收敛到尾帧 |
| `reference generation` | 图片/视频/音频只提供人物、场景、动作、镜头、风格或声音参考 | 明确保留职责和排除项，不把素材误写成硬端点或待编辑原视频 |
| `video continuation` | 新内容直接续写某段源视频 | 明确源视频结束状态、继续路径和新音频是复制还是只参考 |
| `video editing` | 直接修改源视频本身 | 才使用编辑关系；仅参考某段视频的动作/节奏不算编辑 |
| `audio reuse` / `audio reference` | 音频信号被直接复用 / 只参考音色、节奏或声音质感 | 分清复制与参考，不因视频文件“带声音”就自动创建音频职责 |

项目常用的全模态手动生成通常属于 `reference generation`。只有用户明确选择硬帧或源视频续写/编辑时，才切换到对应关系。

## 二、把“源文件”和“要复用的内容”分开

MiniMax 官方全参考格式区分四种语义标签：

| H3 原生标签 | 正确含义 | 项目映射 |
| --- | --- | --- |
| `<Subject N>` | 目标视频里实际复用的可见内容：人物、物体、环境、服装、动作、表情、姿势或风格 | 对应项目语义职责，不是文件名；一个人物可由身份图和动作视频共同定义 |
| `<Picture N>` | 图片本身作为首帧、关键帧、尾帧、编辑帧或构图锚点 | 只有图片真正在时间线中承担具体帧/构图职责时使用 |
| `<Video N>` | 源视频整体用于编辑、续写、镜头运动、剪辑、节奏或时间结构 | 视频中的人物/动作若作为可见内容复用，仍抽象成 `<Subject N>` |
| `<Audio N>` | 独立音频信号，或明确启用的同步音轨 | 绑定声音复制/参考职责；编号与 `<Video N>` 独立 |

这说明“一张素材只能产生一个语义内容”并非 H3 官方规则；但本项目仍要求每份上传素材只有一个**最高职责**。如果同一素材确实提供多个剧情必需内容，必须逐项写清；只要它开始争夺构图、身份或路线，就裁切、拆素材或删除。

### 保留与排除必须成对

对每份参考同时回答：

```text
保留：目标视频真正需要继承的脸、服装、对象外形、动作节奏、机位或音色。
排除：原背景、原姿势、原镜头角度、无关人物、可读文字、原路线或原剧情状态。
```

例如：

```text
程序员身份参考只保留脸、短黑发、细框眼镜和服装；不继承参考图的背景、姿势、镜头角度、手中物和其他人物。
动作视频只参考右手放手机的节奏与关节路径；不继承演员身份、服装、场景、机位和手机外形。
```

“保留/排除对”先放在代码块外的参考计划中。若 H3 网页 UI 只能收到普通自然语言提示，再把与成片直接相关的排除项压缩进末尾连续性约束；不写平台临时 `@图`。

## 三、H3 稳定说话人协议

H3 官方格式用 `(S1)`、`(S2)` 标识实际发声者。它与角色参考标签是两件事：`<Subject N>`负责视觉身份，`(Sx)`负责声音归属。

### 编号规则

- 只给实际说话、唱歌、旁白或产生独立人声的来源编号；从不发声的画面人物不需要 `(Sx)`。
- 按目标视频中第一次实际发声的顺序分配一次；跨镜头、画内/画外切换和音频参考中始终复用同一编号。
- 首次发声时，在 `<d>` 外写明人物身份、画内/画外状态、声线、语速、情绪、动作、身体朝向和视线目标。
- `(Sx)`必须放在人物身份之后、发声动词和`<d>`之前；不能先写完台词，再用“She is (S2)”之类的句子补编号。
- 角色的台词对象、听者反应和声源区域继续遵守项目空间规则；`(Sx)`不能替代说话对象。

### 中文对白

H3 原生对白只把语言标签和准确台词放进 `<d>`：

```text
程序员（S1）身体朝向伴侣，视线看伴侣眼睛，用克制、疲惫的自然普通话轻声说：<d>[Chinese] 我只是想先缓几天。</d>
```

- 身份、动作、表演方式和听话人写在 `<d>` 外。
- `<d>` 内不写“程序员说”、镜头说明、语气说明或字幕要求。
- 对用户已经确认的对白，保留原语言、每个字和基础标点；改写对白先在导演层确认，不能在 H3 适配时偷偷改词。
- 默认不让两人重叠说话；每句之间保留听者消化时间。需要重叠、打断或合说时才明确指定。
- 对白不是屏幕文字；另写画面不生成字幕、翻译、对白文字或可读 UI。

### 画外对白与第一人称心声

- 同一人物从画内变为画外，仍使用原 `(Sx)`，并写清声音来自画外哪个区域、对谁说。
- H3 官方画外旁白用明确的 `off-screen voiceover` 关系；每段旁白后立即说明对应画面人物嘴唇保持完全闭合、不做口型。
- 内心独白不能被降级成无归属的“旁白声”；仍要指定人物、第一人称、声线和嘴唇状态。
- `<scenetrans>`只在同一句人声确实跨越可见切镜时使用；`<cutoff>`只在台词被成片结束主动截断时使用。本项目通常避免把台词切在段尾，因此不要为了显得专业而滥用。

## 四、声音拆成三层

H3 官方基础格式把声音分为：

1. **逐镜同步声音**：具体台词、唱词、画内音乐和与某个动作同步的声音，放在对应时间块/镜头中。
2. **`overall_soundscape`**：全片环境声、物理动作声和非语言人声，用 1–4 句连续描述；不要重复完整台词。
3. **`non_diegetic_music`**：只有观众能听见、角色听不见的配乐；写乐器、速度、节奏和动态。没有就写 `N/A`。

电话、电视、收音机、现场乐器或人物能听见的音乐属于画内声音，不属于 `non_diegetic_music`。声音参考只提供音色/节奏时，不能把原参考台词自动带进新视频。

独立中文案例的可用经验：双人对白时让房间底噪自然降低，但不要完全消失；台词结束后环境声恢复正常。把它当混音建议，不把它写成 H3 必然实现的能力保证。

## 五、运镜和切镜使用可测字段

### 运镜三要素

H3 官方建议在有意义时写清：

```text
运动类型 + 构图变化幅度 + 速度
```

例如：

```text
镜头沿同一光轴小幅缓慢推近，焦点始终锁在程序员眼睛。
镜头大幅快速向右平移，直到关闭入户门进入画面右侧三分之一并稳定。
固定机位，镜头位置、焦距和焦点均不移动。
```

中等幅度和正常速度没有叙事作用时省略，不堆术语。区分：推近/拉远是机身移动，变焦是焦距变化，摇摄是机位不动只转镜头，横移是整台相机平移。

### 切镜规则

- 第一镜建立总体风格和初始构图；后续切镜才写严格递增的切点。
- 每次切镜必须增加人物、空间、状态、视点或时间信息；只改变很小的距离/角度时，优先同镜头内运镜。
- 项目的 `cut_reason`、180 度轴线和切后空间重建继续有效。
- 用户要求完整 15 秒时，H3 适配不能把导演 `UNIT` 误当成多条短生成任务。

## 六、微表情要按触发链传播

中文导演挑战的“眼睛先认出、笑意最后才来”是案例经验，不是所有情绪的固定公式。可把它转成可拍的传播链：

```text
可听/可见触发 → 视线重新聚焦 → 呼吸变化 → 喉结/下颌变化 → 嘴角或眼泪结果 → 稳定落点
```

使用原则：

- 只选与角色心理有关的 2–4 个通道，不把眨眼、吞咽、眼泪、微笑全部强塞进每条视频。
- 先写触发到达的时间和空间来源，再写身体反应；人物不能先反应、后听见。
- 情绪通过面部传播时优先固定镜头；运镜复杂时只保留一个表演变化。
- 泪水数量、精确面部解剖或多重细微动作不稳定时，保留视线、呼吸和一个结果，不继续加形容词。

## 七、两种 H3 交付层

### A. H3普通自由文本入口的实用复制稿

用于目标明确为MiniMax H3、但入口只是普通自由文本提示词，没有选择H3“全参考/全模态参考”模式，也没有要求六段原生结构的情况。继续使用项目角色清单、空间地图和 `0.0–15.0秒`时间块；额外加入 H3 稳定说话人和声音字段：

```text
画面内角色：
- 程序员（S1）：……
- 伴侣（S2）：……

0.0–3.0秒：……程序员（S1）面对伴侣说：<d>[Chinese] 我只是想先缓几天。</d> 伴侣（S2）闭嘴听。

overall_soundscape：普通室内底噪、衣料轻响和自然呼吸持续；对白时底噪自然降低，台词结束后恢复。
non_diegetic_music：N/A。
```

`(Sx)`只表示发声者，不作为角色图上传编号。项目稳定资产 ID、参考路径和临时上传绑定继续放在代码块外。

### B. H3“全参考/全模态参考”模式的原生六段稿

只要目标明确为MiniMax H3的“全参考/全模态参考”模式，就默认输出；用户不需要再额外说“原生格式”：

```text
subject_definitions
summary
retention_analysis
detailed_description
overall_soundscape
non_diegetic_music
```

官方要求六段主体使用英文，只有 `<d>` 中的对白/歌词和画面真实可见文字保留原语言。`detailed_description` 对生成任务通常约 350–500 英文词；对白密集时以完整可说时间线为先，不机械凑字数。这个长度建议不覆盖项目通用的 7000 中文字符上限，也不代表越长越好。

原生标签只在这层出现；它们是单次 H3 适配标签，不取代 `CHAR-* / ENV-* / PROP-*` 项目稳定 ID。稳定ID与临时H3标签映射放在代码块外，六段代码块从`subject_definitions`开始。若平台未明确或只是普通自由文本入口，才使用A层中文实用稿。

## 八、按出错模块单变量修复

不要每次失败都整段重写。先从真实成片判断唯一主问题，一轮只修改对应模块：

| 失败 | 先检查 | 本轮只改 |
| --- | --- | --- |
| 对白错人 | `(Sx)`是否稳定、说话人/听话人/画内外状态是否明确 | 说话人注册、`<d>`归属、其他角色闭嘴和声源区域 |
| 参考图串场 | 素材的保留/排除职责和主空间锚点 | 删除/裁切竞争参考，补保留与排除对；不改剧情对白 |
| 动作太乱 | 时间内是否塞入多个事件、动作是否有结果 | 减少事件，改为起点→过程→结果；不同时增加运镜 |
| 镜头不听话 | 是否缺类型、方向、幅度、速度和最终构图 | 只补运镜三要素或改固定机位；不改人物关系 |
| 视频像PPT | 是否只有风格词，没有连续变化 | 增加一个人物/物体/光线/相机的连续变化链 |
| 环境声抢对白 | 声音是否混在一个段落、台词是否在 soundscape 重复 | 拆逐镜声音、`overall_soundscape`和配乐；对白时底噪让位 |
| 画外声变成新人物 | 画外声是否被当成视觉主体或没有区域 | 复用同一 `(Sx)`，写画外区域、听话人和画面角色嘴唇状态 |
| 一次改动后无法判断原因 | 是否同时改了角色、动作、镜头、声音和参考 | 回到上一可用版本，只保留一个变量的改动 |

保留每轮真实结果和改动点。只有单变量修复无效、或问题来自任务本身超预算时，才拆 `UNIT`、计划内剪切、后期配音/合成或换工具。

## 九、H3 交付前增量检查

- 是否先判断了任务关系，而不是看到图片就默认首尾帧？
- 项目语义职责是否在外部参考图计划中稳定；H3临时标签是否只存在平台适配层？
- 每位实际发声者是否只分配一个 `(Sx)`，跨镜头和画内外保持不变？
- `<d>` 内是否只有 `[Chinese]`和准确台词，身份/动作/语气是否都在外部？
- 每句台词是否仍写清听话人、朝向、视线、声源区域和听者反应？
- 画外旁白之后是否明确画面人物嘴唇闭合？
- 逐镜同步声音、`overall_soundscape`和`non_diegetic_music`是否分层，完整台词是否没有重复？
- 参考是否同时写了保留内容和排除内容？
- 运镜是否有明确类型、方向和必要的幅度/速度；切镜是否真的增加信息？
- 失败修复是否只改了一个问题模块，并保留可比较的前一版本？
- 是否仍满足项目完整15秒、唯一主空间锚点、稳定尾帧和手动生成边界？
