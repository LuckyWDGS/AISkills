# 网络过滤诊断与传输选型

用于“是否被大陆屏蔽”“最新搭建技术”“防止再次断网”等请求。目标是定位故障层、降低可识别特征和缩小故障影响；没有协议、端口或配置能保证永久不被屏蔽。用户只要求研究时，保留正式节点和保护规则，交付可评审方案。

日期相关的版本和研究放在[2026-11-16 技术快照](research/2026-11-16-transports.md)；历史实测放在[脱敏审计案例](cases/2026-11-16-network-audit.md)。后续使用先刷新重要来源与现场状态，不把旧结论当作实时检测。

## 先分故障层

| 观察到的现象 | 优先证据 | 暂不能得出的结论 |
| --- | --- | --- |
| DNS错误，固定IP连接成功 | 查询响应、真实解析链路、维护源与覆写 | IP被封、换协议即可解决 |
| TCP握手未完成 | 双端报文头、同探针对照、云层/主机规则、回程 | SNI或UUID有误、TLS指纹导致当前握手失败 |
| TCP成功，TLS/REALITY失败 | 对齐时间的握手日志、版本、SNI/密钥/目标/证书 | 全部TCP或IP不可达 |
| TCP正常，UDP失败 | 已有授权服务的双向UDP响应、路径/MTU/NAT/QoS | ICMP能通所以UDP一定能通 |
| 境外成功、大陆多网失败 | 相同目标与对照、探针身份、方向与原始计数 | 已直接证明拦截设备归属 |
| 临时核心成功、正式客户端失败 | TUN接力、选中节点、DNS覆写、实际加载参数 | 服务端全无问题、临时出口就是直连路径 |

`timeout` 不是过滤的唯一特征。云安全组、主机防火墙、服务未监听、回程路由、服务商源地址策略、运营商丢包和本机规则都可能产生类似表现。没有证据时保留竞争解释，不靠猜测改协议。

## 跨网络对照的最小方法

1. 先按[验证参考](validation.md)证明本机测试走实际物理接口，记录TUN、旧代理、节点级interface/dialer覆盖和路由器变量。临时核心关闭TUN本身不能排除旧TUN。
2. 固定目标IP和少量**已确认开放且属于用户的端口**。相同目标比较大陆不同地区/电信联通移动与境外探针；同一探针再测一台已知可用的授权对照VPS。尽量复用探针ID，比较元数据。
3. 每项做有限重复，例如每探针三次，记录成功数/总数、时间/时区、协议、端口、超时和探针提供方的位置标注。不要扩展为互联网扫描、全端口轰炸或造成他人连接中断的实验。
4. 单独比较ICMP、TCP连接、完整代理握手与应用请求。UDP优先使用现有授权服务的真实响应；“UDP端口显示open/filtered”或未收到ICMP错误不算可达证明。
5. 需要抓包时，双端同步，仅针对授权目标/测试端口/短窗口采集必要头部，区分SYN未到达、SYN-ACK未返回、客户端未ACK和TLS后中断。包在哪一端没出现不能自动定位到某个组织的设备。
6. 如现有境外节点B可用，可用“本机→B→A”的相同A参数作认证/服务对照。记录每一跳、实际出口和UDP能力；不计入大陆直连A或完整浏览器验收。
7. 需要服务商排除云层/上游过滤时，先整理脱敏证据和询问内容；未获发送授权时不代发工单。提供方回应属于外部证据，仍与实际包路径交叉核对。

三网多点TCP失败、境外成功、对照VPS成功，可支持“大陆方向TCP过滤，高度符合GFW特征”。未排除上游策略时，不写“100%确认GFW”；三个端口不能代表全部端口，TCP不能代表UDP，也不能倒推出首次触发原因。公共测量链接可能包含用户部署IP，留在私密项目资料，不放通用技能。

## 选方案前先问它解决哪一层

| 方法 | 可能改善 | 共同故障与代价 |
| --- | --- | --- |
| 同IP多TCP协议，如REALITY/AnyTLS/Naive | 某协议服务、握手或实现故障 | 仍共享IP、TCP路径、主机与上游；TCP握手受阻时不能保证恢复 |
| 同IP TCP + Hysteria2 UDP | TCP与UDP路径/QoS有差异时的备用 | UDP可能独立受限；同IP/主机故障仍共享；先验证双向UDP |
| XHTTP + 正常TLS + 适配的CDN/反代入口 | 客户端入口与源站IP分开，利用HTTP传输路径 | 域名/边缘也可能受阻；HTTP模式、回源、认证、成本、超时需实测 |
| 不同网络的多个入口 → 固定境外出口 | 单个入口或部分路径失败时可换入口，终点出口仍可固定 | 固定出口主机/上游仍是单点；链路增加时延和维护面 |
| 不同出口的完整备份 | 固定出口主机/网络故障的容灾 | 对端观察IP会变化；与用户的固定出口偏好需要权衡 |

同出口多协议并非多入口容灾。仅给一个IP添加更多端口/协议，不会消除它的IP与上游故障。为故障拒绝直连而设置的保护，也不能由健康检查/fallback组替代。

具体 fallback 语义、主用恢复后的回切、手动选节点与长连接影响见[多协议参考](multi-protocol.md)。不要把每分钟健康检查说成每分钟换协议，或把同出口切换说成既有连接无缝迁移。

## 当前客户端的兼容检查

- 记录**实际运行**的客户端核心与服务端版本，核对发行记录、准确tag源码和当时文档。客户端GUI版本不能代替核心版本；“文档支持”不能代替实际互通。
- Mihomo现有版本已支持VLESS XHTTP，不能复用“Clash不支持XHTTP”的过时说法。核对mode、ALPN、padding、复用和download-settings，不能原样照搬Xray JSON；不同实现默认值可能不同。
- REALITY兼容性警告单独核查。一个历史组合经中转能工作，不意味着双方升级到最新后仍兼容；在隔离配置里验证，再按授权更新正式配置。
- Hysteria上游新功能与Mihomo内嵌实现不等价。分别核查Gecko、ECH、QUIC指纹、端口跳跃的支持；Linux专用功能不能直接写入Windows客户端方案。
- AnyTLS使用具备正确证书验证的生产实现；参考示例及默认padding不构成不被识别的保证。Naive需要匹配的客户端/库和服务端，外部辅助进程会扩大代理与防火墙覆盖范围。

## CDN、UDP与新研究的边界

普通HTTPS CDN终止的是正常TLS/HTTP，不能把REALITY原样放到它后面。XHTTP走CDN时使用正常TLS及匹配的HTTP模式；不要求把全部业务都改为HTTP/3。Hysteria2认证后使用自定义协议，官方明确不支持直接套普通HTTP CDN。TCP/UDP四层转发服务另按实际能力核验，不能和HTTP CDN混称。

CDN候选需核对用户拥有的域名、证书、边缘及回源TLS、HTTP/2/请求类型、流式缓冲、POST大小、WAF/缓存/超时、认证路径与使用限制。源站设置合理访问范围，但先保留独立SSH和回滚入口；不要将管理面板或递归DNS暴露给公网。TLS在CDN处终止意味着CDN参与信任边界，目标应用的内层HTTPS仍需正常校验。

UDP端口跳跃只适用于某些端口级限制，不能修复整体UDP或IP阻断。Gecko等混淆降低的是部分流量特征，不提供“不可识别”证明。ECH保护握手名称信息，仍暴露目标IP和其他流量特征；不能假设叠加所有开关必然更安全或更兼容。

浏览器UDP443限制与代理核心自己的QUIC传输是不同对象。部署Hysteria2时保留核心到节点的必要路径，同时验证业务UDP经代理或被拒绝。不能为了套用“阻断QUIC”口诀把节点自身堵死，也不能为它放开所有程序的物理UDP直连。

论文的发布日期、测量日期、国家/运营商与产品可用版本分别记录。只验证首包/局部DPI的方法不是完整代理验收；俄罗斯TSPU有效不证明中国GFW有效；绕过SNI后转为目的站直连的方法可能违背用户隐藏国内出口的目标。新技术不自动成为默认配置。

## 推荐实施与验收顺序

1. 按当前任务范围处理已复现故障。新部署优先用户提供的 VPS；服务端和隔离订阅测完，再只读报告本机的 DNS 悬空出口名、加载错误及保护缺口，获准后修改。遵守[本机阶段约定](local-review-and-approval.md)，保留明确国内白名单和本机回环，不为技术升级恢复 CN 大兜底。
2. 保留能用的路径；对不同入口/传输建立隔离候选。若固定出口是约束，先画明每条路径的入口与终点，在TCP、UDP、DNS分别确认出口一致；配置组名相同不算证据。
3. 先小请求与握手，再在授权额度内测延迟、抖动、重连和长连接；平均测速不能替代持续可用性。不要给用户的日常任务擅自注入断网。
4. fallback候选只包含经过验证的代理，不包含DIRECT。先验证各候选，再做端到端检查：DNS、HTTP、实际业务所需UDP、预期出口。单个204健康检查不能覆盖全部能力；迟滞/冷却必须有该版本支持证据，无原生机制时列待设计，不能编造参数或把 max-failed-times 当作防抖。
5. 后续获部署授权时，每次只改一项并保留回滚。按[故障测试](failure-testing.md)验证节点失效、核心退出、TUN关闭、IPv6/接口变化及恢复；不能只测“节点超时”就称整机fail-closed。
6. 交付“已证实 / 推断 / 未测试 / 待实施”四栏，写明新增服务、依赖、费用、证书续期和运行时路径维护需求。记录技能或完成研究不代表问题已修复。
