# 本机回环代理绕过与连接排障

适用于代理/防泄漏规则调整后 localhost、IPv4/IPv6 回环、UE Zen、开发服务器或本地工具连接异常。只排查已授权目标，保留公网出口保护；不要把本机服务错误扩大成全网直连。

## 分开验证三层

| 层 | 核对方法 | 不能推导 |
| --- | --- | --- |
| 代理选择 | 系统代理绕过、应用配置、进程环境，实际显示 bypass/direct | 服务在监听、TCP 能通或 DDC 可写 |
| 本机传输 | 目标进程身份、绑定地址/端口，IPv4/IPv6 TCP 与小型 HTTP 请求 | 应用配置正确、缓存图有可写节点 |
| 应用就绪 | 同一次启动的日志、实际健康检查与缓存节点写入 | 其他版本/项目也已经修复 |

`localhost` 可能解析到 IPv4 或 IPv6。分别测试 `localhost`、`127.0.0.1` 和 `[::1]`；URL 中 IPv6 使用方括号，NO_PROXY/libcurl 列表通常使用 `::1`。确认服务实际绑定，不能用只监听 IPv4 的服务验收 IPv6。

## 最小配置改动

- Windows WinINet 的当前用户 `Internet Settings\ProxyOverride` 以分号分隔；保留原字符串和类型，只合并缺失的本机项，避免覆盖 ProxyServer/ProxyEnable/PAC 或原有 LAN 例外。不要假设 `127.*`、`<local>` 已覆盖 `::1`；以目标客户端实际选择为准。
- WinINet、WinHTTP、环境变量及应用专属 HTTP 设置相互独立。Windows 环境变量名称不区分大小写；NO_PROXY 通常用逗号分隔。注册表写入后仍要核对实际应用/新进程读取值，Clash Verge 的系统代理管理也可能在重启或切换时重写绕过表。
- 区分持久所有者（客户端代理设置/覆写、用户环境、应用 INI）和生成文件。若只改注册表一次，注明持久性尚未经客户端重启确认；不要宣称永久生效。
- UE 使用 libcurl 的版本可能支持 `[HTTP] HttpNoProxy=localhost,127.0.0.1,::1`，需与该版本源码及实际加载的 Engine 配置对应。备份后合并已有列表，不能用这三个项覆盖用户其他例外；写入某个用户级 Engine.ini 不证明它参与了本次 GEngineIni 合并。
- 本机传输若被 TUN 捕获，确认回环的精确 DIRECT 例外优先于宽泛进程规则；不要把 fake-IP 段、整个 LAN、公共目的地址或任意进程加入直连来修 localhost。

只备份所需注册表值、类型、INI 原内容、存在状态及哈希，放受限目录。准备/应用/验证分开；脚本超时后先读取实际状态，禁止盲目重复写入并以二次备份覆盖原基线。回滚只撤销本次字段，文件缺失与空文件也要区分。

## 可复现的本机对照

用本任务自建、仅绑定回环的临时服务和空闲端口，保持监听直到全部样本完成；记录服务端 peer 和请求标记。先测显式无代理 socket/HTTP，再测目标应用的系统/环境代理路径。新进程内明确记录或隔离 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、NO_PROXY 及大小写别名，不能把运行时读取环境代理的结果冒充 WinINet 选择。只改测试进程环境，不改用户环境来“修好”样本。

`bypass=true` 只证明选择；客户端与服务日志相符的 HTTP 成功才支持回环连通。服务器收到第一个请求就关闭会造成后续地址假失败。临时进程结束前核对命令/开始时间，清理自己启动的监听。

## WSA 10013 与防火墙

WSA 10013 表示本次套接字操作被权限/网络策略拒绝；不能仅凭错误或一条规则名称断言是特定防火墙规则导致，更不能推导用户的 UE 进程也受相同限制。

检查 ActiveStore 及应用、包、服务、地址、端口、接口、用户/安全过滤器和实际执行令牌。规则可以有 LocalUserAuthorizedList/沙箱 SID 限定；Program=Any 或规则名带 loopback 不表示对全机所有用户生效。结合事件/WFP 证据或获准的受控对照才能归因。

执行环境、沙箱或组织管理的安全规则只报告限制，不删改，也不换身份/工具绕过限制。确有证据涉及本任务自建规则且已授权修复时，修改最小作用范围；Windows 显式 Block 通常优先于 Allow，新增一条 Allow 不一定解决冲突。不要关闭整个防火墙或全部 IPv6。

## UE/Zen 与 DDC 的边界

UE 通用 HTTP 日志出现 `HttpProxyAddress` 不说明 Zen 的专用 HTTP 客户端采用相同设置。已查阅的 UE 5.9 Zen 请求代码有 `CURLOPT_NOPROXY="*"`；版本变化后重新查 owning source 和日志。

`Unable to use cache graph 'Installed' because it has no writable nodes available` 表示选中缓存图没有可用的可写节点，可能涉及 Zen 启动/健康、地址、配置、路径权限或磁盘。保留同一次崩溃前的首个 DDC/Zen 诊断，核对图与写入节点，再分层修复；不能因代理存在就认定根因。

`-DDC-ForceMemoryCache` 可临时帮助进入编辑器设置，但不修 Zen 或持久缓存。未重启目标 UE 并看到新日志/缓存可用前，只能交付“绕过设置已写入/某层测试通过”。本案例只确认过 IPv4 回环成功、IPv6 测试进程返回 WSA 10013；没有完成防火墙归因或 UE 修复验收，不把它记为已解决案例。
