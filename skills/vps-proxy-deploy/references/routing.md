# 指定应用与国内服务直连

## 确定生效范围

先读取当前订阅、模式、代理组选择、全局/订阅专用覆写与最终运行规则。用户操作期间可能切换订阅；每次应用或回滚前重新核实，不能凭早先交接恢复到另一订阅。

“全部流量被 TUN 接管”不等于全部流量走国外：规则模式仍可选择 DIRECT。若客户端处于全局模式，先说明全局模式会绕开普通分流规则；按已授权目标使用规则模式，不把修复特定软件扩大成全部国内服务或全部流量直连。

- 服务端订阅规则可供多个设备使用；客户端全局扩展脚本通常只影响这台客户端，但会作用于其多个订阅。
- 只需某订阅生效时选择订阅专用覆写；需要本机切换订阅仍保留时可用全局脚本。先检查现有脚本，再合并，不能覆盖其他逻辑。
- 明确告知落点。改本机脚本不能声称其他设备重新订阅也自动得到同样规则。

## 规则边界

### 常用类别与候选条目

[domestic-direct-candidates.json](domestic-direct-candidates.json) 保存截至 2026-10-19 实例中使用过的 181 条分类规则，包含来源与范围提示。它是历史候选，不是保证完整、永久有效的官方白名单；按本次授权选组或选条目，核对当前安装程序、连接记录和服务文档后再生成。不要为了凑齐历史数量添加用户未请求的软件。

| 类别 | 候选范围 | 选择时的重点 |
| --- | --- | --- |
| ToDesk、微信/企业微信、QQ | ToDesk 主程序/服务，WeChat/Weixin/WXWork/QQ 等进程，以及对应服务域名 | Windows 版本的进程名可能变化；进程规则影响内嵌页面、直接 IP 与整个进程流量；手机不能照搬 `.exe` 规则 |
| 局域网/NAS | RFC1918、回环、链路本地，必要的本地发现与本地域名 | 地址直连不能解决本地域名解析、组播发现或远程 NAS 登录；fake-IP 与 CGNAT/覆盖网络地址不按 LAN 一概处理 |
| 国内网盘 | 百度网盘、阿里盘、夸克、天翼、移动、115、123、微云、坚果云 | 主站之外可能需要专用 API、下载 CDN、精确共享登录主机；不直连整个云厂商域名 |
| 国内购物 | 淘宝/天猫/1688/闲鱼、京东、拼多多、唯品会、苏宁、当当 | 仅列出的站点与资源/支付主机；购物网站直连不表示已验证下单或支付 |
| 国内会议 | 腾讯会议、钉钉、飞书、华为云会议 | 进程与域名覆盖要结合 TCP/UDP 实际命中；官网能打开不等于音视频通话正常 |
| 支付宝网页 | `alipay.com`，以及实际页面引用的 `gw`、`i`、`mdn`、`render-intl.alipayobjects.com` 精确主机 | 后缀包含主站、登录、收银台和接口，不按国内/海外业务区分；资源主机即使带 `intl` 也可能被国内页面使用，按证据判断 |
| 用户指定网页 | `wanyiwan.top`（玩一玩） | 案例页面 `/game/xjskp` 引用了支付宝接口和资源；主站通不等于游戏会话完整通过，其他游戏的第三方资源需另外观察 |
| 雷电模拟器 | 当前现场进程 `dnplayer.exe`、`ld10406.exe`、`ldplayerservice.exe`、`Ld9BoxHeadless.exe`、`Ld9BoxSVC.exe` | PROCESS-NAME 规则覆盖对应进程的域名、IP、TCP/UDP；雷电版本升级后需重新核对进程名，不自动放行 `adb.exe`、浏览器或所有 Android 模拟器 |
| 指定游戏接口/资源 | `babigame.cn`、`hnycgames.cn` 后缀及精确主机 `render.alipayobjects.com` | 游戏页面直连不自动覆盖后续加载的独立接口/CDN；只补用户指定或实际观察到的域名。进程规则不覆盖在其他浏览器里打开的同一游戏 |

最小规则形式示例（只取授权条目，保留原有其他规则）：

```yaml
rules:
  - PROCESS-NAME,ToDesk.exe,DIRECT
  - DOMAIN-SUFFIX,todesk.com,DIRECT
  - DOMAIN-SUFFIX,wx.qq.com,DIRECT
  - DOMAIN-SUFFIX,im.qq.com,DIRECT
  - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
  - DOMAIN-SUFFIX,pan.baidu.com,DIRECT
  - DOMAIN-SUFFIX,jd.com,DIRECT
  - DOMAIN-SUFFIX,meeting.tencent.com,DIRECT
```

在支持扩展脚本的客户端中，把去重后的选定规则插入合适位置并保留原规则；不把示例整个 `rules` 字段直接覆盖现有配置。现有显式禁止/例外若与新 DIRECT 冲突，先判断用户希望的结果再确定顺序。[Mihomo 规则](https://wiki.metacubex.one/config/rules/)、[Clash Verge 扩展](https://www.clashverge.dev/guide/extend.html)

- 优先选择实际观察到的软件进程名/路径、官方服务域名和必要的精确登录/CDN 主机。进程规则覆盖整个进程；共享域名的规则也会影响其他软件对该主机的访问，报告说明这一范围。
- 用户给出 HTTPS 完整网址时，普通域名规则作用于主机，不能按加密路径仅直连其中一个页面；说明同主机/后缀范围。先检查公开页面和必要资源，不能为一个网页直接放行整个共享 CDN。用服务后缀替代本任务旧的精确 DIRECT 条目时可清理被包含的旧条目，保留其他策略和例外。
- 局域网/NAS 使用已核实的私有地址段与主机名。IP 规则可用 `no-resolve` 避免为了匹配而触发额外 DNS；它不会清除先前已解析出的 IP。[Mihomo 规则与 no-resolve](https://wiki.metacubex.one/config/rules/)
- 检查实际 fake-IP 地址段，不把它当作普通 LAN CIDR 直连。公网 NAS/DDNS、异地 NAS 和覆盖网络地址根据现场判断，不猜域名、不开整段公网直连。
- 窄范围 DIRECT 应排在会拦截它的兜底规则之前，包括现存的 UDP 拒绝规则。规则按顺序匹配；读取真实运行规则确认优先级。
- 不为某远程软件新增整个浏览器 DIRECT、整个云厂商域名 DIRECT、所有 UDP DIRECT 或所有中国 IP DIRECT，除非用户目标确实需要该范围。
- DIRECT 连接仍可能使用既有远端 DNS，不能只凭规则名断言 DNS 已直连。要改变 DNS 时单独核对授权、解析链路与对比证据。
- 本机 DIRECT 只表示绕过本机所选代理；上游路由器仍可能代理或多 WAN 转发。不能承诺本机国内规则一定解决路由器层面的远程连接问题。

## DIRECT 与 DNS 分别验证

读取最终运行配置的 `nameserver`、`nameserver-policy`、`direct-nameserver`、`direct-nameserver-follow-policy`、`proxy-server-nameserver`、`respect-rules` 和 DNS URL 的指定出口。DIRECT 站点仍依赖 VPS DNS 时，节点/DNS 故障可能影响国内访问。先报告这条依赖；分流授权不自动要求连带更换解析器。

若用户授权改善国内 DNS，独立比较实际网关/本地解析与远端解析，并考虑本地域名、私有 DNS、fake-IP 和解析引导循环；再按安装版本选择最小配置。不要机械套用“开启 respect-rules”“填国内 DNS”“全局模式”之一。[Mihomo DNS](https://wiki.metacubex.one/config/dns/)

## 应用、验证与回滚

1. 在复制含私密配置的文件前创建受限目录/ACL，并排除 Git；记录当前订阅、组选择、核心 PID、脚本和配置哈希。原始订阅、合并配置、运行时分别保留所需证据。
2. 在备份副本上生成候选；脚本应可重复应用且不堆叠重复规则。深比较确认只改变授权字段；用实际核心版本运行配置检查。全局脚本影响多个相关订阅时，检查当前和目标候选。
3. 优先用应用支持的更新流程；采用核心 API 热加载时同时维护合法的持久覆写来源，避免下次刷新丢失。不为更新规则重启整个客户端或关闭所有连接。
4. 验证实际运行的规则顺序、代理组/模式/TUN、核心 PID，以及小请求/目标连接的 DIRECT 命中。另测国外控制请求与出口；网页 HTTP 200、规则命中不能代替真实远程会话、NAS 登录/文件传输或会议通话验收，未做就注明。
5. 回滚前检查当前订阅及文件哈希。若用户已切换订阅，重新针对当前配置撤销本次规则；不能强行覆盖旧备份从而改变用户当前节点。保留完整原始规则和无关配置。

热加载后用新连接验证；既有长连接可能继续使用旧代理链，提示重新打开相关页面即可，不为此关闭全部连接。游戏接口根路径返回 403/404 与路由失败分别判断：TLS、DIRECT 命中只证明连接和路径，不能宣称实际带签名的游戏接口或完整游戏会话已通过。

规则 API 可能同时返回动态命中/未命中计数和时间；变更保护比较规则定义及禁用状态，不把正常增长的统计误判为用户改配置。连接嗅探开启时，在发送 TLS 握手后按测试连接的本地源端口核对命中，避免尚未完成嗅探就误报没有连接。现有 Windows named-pipe 读取器若不支持并发，串行采集 API；采集异常与站点连通失败分别记录。
