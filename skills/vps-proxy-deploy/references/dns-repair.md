# DNS 日志定位与局部修复

用于已有 DNS 上游错误、域名请求超时或“先 DNS、后 BBR”的维护任务。不要把某次上游故障固化成所有 VPS 都应更换某供应商的默认策略。

## 先区分故障层级

对齐客户端与服务器时间、域名、查询类型和持续时间。相同域名在同一窗口出现上游 502/超时，是有价值的关联；没有请求标识或抓包时，不称为逐请求因果证明。服务器到解析器的失败发生在 VPS 上游链路，不能仅因用户路由器开了代理就归因于路由器。

最小证据包括：

- 实际客户端的新建 HTTPS 请求：域名目标与固定目标 IP 分开，保留正确 Host/SNI 和证书验证。确认客户端/服务端嗅探与目标重写，固定 IP 形式本身不能保证整个链路完全没有 DNS。
- VPS 本机到实际 DNS 监听地址的多域名 A/AAAA 查询，记录 rcode、答案、耗时和失败；缓存命中与上游访问分开。不要为测试清空所有用户缓存。
- 当前 DNS 服务配置与运行版本、对应时间段错误日志、资源/服务状态；输出只包含测试域名或脱敏错误，避免收集其他浏览历史。
- 同机到候选上游的独立测试，以及 DNS 服务自身支持的上游测试。自写 HTTP/1.1 客户端得到 505，不能直接替代生产客户端 HTTP/2 路径的 502 证据；比较协议和请求体后再解释。

后续查询成功不能否认前一次间歇错误。若域名与固定 IP 都失败，DNS 可能只是其中一项；不要用更换 DNS 解释所有 TLS EOF。

## AdGuard Home 的最小修改

按安装版本核对 API；例如 v0.107.79 支持 `GET /control/dns_info`、`POST /control/test_upstream_dns`、`POST /control/dns_config`。只通过已有受保护管理路径访问，凭据不出现在日志或命令输出。版本源码与 schema：[OpenAPI](https://github.com/AdguardTeam/AdGuardHome/blob/v0.107.79/openapi/openapi.yaml)、[DNS API 实现](https://github.com/AdguardTeam/AdGuardHome/blob/v0.107.79/internal/dnsforward/http.go)。

1. 保存 root 限权目录中的 YAML、相关运行时 API 字段和基线哈希/PID。配置文件与内存状态可能不同，不能只备份磁盘就认定保存了运行行为。
2. 独立确认候选上游能回答正常 DNS 请求。若只发现一个上游间歇错误，优先替换该条，保留模式、超时、bootstrap、fallback、DNSSEC、监听和客户端配置。两条同服务商地址不等于跨服务商容灾；替换服务商也可能改变其内置域名过滤行为，报告这一差别。
3. 通过支持的局部 API 更新授权字段；API 热更新不需要进程重启，但仍可能重建内部 DNS 监听/连接，不承诺绝对零瞬断。不要运行中盲目整文件覆写，也不要同时更换客户端解析策略、BBR、协议或端口。
4. 对比持久 YAML 的语义和运行时字段；多出的变化先查证，不自动忽略。v0.107.79 的空 `blocked_hosts` 会初始化为 `version.bind`、`id.server`、`hostname.bind`，API 保存时可能把默认值写回；`upstream_mode` 的 API 空串也可能表示 load_balance。应结合更新前运行时与[版本源码](https://github.com/AdguardTeam/AdGuardHome/blob/v0.107.79/internal/dnsforward/config.go)判断，不推广成任何字段差异都正常。
5. 准备只撤销本次字段的回滚，并检查当前字段是否已被后来改动。若第一次调用后的结果不确定（如 SSH 断开），先读取配置/API/远端结果文件，再决定是否重试；不要重复执行可能已完成的写入。

修复服务器内部解析上游且订阅内容未变时，不需要为了该改动刷新客户端订阅或修改 Clash DNS 覆写。若另有 DIRECT 站点仍依赖代理 DNS的问题，按[分流参考](routing.md)单独处理。

## 验证与结果表述

按顺序验证服务端多域名查询、上游测试、客户端域名/固定 IP 新连接、实际 TUN 请求与测速 URL，并核对配置/PID和选择未意外改变。用限定的小样本验证，不运行大流量测速。

日志报告必须写清起止时间、时区与检索条件。例如只读取变更后 42 秒的日志，应写“这 42 秒未检出所匹配错误”，不能写“之后一直没有报错”，也不能将它当成稍后 BBR 测试期间无 DNS 故障的证据。短窗无错误只支持保留候选配置，不能证明间歇问题已永久消除。

仍有超时，保留 DNS 设置并按已获授权开展 [BBR 单变量比较](performance.md)或链路诊断；授权改动完成与剩余故障未解可以同时成立。报告原始计数和局限，不把所有后续恢复都归功于刚才的改动。
