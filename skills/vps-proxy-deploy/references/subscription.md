# 订阅、名称、流量与证书

## 成品订阅

- 优先使用部署版本提供的原生 Mihomo 订阅。客户端支持 VLESS REALITY 时不要误用会过滤不兼容协议的旧 Clash 格式。
- 节点名短且稳定，例如“美国 GTT”；订阅标题独立，例如“美国 GTT · 自用”。地区/线路信息要真实，未知就用用户指定标签。
- 流量、到期日、重置日不要拼进每个节点名；名称变化可能破坏代理组选择和缓存。中文乱码时检查 UTF-8、标题头编码和客户端支持方式，不反复改 UUID。
- HTTPS 反代只开放指定私有订阅路径，其他路径拒绝；避免把面板或整个原生订阅服务一起暴露。敏感路径不要记录到通用 access log。不要向公共订阅转换站提交私有链接。
- 下载时保留 TLS 校验，校验 HTTP 状态、内容格式、响应头、预期节点和字段，并用用户实际核心做语法检查。防止拿到登录页/HTML 200 却当作有效 YAML。
- 最终成品的 DNS、代理组和路由规则要一起验证。测试组只含目标节点，避免 DIRECT 回退造成误判；正式订阅则按用户分流需求配置，不擅自全局代理或阻断所有 UDP。
- 用 YAML 解析器合并配置，拒绝重复键或先明确处理重复键；不要把 `interface-name`、端口、控制器等简单拼到 YAML 前面。

## 流量与月重置

`Subscription-Userinfo` 常用形式：

```text
upload=上行字节数; download=下行字节数; total=额度字节数; expire=Unix秒
```

使用真实计数。确认 `expire=0` 在当前服务与客户端中的语义后再表示不过期。卡片刷新的是订阅响应头，不一定是实时计费。

- 供应商 GB 与 GiB 要区分：1 GB = 10^9 字节，1 GiB = 2^30 字节。不能把“600 GB”自动转换成“600 GiB”。
- 客户端可能按二进制缩放却标成 GB；例如 1000 GB = 1,000,000,000,000 字节，约显示为 931.32 GiB。不要为把卡片数字改成 1000 而暗中增加额度。商品标称额度、管理后台额度、订阅显示总量和实际硬限制分开核对；差异不等于已获升级。
- Xray 客户端上传+下载通常只是该客户端经过代理的计数；供应商还可能计入其他服务、协议开销，或采用单向计费。不得把估算“剩余”标成供应商权威余额。
- 先核实供应商重置日、计费方向、时区和套餐到期日。无法核实时明确标注假设，不把本地电脑时区当账期时区。
- API 的字段名可能误导。历史 3x-ui 3.9.0 的 `totalGB` 存字节；`trafficReset` / `trafficResetDay` 控制流量周期，而 `resetDay` 属于到期续期逻辑。以后按安装版本再次核实，别凭名字猜单位。
- 只修改本任务 client 的额度/周期，保留已有 up/down。订阅刷新和改节点名不应清零；手动重置本身是单独有副作用的操作。
- 使用小额请求观察计数增加，等待统计周期后再比较；无需为验证流量条做大流量测速。

仅获授权修改展示时，保留原始 up/down、硬额度和到期执行设置。物理网卡 RX+TX 账本是服务器估算，不是供应商计费 API：需要处理重启/计数回退/月边界/时钟与网卡变化、持久采样和崩溃末尾丢样。起始时间不覆盖整个账期时不能把它标为完整已用量，也不能把截图数字伪装成实时供应商同步。若通过订阅头适配层展示，应验证 YAML 正文未变、后端仅 loopback、HTTPS 私有路径仍受限，并为接口断续与账期边界保留不确定性。

历史字段出处：[3x-ui v3.9.0 订阅头](https://github.com/MHSanaei/3x-ui/blob/v3.9.0/internal/sub/calendar_expire.go)、[月重置任务](https://github.com/MHSanaei/3x-ui/blob/v3.9.0/internal/web/job/periodic_traffic_reset_job.go)。

## 可信 HTTPS 与自动续期

有用户控制的域名时使用对应证书；只有 IP 时先检查当时 CA 和 ACME 客户端的 IP SAN 支持。2026-10-12 官方资料确认 Let's Encrypt 支持 IP 证书，需 shortlived profile，当时有效期为 160 小时；未来执行时重新核对，不硬编码旧期限或命令。[官方说明](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)、[证书 profiles](https://letsencrypt.org/docs/profiles/)

- HTTP-01 需要公网 TCP 80 的 challenge 路径；其他路径可拒绝。不要把订阅端口 8443 误认为 HTTP-01 的验证端口。[挑战类型](https://letsencrypt.org/docs/challenge-types/)
- REALITY 代理占用 443 时，不为签订阅证书随意停掉代理；选择适用的验证方式和独立 HTTPS 监听。
- acme.sh 使用 `--install-cert` 将文件部署到 Nginx 使用的路径；不要把其内部工作目录当成稳定生产证书路径。[acme.sh 安装证书](https://github.com/acmesh-official/acme.sh#3-install-the-cert-to-apachenginx-etc)
- 续期成功后先 `nginx -t`，再 reload。一个调度入口即可；避免 cron 与 systemd timer 重复签发。
- 调度频率、ARI/续期窗口、失败重试和有效期须匹配；短期证书不能照搬按月巡检。
- 验证证书链、SAN、有效期、证书与密钥配对、外部实际提供的证书、计时器 enabled/active/next run、上次服务结果和 reload hook。
- `oneshot` 服务成功结束后的 inactive/dead 可能正常；结合退出码判断。检查配置成功不能证明未来续期已执行，不为证明状态反复强制签发。

## 客户端展示

Clash Verge 订阅卡片显示的 `:8443` 可能是下载订阅的端口，代理节点连接 `:443` 并不矛盾。分别检查“订阅 URL”和“节点 server/port”。服务端改标题后客户端卡片可能保留本地名字；只对目标订阅刷新/编辑名称，再核对代理页的稳定节点名。

刷新已有订阅时使用该卡片的更新操作，不以重复导入制造另一个条目。记录更新前后的时间戳、统计元数据、当前订阅与代理组，以及运行规则/覆写哈希；下载成功与客户端已刷新是两回事。订阅已经选中且运行时与目标一致时，无需为了“切换过去”先切到别的节点。目标卡片刷新仍保留旧自定义标题时，可在授权范围内单独改为稳定名称。
