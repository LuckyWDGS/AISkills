# 路径验证、客户端验收与检测解释

## 先隔离验证环境

1. 发现用户当前核心、系统代理、TUN、物理网卡/地址和路由。只读查看相关配置，不广泛输出其他订阅。
2. 从最终 HTTPS URL 下载私有 YAML 到受限工作目录，核实证书、HTTP 状态和订阅字段。下载本身也要区分经过旧代理或物理直连。
3. 创建独立测试配置和独立工作目录：空闲 loopback 代理/控制端口、随机控制器 secret、`allow-lan: false`、TUN 关闭、不设置系统代理。不要覆盖客户端正在使用的配置。
4. 对临时核心设置当前机器实际的 `interface-name`，检查每个目标节点的同名覆盖、`dialer-proxy` 和继承配置。测试只选该节点，禁止通过旧节点接力或 DIRECT 回退。
5. 清除测试请求对代理环境变量的依赖，显式使用测试核心 HTTP 端口。SSH/订阅直连需要时使用操作系统支持的接口绑定；仅绑定源 IP 不一定足以排除 TUN。不要硬编码历史网卡名或索引。
6. 记录配置路径/哈希、核心 PID/版本、网卡、目标 server/port、代理组选择和到 VPS 的实际连接/路由证据。必要时用范围受限的抓包核对源接口；出站流量不得经用户原有代理。

`interface-name` 的含义见 [Mihomo 全局配置](https://wiki.metacubex.one/config/general/)；节点级字段和 `dialer-proxy` 见 [出站通用字段](https://wiki.metacubex.one/config/proxies/)。

物理接口绑定不绕过路由器。若路由器另有代理、多 WAN 或负载分配，记录为未控制的路径变量；成功连接出现多个公网源地址只是路径线索，不能单凭它认定多线路导致失败。用户只要求修节点时，不擅自登录或改路由器配置。

## 按层验收

| 层级 | 有效证据 | 不能代替的证据 |
| --- | --- | --- |
| 订阅 | 可信 TLS、合法最终 YAML、预期字段 | 浏览器打开一个订阅卡片 |
| 传输与 REALITY | 已核实物理路径的真实代理请求 | 端口 TCP connect 成功 |
| 延迟与稳定性 | 实际客户端测速 URL 成功、连续小请求结果 | 一次成功或 ICMP ping |
| 出口 | 受控目标的出口 IP 与预期一致 | 地区标签或代理组名字 |
| DNS | 查询结果及预期解析链路证据 | 只看到 fake IP 或装了 DNS 服务 |
| 客户端 | 原客户端刷新/选择后的核心状态和请求结果 | 另开的测试核心成功 |
| TUN | 无显式 HTTP 代理的请求及路由/出口证据 | 经客户端 HTTP 端口请求成功 |

默认用 10 次小请求查间歇失败，报告成功次数/总次数和响应码。测试 URL 使用当时可用的 generate_204 类地址；核实当前客户端真正使用的测速 URL，HTTP 与 HTTPS 都可能不同。10/10 是一次有限样本，不是长期稳定性保证。

脚本 [probe_proxy.py](../scripts/probe_proxy.py) 仅完成 HTTP 代理小请求和出口检查。它有意将 `physical_path_verified`、`dns_path_verified`、`client_tun_verified` 写为 false，避免报告被误当作完整验收；将额外证据单独写入总报告，不伪造脚本验证能力。

DNS 需要检查真实使用的 resolver；若应经 VPS 私有 DNS，可短时启用该服务查询日志，发出唯一的测试名称，检查对应条目和上游。随机名称可能合法返回 NXDOMAIN，它可以证明请求到达，但另需已知域名的有效解析结果。恢复原有日志配置，不长期保留用户浏览历史。

出现有时间/域名关联的上游故障时，读取 [DNS 故障与局部修复](dns-repair.md)。固定目的 IP 测试须保留正确 SNI，并核对[域名嗅探和目标覆写](https://wiki.metacubex.one/config/sniff/)，否则不能将结果描述为已完全绕过 DNS。

## 超时阶段与维护连接

- `CONNECT 200` 可能只是本地代理接受了 CONNECT 请求，不证明远端 TCP/REALITY 已完成。某些核心版本的 `connect error: context deadline exceeded` 包含拨号与协议握手，按实际版本源码确定边界；不能由错误文字直接断定 TCP 不通或 Reality 被阻断。
- 以请求开始、失败时间和核心/服务器日志定位。需要抓包时，仅采集授权目标、测试窗口和必要头部，优先关联测试端口；只有成功连接的抓包不能解释未捕获的失败。
- SSH banner/连接中断不是 DNS 故障的替代证据。维护连接保留主机密钥验证，可用有界 keepalive；连接断开后写入是否执行未知时，重连只读检查受限结果文件与实际状态，再重试或回滚。不要原样回显带认证参数的异常。
- 报告实际观察窗口；系统默认、已有连接、网站成功率、原始 TCP 吞吐分别记录，不拼成“网络完全正常”的结论。

## 真实 Clash Verge 验证

- 先保存原订阅标识、当前代理选择、相关覆写开关和必要备份。用户已授权客户端修复时直接继续，不重复问许可。
- 用可用的应用 API/CLI 或 Windows `computer-use` 技能进行操作。读取该技能再自动化 UI，每次操作后刷新状态；别复用陈旧元素编号、窗口句柄和截图坐标。
- 只刷新本任务订阅，检查稳定节点名和 server/port/SNI。必要时编辑本地订阅标题，不刷新或修改其他订阅。
- 选择目标订阅和目标节点，测速后从实际核心 HTTP 端口验证网页及预期出口；用户使用 TUN 时另外验证无显式代理的流量。确认 DOM/UI 选中状态和核心加载状态一致。
- 对比源订阅、合并配置和运行时。Clash Verge 全局/订阅专用 DNS 覆写可能覆盖订阅的 DNS；先确认合并结果，再最小修改。
- HTTP 控制端口未监听不等于核心没运行。Windows 可能使用命名管道；从当前配置和实际可用管道发现，别盲猜 9090/9097 或机械替换历史 pipe 名。只输出所需非秘密字段。
- 窗口黑屏、激活失败且桌面锁定时，暂停 UI 操作并请求用户解锁；可以继续独立服务端检查，不能宣称客户端已验收。
- 黑色截图本身不能证明桌面锁定或应用不可读；有可用无障碍树时按 Computer Use 指引检查。激活/输入失败后依该技能做一次窗口重新发现与恢复，仍失败就报告原始错误并请求用户完成具体按钮操作，不用其他注入方法绕过。可继续独立网络/API 检查，分别报告已加载状态和未完成的 UI 动作。
- 新订阅导致断网时，及时恢复记录的原订阅/节点，继续在隔离核心中分析；别通过停止原核心“修好”测试。

## 常见现象的判断

| 现象 | 下一步 |
| --- | --- |
| 可以导入、节点名异常 | 查订阅生成模板、编码和本地标题；别把动态流量拼进节点名 |
| TCP 通，但测速失败 | 查核心兼容性、UUID/flow/SNI/密钥/short ID、系统时钟和握手日志 |
| 独立核心通，实际客户端不通 | 先排除旧 TUN 接力，再查实际加载配置、DNS 覆写、模式与组选择 |
| 偶发超时 | 固定其余变量，比较端口/目标/网络的重复结果；不要用一次成功盖过丢失样本 |
| 测速失败但网页正常 | 核对测速 URL、超时阈值及该网站可达性，不直接重装服务 |
| DNS 黑洞、resolver_count=0 | 解释为测试未观察到解析器；检查测试自身成功率，再决定是否需要网络诊断 |

`fake-ip` 是 Mihomo 的正常 DNS 模式：给应用虚拟地址，再由代理处理连接。`resolver_count=0` 既不能单独证明 fake-ip，也不能证明全部 DNS 未出网、DNS 泄漏、节点损坏或平台必然识别。网页正常时先保持配置；真正要检查 DNS，按上面的链路验证执行。[Mihomo DNS](https://wiki.metacubex.one/config/dns/)

用户要求 IP/AI 服务可用性检查时，再做范围对应的测试。第三方分数、机房分类、首页 HTTP 200、未登录 API 401、Cloudflare challenge，分别代表不同事实；不能据此承诺账号可用、不会风控、住宅 IP 或“绝对纯净”。混合旧 TUN 与显式 HTTP 代理时出现不同 WebRTC IP，应先确定路径，不能直接认定新 VPS 泄漏。不要为了消除检测指纹去改造风控规避方案。

账号主页/评论的 IP 属地不是实时出口检测。先明确是当前电脑浏览器还是另一设备 App，核实对应请求在实际核心中的路径和受控出口；有延迟、历史记录或平台分类的可能时标为待证实，不把其中一个解释当成已查明原因。

## 请求方法与 TLS 客户端差异

HEAD 返回 405/501 或与浏览器行为不一致时，可做一次有时限、限制读取量的 GET。Windows curl/Schannel 报 TLS 错误不自动证明节点整体断网：固定 URL、代理、解析结果及其他变量，使用另一合法 TLS 实现顺序比较；需要时复用同一 SSLContext 降低测试设置差异。保留证书验证和失败样本，后续成功不能反推先前失败原因。不同 DNS 得到不同 CDN IP 也不是故障归因；还需各 IP 的同条件 TLS/请求证据。

## 回收与结果记录

只终止本任务创建且命令路径核实的临时进程，验证测试端口释放；只删除本任务临时转发规则。保留最终私有配置、最小脱敏结果与回滚路径。记录四种状态：自动实测通过、用户确认、未验证、失败，不能混写。
