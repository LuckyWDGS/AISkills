# 检测站、评分与真实出口证据

用于用户要求 Net.Coffee、ping0 或环境评分检查的场景。检测站是观测工具，不是 AI 服务的官方风控接口。先完成路径、功能和泄漏验证，再解释分数；不要为了达到阈值伪造设备或修改正常语言、字体。

## 先记录测试对象

记录时间/时区、URL 与页面或脚本版本、浏览器及配置目录、实际核心与节点、系统代理/TUN、每一跳、最终出口、测试方法和未完成项。至少分清：

| 测试 | 能证明的范围 | 不能冒充 |
| --- | --- | --- |
| 指定 IP 的查询页/API | 该数据库对输入 IP 或网段的判断 | 浏览器正经此 IP 上网、DNS/WebRTC 安全 |
| 显式 HTTP 代理请求 | 这次 TCP/HTTP 的路径与出口 | 原浏览器、TUN、UDP、所有 CLI |
| 独立核心的 DNS | 被观察到的这几次查询 | 所有应用、自带 DoH、物理接口 DNS |
| 浏览器环境检测 | 当前页面实际完成的项目 | Claude Code、桌面应用或另一个浏览器 |
| 经中转访问目标节点 | 中转后目标节点的认证/转发能力 | 大陆到该节点直接可达 |

多个核心同时运行时，以实际请求关联的连接为准。不要把正式浏览器节点 B 的结果算给临时 HTTP 节点 A；HTTP 代理对 UDP 的覆盖尤其需要单独证明。

## 各站解释方法

| 来源 | 检查重点 |
| --- | --- |
| [Net.Coffee Claude](https://ip.net.coffee/claude/) / IP 查询页 | 总分、IP信誉、出口一致性、DNS、WebRTC是不同项目；保留实际返回 IP、CIDR、ASN、分类及脚本版本 |
| [ping0](https://ping0.cc/) | 记录是否取得指定 IP 的正式结果；Turnstile/其他验证页表示未测完，不绕过挑战，不编造绿色 |
| [Vercel 环境检测](https://fuck-claude.vercel.app/zh/) | 浏览器分项、IP纯净度 API 和命令行估算接口分别报告；保留 estimate、coverage、未检测项 |
| [另一环境检测版本](https://fuck-claude.com/) | 实际项目、权重与版本可能不同；不能与 Vercel 版本共用阈值或默认都包含 WebRTC |
| [Claude 域名候选页](https://ip.net.coffee/claude/site.html) | 仅作为带获取日期的候选清单；结合官方域名、实际连接和默认出口检查，不能宣称穷尽所有遥测/第三方域名 |

网站标为“住宅”与“机房”冲突时，记录分歧，不挑有利标签。响应 IP 与查询 IP 不一致或返回整个 /24 时，不能称为精确主机结论。地区库、IP历史信誉、TCP可达性、账号资格互不等价。

语言、中文字体、Intl 或 Emoji 命中只是该工具选用的地区特征，不是国内公网出口泄漏证据。浏览器分数也不能直接解释 CLI。用户要求 90/100、全绿或风险分低于 30 时，可记录目标与差距，但不承诺分数代表服务放行、不封号或不被网络屏蔽。

## 空结果不能算严格通过

2026-11-16 读取的 [Net.Coffee 脚本](https://ip.net.coffee/claude/claude-page.js?v=20260916a)存在以下覆盖边界；后续使用须重读实际版本，不能假定网站永远不变：

- DNS 未收集到解析器时也显示绿色“DNS 加密或未暴露出口”。无结果不等于加密、正确代理或未出网。
- WebRTC 等待约 5 秒，空候选也显示绿色。阻断、超时、DNS故障和测试自身失败都可能产生空结果。
- `publicUdp` 判定排除 IPv6，并排除整个 `172.*`，超出了 RFC1918 的 `172.16.0.0/12`。这段逻辑不能覆盖所有公网 IPv4/IPv6。

这些缺陷不证明用户已发生泄漏，只说明“页面全绿”不足以作严格验收。DNS 使用唯一查询名、正常解析结果和权威端/核心证据交叉核验；解析器出口在国外也不单独证明客户端到解析器的链路已加密。

WebRTC 记录 ICE 收集状态、host/srflx/relay 候选及相关地址、实际 STUN/TURN 路径；国内/国外、域名/数字 IP、IPv4/IPv6按可用范围分别测。要求保留功能时还需正常基线、DataChannel 双向收发和失败后的恢复样本。详见[流量防泄漏](traffic-privacy.md)与[故障测试](failure-testing.md)。

## 操作边界与报告

- 用户要求不打开/不登录 Claude 等实际服务时，不创建会话、不使用凭据。第三方检测站可能自动请求服务的 trace/可达性端点，应记录该行为；如用户禁止任何目标请求，先查测试代码，使用离线候选与受控端点。
- 站点/API收到的是测试 IP 和浏览器/请求元数据；不上传订阅、密钥、控制器信息。不要把私有 IP 查询路径或公共测量 ID 带进通用技能案例。
- 检测失败先区分挑战、服务错误、DNS、TCP、TLS与超时。不要仅为消除警报就关闭 Fake-IP、TUN、证书验证或既有保护。
- 国内明确 DIRECT 白名单对所有访问该主机的页面生效。国外网页调用这些服务时，服务端可能看到国内出口；页面能否读取/关联结果取决于跨域和服务行为。AI主域名规则不能消除全部第三方风险。用户取消整浏览器代理后，不擅自恢复。
- 用“已通过 / 已失败 / 未验证 / 用户确认”四种状态；结果归属到具体路径和观察窗口，不把 API 估算、浏览器全测和故障保护合并成一个分数。
