# 内容、热点与复盘

本文件管：栏目与观众承诺、证据分层、当次热点与话题、包装、复盘口径。发布状态与提交规则见 [publishing.md](publishing.md)。

## 栏目与观众承诺

当前默认目标是积累愿意持续观看的粉丝。下面的选题、配比、时段都是编辑建议，不是平台算法或已证实的热门规律。

“用 AI 做的”本身不构成关注理由。先为账号定一个**观众承诺**——观众在这里能持续得到什么，例如“每期一个可以停留的治愈空间”或“每期用一个小故事讲清一个工具”。具体承诺和栏目由用户决定，记在 `operations.json` 的 `working_direction`；本文件的例子只用来说明写法。

- 作品、图册、制作解析围绕同一承诺；不随机混入与承诺无关的题材（如财经数字人、明星变脸、工具新闻）。
- 关注和追更的理由来自：第一眼的向往或有趣结果、值得再看或收藏、知道下一期还有什么、自己的偏好得到后续回应。
- 塑料质感、虚假动态、乱码、机械旁白和重复模板会损害信任，不能靠标签修复。
- 制作解析只在服务同一批观众时少量加入，不为展示接单能力挤占主线。

### 多平台同步

主平台和同步平台由用户决定，记在运营档案。以抖音为主、发布后同步其他平台（如 B 站）时：

- 以抖音反馈决定下一条做什么。
- 同步同一成片前，分别核对音乐的跨平台使用权、标题简介、封面与画幅、分区和 AI 声明，并查目标平台已有记录防重。
- 抖音发布表单里的跨平台勾选不等于其他平台投稿成功；不为同步擅自加长、重做或混算两平台指标。
- 各平台的最终提交仍按各自的提交分工执行，不建立无人值守的定时发布。

## 运营档案与待发队列

- 运营档案 `operations.json`：已确认的用户决定优先；栏目、昵称、简介等候选项不会自动变成用户已选事实。账号身份每次在现场核对。
- 待发队列 `content_queue.csv`：记录本次选定素材、栏目、画面/声音/权利核验、待补项和稿件路径。状态未知不能标 ready；`planned` 不是平台发布状态。不从整个私密目录里找素材补位。
- 主页置顶：准备“代表作、认识账号、系列入口”三类候选，优先已完成的作品，不为填满置顶而赶工或重发。
- 每条作品记录：最强停留点（画面或声音）→ 最大流失点 → 关注理由 → 优先改动。可以建议修改，不擅自剪辑或生成视频。
- 评论按“喜欢的细节 / 想看的内容 / 没看懂的地方”归类到 `audience_requests.csv`。只记真实留言、匿名记录；建议被做成作品后才能说“已采纳”。可以写回复草稿，发送回复需要用户具体授权。

## 证据分层

每条研究记录写：`observed_at / timezone / platform / region / source_url 或页面 / source_date / window / exact_label / value / scope`。

用户要近期信息时，默认优先近 7 天的作品，以近 30 天为主要研究窗口；后台取当次最新可用值，指数保留最新完整窗口的实际起止日期。这是内部筛选约定，不是平台规则。发布时间和抓取时间分开记；日期没核实的卡片不算近期样本；旧作品、旧报告单列为历史参考，不支撑“现在很热”的判断。近期证据不够就写“不足”，不用历史累计高赞补齐。

| 证据类型 | 怎么用 |
| --- | --- |
| 平台实测 | 后台指标注明“登录可见”，公开指标注明“公开”；等加载完成再记 |
| 公开案例 | 写原作品或可靠报道及截止时间；报价、商单不等于到账或利润 |
| 趋势线索 | 旧文章、缓存只作线索，不能当“今天的热榜” |
| 编辑判断 | 选题、评分、时段建议；不能说成推荐机制 |
| 用户决定 | 用户本次确认的内容，和建议分开记 |

对标作品至少保留：作品链接、栏目承诺、封面与开场、内容如何兑现、追更原因、已知商业证据和未知部分。学结构，不搬素材、声音、造型、标题，不逐帧复刻。

## 当次热点

### 来源与降级

按顺序尝试，前一个读不到就降级到下一个，并在发布包里记下实际用到哪一级：

1. **创作者中心**（已登录）：首页的热点、话题、活动、创作灵感等模块。入口见 [ui-notes.md](ui-notes.md#入口)。
2. **抖音热榜公开页**：https://www.douyin.com/hot 。可能要求登录或触发验证。
3. **巨量算数**：https://trendinsight.oceanengine.com/ 。通常需要登录。
4. **都读不到**：本条不挂实时热点，只用与作品强相关的**常青话题**，发布包写明“实时热点未核验：<原因>”。

遇到验证码、反爬或登录墙时，不绕过、不循环刷新：请用户登录或换下一级来源。不用旧文章或记忆里的“热点”冒充当天数据。

### 读数口径

- “猜你喜欢”是个性化推荐，不是全站热度。
- 热门话题的播放量是累计值，不是当天新增。
- 热点榜的“热度”不是播放量。
- 活动卡片出现不代表有参加资格。
- 以上不能互相换算或混加。加载中的 0、“暂无”、空卡片不能当最终数据。

抖音指数类数据：保留平台、地区、词语原文、统计周期，以及搜索指数/综合指数/热点指数等原字段名。对比词只在同一窗口、同一口径下比较；指数均值不等于搜索人数、播放量或某个话题能分到的流量。平台提示“暂不支持查询”的词记 `unavailable`，不填 0。创作指南里的类目消费分析只代表该类目和所选周期，不能把邻近类目的时长结论当成本账号的最佳时长。趋势报告要区分标题年份、实际发布日期、摘要和已读正文范围；旧报告可以支持创作方法，不能代表当日热度。

### 选词

- 核对词义和与作品的实际关联。活动要核时限、体裁、入口和组件。
- 填写时有平台候选就选对应词条；手打 `#` 不等于报名活动。
- 即时新闻和短期活动在**提交前**再查一次；普通热点 24 小时内或日期变化后重查（内部保鲜规则）。
- 常用 3–5 个强相关话题：制作类别 + 题材 + 系列或情境 + 0–1 个匹配的热点。这不是官方最优数量；示例写法如 `#AI创作 #治愈系 #<你的系列名>`，按真实作品选，不标“已验证热门”。

每个候选词写一条**兑现证据**：对应哪个可见物件、情境或已听过的声音；覆盖全片还是局部；希望吸引谁。

- ASMR、“听雨”这类承诺必须以人工听审过的声音细节为主要价值；白噪音、配乐、环境声不能互相替代，只有雨窗画面不能承诺“听雨”。
- 商品、手工、品牌词会吸引相应意图的观众，作品里没有实际展示就弃用。
- 生活、季节语境可以借，前提是作品里真的有对应内容（例：作品里真有冬季小吃才挂相关话题）。金价、体育、无关明星事件不因为热就挂上。

用户最后审核时可能改动已准备的话题；复盘以平台实际文案为准，不覆盖旧包，也不猜测是谁改的。

### 编辑评分（内部用）

素材匹配 0–40、受众 0–20、热点意图兑现 0–20、证据新鲜度 0–10、原创空间 0–10。素材匹配低于 20 直接弃用；总分 70 以上可用，50–69 备选，低于 50 弃用。侵权、误导、消费灾难或毫无关联的直接排除，热度再高也不抵消。这不是抖音的算法权重。

## 包装

- **标题**说具体的情境、选择或结果。工具名只有在制作解析里才是重点。没有完整步骤不写“教程”；AI 概念图不写成真实房源或实拍。
- **正文**：一句观看理由 + 一两个可见细节 + 可选的自然讨论。不每条都机械提问，不搞关注交换、点赞转运、虚假福利。“下期预告”必须能兑现。
- **视频**：封面用实际质量好的帧，字少、可读、避开平台界面遮挡。前两秒的吸引力看画面本身，不能靠文案补救空片头（见[成片检查](media-qa.md)）。剪辑修正和发布包装分开记录。
- **声音作为卖点时**，发布包加 `audio_promise`：动作声、环境声、BGM、独白各起什么作用，关键效果在哪个时间段兑现，听审状态和音乐权利。没有人工听审就保持 pending，不从语音转写、峰值或音乐署名推断听感。需要重混或重做时交给创作类 Skill（如 douyin-ai-creator-lab），不在发布环节擅自处理。
- **图文**：首图独立成立、引人向往，后续每张增加差异或细节；正文顺序与图片对应，不凑几乎重复的图。不把 AI 推测出的反向角度说成摄影事实。图上文字实际排版后检查。
- **无素材生成图文**：在用户明确要求时制作同系列 3–6 张左右，验图后才发布。不拿别人作品截帧充当原创，不调用视频生成。只是规划请求时先给制作计划。
- **口播**：讲自己实际做过的问题 → 修改 → 结果，展示前后对比和理由。字幕按真实声音核对；声音克隆另核授权。

## 复盘

记录：状态、发布时间及平台时区、栏目、时长或图数、首图或开头、文案版本、话题和活动、已知投放。按 24h / 72h / 7d 对齐作品年龄，不拿发布 2 小时的作品和 2 个月的累计数比较。

- **视频**看：2 秒跳出、5 秒留存、平均观看时长、完播。
- **图文**看：划走、平均浏览图数、收藏。
- **共同**看：分享、作品带来的关注、主页访问和具体的系列反馈。
- 只用后台实际开放的指标；缺失写 null 或未知，私密作品显示的 `-` 不是 0。

数据口径：

- 分别记录账号总览、单条累计、实时数据和每日更新数据的截止时间；截止日之前没发布的作品不能解释该时段的涨粉。
- 页面没显示时区时保存原文，作品年龄记为未知，不强行对齐。
- 不同模块的播放、完播、跳出、来源占比可能分母和更新时间不同，保留原值，不用一个模块的数反推另一个模块。来源表里没出现某入口不等于该入口流量为 0。
- 图表开放门槛只是数据可见条件，不是流量池规则；同类作者百分位不能代替留存和涨粉判断。
- 点赞率 = 点赞 / 播放；分享率 = 分享 / 播放；关注转化 = **作品吸粉量** / 播放；分母为 0 不计算。账号粉丝净增不能归因于某一条作品；总获赞也不是当前公开点赞之和；粉丝指数不是粉丝总数。

基线与实验：

- 用同栏目、相近时长、同龄作品的中位数做自己的基线，样本少时标“探索”。不存在固定的 200/500 流量池、万能 30% 完播率或黄金时段。可以测试午间或晚间，但要核对平台排期时区，用户说“今晚”按用户时区。
- 每批只改一个主要变量，给一个保留点和一个具体改动；同时换画面、标签、时间就无法归因。数据极少时不推断限流，先查审核、权限、开头和兑现；不默认删除隐藏、换号、刷视频养号或付费诊断。
- `metrics_snapshots.csv` 按作品 ID 追加：观察时间、作品年龄、指标原名、单位、值、分母、来源；拿不到写空值并注明原因。`experiments.csv` 记录主要变量、假设、可比基线、观察结果、保留点和下一条改动。
- 用户手动发布后的状态核对方法见 [publishing.md](publishing.md#用户手动发布之后)。

用户以后明确提出商业目标时，再另记有效咨询、成交和交付成本；没有“粉丝到多少自动转商业”的设定。不擅自建立定时监控。
