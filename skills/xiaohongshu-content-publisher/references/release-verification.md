# 一次提交、结果核验与发布记录

## 提交前与提交后

先查当前内容是否已有发布 ID／同标题同媒体作品或现有草稿。“下一个星座”依据当前管理记录和系列顺序确定，不根据旧计划机械重发。

有本次明确发布授权，且账号、媒体、正文、原创、AI、话题活动、可见范围和时间全部核验后，对最新 snapshot 中的真实最终按钮执行一次提交。立刻记录已点击／处理中；工具超时或按钮恢复不能单独证明未提交，应先查成功页、发布响应或管理列表。

核验按证据强度记录：

| 状态 | 所需证据与动作 |
| --- | --- |
| `draft` / `draft-verified` | 草稿已保存；后者还经过刷新重开并核对媒体和设置。不能称已发布。 |
| `submitted-once` | 本次最终按钮已点击；结果尚未确定。只读查证，不再次提交。 |
| `under-review` | 作品 ID／标题匹配，平台明确显示审核中；报告已提交、审核中。 |
| `published` | 平台实际状态明确为已发布，例如管理“已发布”列表中 ID／标题相符；记录核验时间。公开页面可访问本身不等于审核完成。 |
| `failed` / `needs-attention` | 平台明确失败，或证据仍不够；保留原包及具体原因，不擅自重发。 |

平台页面显示“发布成功”或 HTTP200 的响应只能按其真实语义解读。读取业务成功字段及真实作品 ID；错误码、失败正文或仅网络200不能叫成功。网络请求可用于补充核验，但不将隐藏接口直接写入作为替代提交方式。

平台仍明确显示“审核中”时优先记录 `under-review`，即使真实作品页面已经可以访问，也不能升级为 `published`。

成功后到笔记管理核对标题、封面、真实作品 ID、审核状态和时间。只在真实页面中找到链接后提供作品链接，不由 ID 拼一个未经验证的公开 URL。平台显示时间的时区未知时明确标注，不直接当作本地时间。

图文发布后尽可能检查该作品记录的图片数量及远程加载／尺寸；视频检查最终播放／时长和封面。加载通过不等于原文件 SHA256 或像素相同。若独立公开详情页未核验，只报告管理页和远程媒体的实际检查范围。

## 记录内容

发布包保留：

- 内容标题和正文、媒体顺序／封面、源文件的仓库相对路径及 SHA256；实际有必要时记录像素比对结果。
- 当次原创和 AI 状态、正式话题、活动及选择理由、公开／定时设置。
- 授权范围、保存／重开状态、最终提交次数、真实作品 ID 和当前状态；执行者为用户或代理。
- 核验时间和时区、成功／审核／已发布的具体证据、媒体加载结果与仍未验证的事项。

项目进度更新本次结果，避免新会话重复发布。个人账号详情和运行截图按项目约定留本地；若整理进 GitHub，使用必要的非敏感摘要及相对路径。绝不提交密码、Cookie、令牌、完整原始抓包、临时浏览器状态、签名 CDN URL 或本机网络配置。

用户只要求草稿时，交付还应指出保存位置、媒体／设置已验收范围及最后未执行的动作。用户已要求本条发布时，完成授权内的提交和核验，不把同一最终动作再次交给用户确认。

## 离线归档与 GitHub 验收

用户仅要求整理已有发布资料或传入 GitHub 时，读取现有发布包、媒体原件和已存证据，不创建线上草稿、不重新上传或改动笔记。历史发布状态与此次归档状态分开记录：例如历史笔记已发布，归档文件仍待核对／待提交／已推送；没有再次读取线上状态时，保留原核验日期，不能把归档日期写成新一轮发布验收日期。

归档前检查：

1. 标题正文、顺序、声明、作品 ID 和历史结果与证据相符；推断、未验收事项与实测事实区分。
2. 媒体保留原件，清单使用仓库相对路径；逐张核对源图文件 SHA256，检查相对文件链接能够解析。已有原图在同一仓库时可引用，不必复制一套相同大文件。
3. 检查本次拟上传文件，不含凭据、签名 URL、原始抓包、临时浏览器状态或本机网络配置；会话记忆与运行截图按项目的本地保留规则处理。
4. 查看 Git 差异并精确暂存本次文件，不打包无关修改、临时缓存或另一仓库的历史未推送提交。
5. 获得 GitHub 同步指令后执行真实提交和推送，再核验对应远端分支包含本次提交；未执行推送或推送失败时仅报告本地整理／提交完成，不称已上传 GitHub。记录仓库、分支与提交号，不修改仓库可见性或强制覆盖历史。

交付说明可复用规则入口、归档包入口、媒体所在位置、核对结果和真实 GitHub 同步状态。历史笔记已经发布不代表此次文件已入 Git，Git 推送成功也不代表重新发布了一篇笔记。
