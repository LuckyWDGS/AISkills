# 抖音与B站AI创作实验室

把「喜欢这条，想学着做」转成有证据的观察、自己的观看承诺、可试生的小样和下一条决策。AI是制作方式；栏目要让观众知道下次还值得看什么。不要从一条爆款直接替用户永久定赛道。

## 路由

- 对标、主页、相似作者、广告筛除、跨平台比较、为什么高赞：读[案例研究](references/case-study-method.md)。
- 不知方向、给参考图/提示词、首片、验片或复盘：读[小样与反馈](references/pilot-and-feedback.md)。
- 实际生图：使用当前可用的图像生成Skill。已安装image-generation-director/cm-imagegen时沿用用户路由偏好，真正生成并验图；工具不可用则交制作简报并明确图未完成。
- 实际视频提示词：使用ai-video-prompt-director及当次平台适配器；参考选择、导演意图先于平台语法。用户未明确平台且没有有效持续偏好时，只问一次平台。已选Muse而底层模型未显示时，沿用自然中文导演稿并记模型未知，不反复要求二选一H3/Seedance。
- 用户已授权用Muse生成、剪辑或修片：读[Muse制作与剪辑](references/muse-production-and-editing.md)，完成真实媒体和独立核验。仅研究/写提示词不触发生成；既有授权范围内的片长、单元与常规剪辑选择由Codex执行。
- 已有成片改画幅：读[Muse制作与剪辑的尺寸与导出部分](references/muse-production-and-editing.md#尺寸与导出陷阱)，按用户选定的保留画面、裁切或重新制作路线执行。
- 成片发抖音：使用douyin-ai-publisher及真实媒体、具体账号与当前授权。
- 已确定成片发B站：读[B站投稿核验](references/bilibili-publishing.md)，核实际表单、双比例封面、AI声明和提交状态。研究或建立全流程不等于发布任何未确定的成片。

在项目中先读AGENTS和当前进度。动态案例、账号数据、图片、成片和发布记录留项目；Skill只保存经实际使用支持的方法。不要把用户一个项目的画风、每镜时长或声音选择变成所有项目的要求。

## 研究到小样

1. 从用户作品定位原链接与作者，记录平台、地区、作品日期、观察日期和查看范围。分享口令日期不是发布日期。
2. 检查高赞、同类普通和近期作品，扩展到真正相近且有差异的作者。按唯一作品URL去重，先分离作品、推荐线索与广告卡；数量不能代替观看质量，推荐或自动连播不算完整观看。
3. 明确每条是完整视听、无声画面采样、仅元数据还是检索线索。没听到声音就不写曲名、对白、配器或听感；没看动态就不写完整运镜。
4. 用实际首屏、变化、切点、结尾与观众表达建立假设。高赞与普通都有的特征只能说明风格共性，不能解释爆款差异。不可见的播放、完播、投放和历史粉丝规模保持未知。
5. 先写观众能获得什么，再提少量差异清楚的原创方向；保留原作的功能性经验，改变具体空间、视觉母题、文案、节拍或进入方式。不要逐帧复刻或换个提示词就宣称原创。
6. 生成少量原创静态候选，帮助确定方向；用户已授权采用导演审美时沿用该决定。补本次需要的空间/身份资产，完成最小参考计划、导演稿、平台提示词、声音与后期计划、失败退路；风格采用不等于未知视角几何已锁定。
7. 按当前分工由用户或Codex取得实际视频，再验片、剪辑和交付。原片长度、计划片长、实际成片时长分开记；依据实际内容去重，不用空镜或冻结补足设计时长。先做一集再评估时，到该集交付和反馈为止；发布另按当前明确指令执行。

## 交付与判断

交付应让用户立即知道：建议先做什么、证据支持到哪里、下载哪张干净参考、复制哪段正文、怎样生成、成片怎样交回。只要完整提示词时，主提示词覆盖所要求时长，内部生产单元不能冒充主交付；要求代做成片时，主交付是可播放的实际视频和简明复盘，不必为了交一段长提示词限制合理分单元制作。文字多不代表完成，提了生图方案也不等于已有图片。

「为什么爆」写成 **可见证据 → 可能观看机制 → 反例/未知 → 原创试法 → 观察指标**。梦核可能同时带来向往、熟悉、孤独、不安与晕眩，不一律包装成治愈。避免把用户或作者自述的限流当平台事实，避免承诺流量池、必火标签或固定收益。

区分素材QA和市场验证：图片好看、模型成功、技术核验、直接听审、用户满意、作品发布和观众愿意追更是不同状态。只有转写/信号测量时，声音保持listening_pending；一部作品的声音认可不移植到另一部。视频仍由用户操作时不代提交；用户已明确授权某路线生成与剪辑时不重复确认同一分工，也不自动恢复其他暂停路线。用户未要求监控时不建立自动复盘或定时发帖。
