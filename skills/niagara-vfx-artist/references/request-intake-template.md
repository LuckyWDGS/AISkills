# 特效需求输入模板

## 用途

这份文档用于把模糊需求快速整理成可执行输入，减少因为关键条件缺失导致的返工。

适合在这些场景读取：
- 用户只给一句模糊描述
- 用户要完整方案，但条件还不全
- 需要先把需求补齐，再进入设计或实现

## 1. 使用原则

需求输入的目标不是问得越多越好，而是尽快拿到足够做判断的关键信息。

优先级顺序：

1. 效果类型
2. 使用场景
3. 平台
4. 时长 / 常驻与否
5. 视角与镜头距离
6. 艺术方向

如果这几项不清楚，后面的方案很容易偏。

---

## 2. 必要信息

### 1. 效果类型

先确认属于哪类：
- 命中
- 火焰
- 护盾
- 法阵
- 投射物
- 烟流
- 水流
- Portal
- Buff / Aura

### 2. 使用场景

例如：
- 角色技能
- 场景常驻
- 武器附着
- UI / HUD
- Boss 大招

### 3. 平台

必须明确：
- PC
- 主机
- Android / iOS
- 是否要低配版

### 4. 持续时间

要明确是：
- 瞬发
- 持续
- 循环常驻

### 5. 视角

要明确：
- 俯视
- 第三人称
- 第一人称
- Cinematic

### 6. 参考

如果有参考，优先级最高：
- 图片
- 视频
- 关键帧
- 已有游戏参考

---

## 3. 推荐补充信息

这些不是每次都必须，但非常有价值：

- 是否偏写实还是风格化
- 属性词：
  - 神圣
  - 黑暗
  - 科幻
  - 火
  - 冰
  - 电
  - 治疗
  - 毒
- 是否要和动画对齐
- 是否需要交互
- 是否必须可扩展成低配版
- 是否已有资产可复用

## 5. 缺条件时的默认假设

如果用户没有明确说明，可以先用下面这些默认假设推进：

- 平台默认：PC 优先，同时提醒是否需要移动端
- 视角默认：第三人称中景
- 时长默认：
  - 命中特效 = 短促
  - 场景火焰 = 持续循环
  - 护盾 = 常驻 + 命中反馈
- 风格默认：偏游戏可读性优先，而不是纯镜头级复杂度

这些默认假设可以推进工作，但必须在输出里明确写出来。

---

## 6. 输出前确认清单

在真正开始给方案前，先确认：

- [ ] 效果类型已明确
- [ ] 场景用途已明确
- [ ] 平台已明确
- [ ] 时长 / 是否循环已明确
- [ ] 视角和观看距离已明确
- [ ] 风格方向已明确或已做默认假设
- [ ] 是否有参考图已明确

---

## 一句话原则

好的输入模板不是为了问更多问题，而是为了尽快把需求补到“足够做正确技术路线判断”的程度。
