# 工具化与自动化思路

## 用途

这份文档用于沉淀哪些 VFX 生产环节值得做成脚本、Editor Utility、Python 工具或自动检查。

适合在这些场景读取：
- 团队开始规模化做特效
- 发现大量重复劳动
- 需要降低漏检查、漏命名、漏低配版等问题

## 1. 自动化的判断标准

一件事适不适合自动化，先看三点：

1. 重复率高不高
2. 人工漏掉的代价大不大
3. 规则能不能写清楚

满足这三条，就值得做工具。

---

## 2. 最值得自动化的检查

### 资产命名检查

适合自动化：
- 材质命名
- 材质实例命名
- 纹理命名
- Niagara System / Emitter 命名

### Flipbook / Atlas 检查

适合自动化：
- 分辨率
- 是否带 `_Flipbook` / `_Atlas`
- 是否符合指定格子数

### 低配版检查

适合自动化：
- 是否存在低配版资源
- 是否存在平台分版本

### Effect Type 检查

适合自动化：
- Niagara System 是否挂了 Effect Type
- 是否配置了 Scalability

### User Parameters 检查

适合自动化：
- 暴露参数数量
- 是否符合命名规则

---

## 3. 最值得自动化的生产流程

### 新建模板资产

可以自动做：
- 新建标准材质实例
- 新建标准 Niagara System
- 新建预设 Emitter

### 批量挂统一设置

可以自动做：
- 批量设置 Effect Type
- 批量设置命名
- 批量设置默认 User Parameters

### 生成检查报告

可以自动做：
- 命名报告
- 缺失资源报告
- 平台版本缺失报告

---

## 4. Editor Utility 方向

适合 Editor Utility 的：

- 批量重命名
- 批量创建材质实例
- 批量创建 Niagara 模板资产
- 批量设置标签 / 路径 / 统一参数

优点：
- 贴近美术工作流
- 团队使用门槛低

---

## 5. Python 工具方向

适合 Python 的：

- 扫描目录
- 资产规则检查
- 生成报告
- 批量校验纹理 / Flipbook
- 批量导出清单

优点：
- 更适合做离线检查
- 规则更容易程序化

---

## 6. 资产规范自动验证

下面这些很适合做自动校验：

- [ ] 命名是否符合规范
- [ ] 主材质是否存在实例
- [ ] Niagara System 是否挂了 Effect Type
- [ ] 是否存在低配版
- [ ] Flipbook / Atlas 是否命名清楚
- [ ] 关键参数命名是否符合 `S_ / V_ / T_ / SS_`

---

## 7. 自动化优先级

最优先：

1. 命名检查
2. Effect Type / Scalability 检查
3. 低配版缺失检查
4. Flipbook / Atlas 资源检查
5. 模板资产一键创建

---

## 一句话原则

最值得自动化的，不是“最酷的工具”，而是那些最容易重复、最容易漏、漏了最贵的环节。
