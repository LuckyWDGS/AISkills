# 2K 尺寸核查

本次统一请求 size=2560x1440、quality=max、output_format=png，并启用 require-exact-size。

本地 cm-imagegen 的 image_payload 将 args.size 原样写入 size；图生图 multipart 同样使用 args.size。save_image_from_item 解码后直接 write_bytes(raw)，没有本地缩放步骤。原图目录与 review 缩略图目录分开。

已返回的文生图原始 PNG 是 1536×1024；已返回的图生图原始 PNG 是 1672×941。其像素量均约 157 万，低于请求的 368.64 万像素；文生图的比例还从 16:9 变为 3:2。CLI 的 ok=false / image_size_mismatch 在这些请求中指尺寸不合格，并不表示没有返回图片。

2026-11-07 在线读取的 [OpenAI 官方 Image generation 指南](https://developers.openai.com/api/docs/guides/image-generation#size-and-quality-options) 明确说明 GPT Image 2.5 支持 WIDTHxHEIGHT 自定义尺寸、边长为 16 的倍数，2560×1440 是实验性更高分辨率的分界点。本次请求值符合其文档格式。指南的 2.6 章节说明省略 complexity 默认 high，但这不能证明兼容网关实际采用同一默认值。

可确认的范围：当前客户端确实请求了 2560×1440，收到的原始图像没有满足该尺寸。尚未取得本轮网关出站 JSON、已部署代码版本或经核验的上游模型身份，不能进一步断言是网关丢弃尺寸、上游限制，或模型映射导致。没有修改在线配置、换供应商或放大原图。

因此本次画质评分只适用于实际收到的低于 2K 的输出，不能包装成已经完成的原生 2K 能力对比。
