# Single-provider image API

Default and explicit `--api images`: POST `<configured_base_url>/images/generations` (JSON) for text-to-image, or `<configured_base_url>/images/edits` (multipart) for edits and references. For a base ending in `/v1`, these are `/v1/images/generations` and `/v1/images/edits`. Both explicitly set top-level/form `model: "gpt-image-2.6-sunburst"`, `quality: "max"`, and `complexity: "high"` by default. Edit uploads use the `image` file field and optional `mask` or `markup`, never both. The legacy `response_format` field is omitted by default.

GPT Image 2.5/2.6 Sunburst and Flare support `quality: low|medium|high|xhigh|max|auto`; `max` is the highest rendering-quality setting. GPT Image 2.6 additionally supports `complexity: low|medium|high`; `high` is the highest image-planning level, independent of quality. Preserve explicit overrides. Older models do not receive complexity automatically, and models outside these families do not receive quality automatically. Use `complexity` on Images, not `reasoning`, `reasoning_effort`, or `--responses-reasoning`. Requesting a value does not verify gateway passthrough or upstream execution.

Explicit `--api responses` remains available for requested conversational workflows: POST `<configured_base_url>/responses` with `stream: true`, a text controller in `model`, text/image `input` parts, and `tools: [{type: "image_generation", model: <image model>, ...}]`. Normal requests set `tool_choice: {type: "image_generation"}`. Custom `--tools` does not automatically force a tool; `--responses-extra` can override payload fields. The tool receives `action: generate` with size/quality and optional background/output_format; reference bytes are input_image data URLs. Controller reasoning is separate from image quality and applies only on this route.

Both APIs use the same configured provider and primary key. There is no automatic route switching. A model catalog listing does not prove image-generation access.

Decode base64 images or download returned image URLs to local files; parse SSE image_generation_call results and terminal evidence. A stream without an image result is an error, even when HTTP status is 200. Keep in-progress/uncertain jobs separate from confirmed failed terminal responses to avoid duplicate submissions.

Supported output is PNG/JPEG/WebP, animated GIF, and static SVG generation. See [formats-and-sizes.md](formats-and-sizes.md) for extra fields and compatibility limits. GIF frame fields are scalar JSON/multipart fields; SVG author selection is the nested `svg: {model, reasoning: {effort}}` object on generations. Boolean multipart values use JSON `true`/`false`. Unsupported combinations fail before catalog requests or image submission.

PNG dimensions can use the standard library; full raster decoding, GIF frame/timing checks, and markup transparency/orientation checks use Pillow. SVG XML is parsed without execution. An SVG viewBox alone does not establish output pixel dimensions. Exact-size checks fail closed when dimensions cannot be read. Four-K requests enforce exact size automatically. Files retain returned bytes and get an extension matching their detected format; no resizing, vectorization, animation assembly or format conversion is performed. Images SSE previews are excluded from final results, and a preview-only interrupted stream is not successful completion.
