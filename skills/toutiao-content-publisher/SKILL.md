# 今日头条图文发布助手

通过用户已登录的真实创作页面处理图文文章，分清正文插图、展示封面、草稿、提交和已发布。支持离线归档及只读效果复盘；不自动生图、生成视频或开启周期发布。

## 按本次请求选择入口

| 请求 | 执行范围 |
| --- | --- |
| 整理归档、整合流程、同步 GitHub | 读取既有文件与证据，离线整理；不访问后台、不创建草稿 |
| 检查发布状态、阅读量、效果如何 | 只读管理页与数据页，使用[效果复盘](references/performance-review.md)；不进入发布流程 |
| 准备文案、预览、保存草稿 | 做出可审阅发布包及草稿，不提交 |
| 明确要求发布本条或下一篇 | 查重并确定账号、内容、媒体后，完成本次一次最终提交与核验 |
| 用户说已自己发布 | 立即停止上传与提交；需要时只读核验，记为用户自行发布 |
| 微头条、图集、视频 | 不在本 Skill 范围；说明边界，最多交付文字与素材清单，不借文章流程上传 |

只检查某个平台时不顺带操作其他平台。安装、更新或整理本 Skill 本身不构成访问后台的请求；用户暂缓检查头条时保持暂缓。发布本条的授权不扩展为连续发文、修改旧文章、评论、私信、投流或自动监控。

## 图文执行

1. 先读项目规则与头条自己的台账，再只读查目标账号的已发布、审核中和草稿。按真实文章 ID、标题及素材交叉查重。“待核实”不等于未发布，“下一个”不能只按星座顺序或另一平台进度推定。
2. 按[正文、图片与页面设置](references/image-article.md)建立发布包：实际标题正文、有序源图及 SHA-256、每图职责、独立封面、声明和时间。缺图或目标不明时完成能做的部分，只解决具体缺口；不借用别组素材冒充齐套。
3. 按用户浏览器偏好选择当前实际可用的浏览器工具（优先已登录头条号的那个）。读取当前工具 schema、真实网址、可见账号和最新页面；通过页面自己的文件输入上传。工具没有上传等所需能力时交接发布包，不猜隐藏上传接口、不照抄历史元素 ID、不迁移 Cookie 或登录状态。
4. 正文插入后核对每图前后文字、实际加载、顺序和段落。正文与封面各自验收；选择文件、上传完成、确认插入是不同阶段。
5. 核设置、保存成功，从同一草稿刷新重开，滚动完整手机预览。检查全部正文图及封面；区分原文件、临时 blob、服务器保存预览及公开媒体。
6. 有本次具体发布授权且验收通过时，对真实最终按钮提交一次。立即记录提交动作；超时或返回结果不明时只核验原稿，不再次点击。
7. 按[结果与归档](references/results-and-archive.md)记录真实 ID、状态、核验时间、媒体检查范围及未完成项。明确区分已提交、审核中与已发布。

## 本用户的头条默认设置

来源于已归档的《十二星座庇护所》文章要求，用户后续明确选择优先；其他题材按本次内容适用性核对，不能硬套六图模板。

- A/B/C 比较正文按 A外→A内→B外→B内→C外→C内，段落与图对应；展示封面独立选三张，允许跨组。
- 开启“投放广告赚收益”，这是文章广告收益设置；不执行付费推广。当前账号或内容无资格时记录不可用，不修改账号配置。
- 实际使用 AI 素材时开启当前页面的“引用AI”或等义标识，正文说明虚构场景；不把效果图写成真实房产、旅行或入住经历。
- “头条首发”默认关闭，不作未获授权的独家承诺。不开启自动同步微头条／其他平台，不借用小红书的原创、活动或封面规则。
- 可见性、定时、位置、商业合作等按具体请求核对；没有安排的明确发布指令按立即发布核对。

## 故障与实测边界

登录、验证码与实名／资格校验由用户完成。浏览器不可连接、素材缺失或预览失败时保留原稿，说明具体阻碍；不杀浏览器、删除他人草稿或把历史网络修复当作修改代理／DNS 的指令。源码和通用记录不保存凭据、签名链接、真实后台数据或机器配置。

历史依据为 2026-10-09 双鱼文章的六图插入、独立三封面、手机及服务器保存预览、一次提交；最后可靠状态为审核中。历史记录不证明今天审核已通过、公开页可访问或本 Skill 已完成新一轮端到端发布。
