# 一次提交、真实结果与离线归档

## 查重与提交

先核对目标账号在头条的文章和草稿；标题可能改动，结合真实 ID、媒体和原记录判断。“历史有发布请求”或“台账没有收录”都不足以认定未发布。已有同稿时先核验，不新建替代品。平台未给 ID 的草稿保留标题、媒体指纹与保存证据，不伪造 ID。

内容、账号和本次发布授权明确，且正文、图片、封面、声明与时间验收通过后，记录准备提交状态，点击当前页面的最终提交按钮一次，立即登记已点击。多步确认界面以真正产生发布的最终动作为界；不把最终动作重试当作导航。

超时、按钮恢复、空白页或工具报错不能证明未提交。先查同一标题／ID 的成功页、文章管理及实际业务结果；状态未知保持待核验，不再次点击、不另建同稿。后续新发布必须有新的具体指令并先解决原提交状态。

## 状态与证据

| 状态 | 记录条件 |
| --- | --- |
| 本地准备完成 | 包和素材已核对，尚未创建线上草稿 |
| 草稿已保存 | 页面给出真实保存结果；刷新重开通过另记 |
| 已提交待核验 | 最终提交已执行一次，业务结果尚未确认；此后只读查证 |
| 审核中 | ID／标题匹配且平台明确显示审核中；报告已提交、审核中 |
| 定时待发 | 站点明确保存定时计划；不叫已公开发布 |
| 已发布 | 管理页明确显示该 ID／标题已发布，记录核验时间 |
| 失败／需处理 | 平台明确失败或证据不足，保留原稿与原因，不自动重发 |

HTTP200、文件上传成功或“操作成功”要结合业务语义、真实 ID 和管理状态。服务器预览能打开不证明审核通过；平台仍显示审核中时保留审核中。

提供作品链接前，从实际页面读取并验证链接用途，不由 ID 猜公开地址。管理页、服务器保存预览、独立公开页分别记验收范围；没有检查公开详情就明确未检查。平台显示时间的时区未知时保持未知，不强行转换为本地时间。

## 每条结果记录

- 平台及本次目标账号的本地核对结果、准确标题、正文或可靠原文入口。
- 原件相对路径／哈希及有序图片角色；展示封面三个位置与裁切。
- 广告收益、AI、首发、同步、时间与可见性等实际设置。
- 用户本次授权摘要、草稿保存／重开结果、最终提交次数、真实文章 ID／状态。
- 采集时间和时区、状态证据、实际媒体加载范围、未核实事项和下一步。

原文没有可靠副本时标出缺口。其他平台的同题文案或后来重写不能冒充历史原文；补档只读导出同一文章并注明日期，不再次发布。

## 离线整理与 GitHub

只要求归档、整合 Skill 或同步文件时复用既有文件与证据，不打开后台、不刷新线上状态。保留历史核验日期，整理日期不能变成新的发布证明。

核对相对链接、文件存在与 SHA-256，已有原图只引用一次。库存校验通过不代表缺图已补齐，也不代替逐张解码和视觉检查。项目已有库存脚本时先读取用途，默认执行只读模式，不借整理任务重建正常基准。

Skill 源码保存可迁移规则，项目档案保存选图与脱敏历史事实。后台指标、私人账号资料、截图、原始抓包和临时副本按项目规则留本地；不提交 Cookie、令牌、签名媒体链接、登录状态或网络配置。

有 GitHub 同步授权时精确暂存本次文件、审查差异、提交并推送，核验远端包含本次提交；不夹带用户其他改动，不强推。推送文件与线上发文是两个结果，分别报告。没有新发布或重新在线核验时不改写旧发布状态。
