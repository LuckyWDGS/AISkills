# 正文、图片与页面设置

## 发布包与素材职责

保留媒体原件。包中记录标题、正文、图片顺序与源路径／SHA-256、每张图的角色、独立封面及裁切、AI 等设置、授权和当前状态。仓库使用相对链接；临时上传目录不是长期素材位置。

对于本用户的星座三方案文章，顺序为 A 外景、A 内景、B 外景、B 内景、C 外景、C 内景。每组实际加粗小标题，外景描述后放外景，内景描述后放内景。缺哪张就记录哪张，不把模板数量当库存；其他类型文章按真实内容安排图片。

选定某组制作视频与发三方案比较文章相互独立。读者选择不撤销既定视频方向，图文成功不代表视频或声音已验收。

标题说明空间主题和读者价值，正文描述图中真实可见的光线、座位、材质等细节。没有展示的房间和路线不写成事实；不把星座性格写成必然规律。虚构空间明确写为 AI 场景设定，不对应真实建筑或地点。

## 正文插图

1. 读取页面当前格式、大小、张数限制，从最新 snapshot 定位正文工具和实际文件输入。
2. 把光标放在正确段落的插图位置，再选择相应原图。连接器限制本地路径时，仅在其明确允许的目录建立本次专用副本，核对文件 SHA-256；不改原图、不扩大文件访问权限，临时副本不进 Git，也不写成固定机器路径。
3. 工具返回文件已选不代表站点上传成功。等待站点上传完成、数量正确及“确定”可用，再确认插入。
4. 回到正文，核对图片实际可见、加载完成、自然宽高大于零，以及前后文字和组别正确。每图单独落实职责，避免重复图、漏图和文字被覆盖。

富文本必须回读实际自然段和加粗格式，不能把 Markdown 星号、工作备注、本地路径、占位说明留给读者。输入丢失换行时用当前工具支持的编辑方式修正，再回读。不要直接改框架内部状态或伪造平台成功结果。

## 独立三图封面

本用户默认三张不同的展示封面，可同组或跨组。选缩略图里主体清晰、对比适当的画面，逐槽回读三张实际落位及裁切；横幅裁切不能切掉主要窗景、座位或建筑。只有封面有图不代表正文有图。某槽未落位时只修复该槽，不重新上传整篇。

## 设置检查

| 项目 | 本用户默认与核验 |
| --- | --- |
| 投放广告赚收益 | 开启并回读；不可用时记录原因。与付费投流分开 |
| 引用AI／等义披露 | 按实际素材开启；正文保留准确说明 |
| 头条首发／独家 | 关闭；不承诺未经授权的独家期 |
| 同步微头条／其他平台 | 不主动开启；用户有本次明确安排才按范围处理 |
| 时间／可见范围 | 服从具体请求；无定时安排的发布指令核对立即发布 |
| 位置／商品／商业合作／合集 | 有具体意图和事实依据才配置 |

平台新增的声明或资格要求须读取当前含义，不能用小红书原创声明替代，不能绕过实际缺失的资格。

## 保存重开与媒体分层

保存后看到真实成功提示，从草稿箱重新打开同一篇，核对标题、段落、全部正文图、三个封面及广告／AI／首发状态。手机预览从头滚到尾，让懒加载图片进入视口；仅看首图或计数不能完成验收。

| 层级 | 可以证明的内容 |
| --- | --- |
| 原件与临时副本 SHA-256 一致 | 上传输入文件一致 |
| 编辑器的临时 blob 可见 | 当次本地编辑显示正常 |
| 草稿刷新重开 | 草稿可恢复；仍需识别图源是否为本地 blob |
| 服务器保存预览的远程图 | 当时服务器保存版本及媒体可读取；不证明审核通过 |
| 已发布记录／公开详情中的媒体 | 相应页面当时媒体可读；仍记录实际检查范围 |

尺寸、编码或文件哈希变化不自动表示传错图。只有做了实际解码像素比较才声称像素一致；远程加载通过不等于原件字节或像素未变。

若上传失败，先定位文件选择、上传、插入、保存或远程加载哪一层出错。保留已经成功的附件，不盲目整篇重传。HTTP400、ORB 或 CDN 错误不能单独证明代理／DNS 有问题。
