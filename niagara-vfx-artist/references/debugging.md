# Niagara VFX 调试与排错

## 用途

这份文档用于处理 Niagara 特效在制作和落地过程中常见的问题。

适合在这些场景读取：
- 用户说“效果不显示”
- 用户说“看起来不对”
- 用户说“性能太贵”
- 用户说“PC 正常、移动端不正常”
- 需要快速定位是 Niagara、材质、渲染、排序还是平台问题

## 1. 粒子不显示

### 常见原因

- Spawn Rate / Burst 为 0
- Lifetime 太短，刚生成就消失
- 粒子大小为 0 或接近 0
- Renderer 没加或类型不对
- 材质透明度为 0
- Bounds 不正确，导致被剔除
- 发射位置在镜头外
- 使用了不受平台支持的功能

### 快速检查项

1. 先看是否真的生成了粒子
2. 再看 Renderer 是否存在
3. 再看材质是否可见
4. 最后看 Bounds 和剔除设置

### 排查建议

- 临时把粒子颜色改成纯白高亮
- 临时把粒子大小拉大
- 临时关闭复杂材质，换成最简单的 Additive 测试材质
- 临时关闭某些 Update 模块，确认是不是某个模块把粒子“杀掉了”

## 2. 材质显示异常

### 问题：材质太黑或完全不亮

常见原因：
- Emissive 强度太低
- Blend Mode 不合适
- 颜色乘了过低的 Alpha
- 粒子颜色输入被错误覆盖

建议：
- 先只保留 Emissive 主链路
- 把强度临时提升到明显可见
- 检查 `Particle Color`、`Dynamic Parameter` 是否接错

### 问题：边缘太硬

常见原因：
- 遮罩太硬
- 没有做软边
- 噪声层次不够

建议：
- 增加 Soft Mask / SmoothStep / Depth Fade
- 降低 Alpha 对比度
- 在边缘加入少量噪声扰动

### 问题：过曝或太刺眼

常见原因：
- Emissive 过高
- 高亮区域面积太大
- Additive 层叠太多

建议：
- 控制高亮只出现在核心区域
- 把亮度峰值和亮区面积分开控制
- 多层 Additive 时注意总亮度叠加

---

## 3. 运动和时序异常

### 问题：效果看起来很僵硬

常见原因：
- 所有粒子参数完全一致
- 没有随机区间
- 曲线变化太线性

建议：
- 给 Size / Rotation / Velocity 加少量随机
- 使用更自然的曲线，而不是匀速变化
- 把运动拆成“生成 -> 扩张 -> 消散”三个阶段

### 问题：效果节奏不对

常见原因：
- Burst 数量和持续时间不匹配
- 生命周期过长或过短
- 曲线峰值时间点设置不合理

建议：
- 先确定总时长
- 再定义每个阶段占比
- 最后微调曲线峰值和拖尾长度

### 问题：拖尾不顺或断裂

常见原因：
- Ribbon 采样不足
- 源粒子生成不连续
- 宽度或透明度变化太极端

建议：
- 提高生成连续度
- 平滑控制 Ribbon 宽度
- 检查是否有突兀的速度变化

---

## 4. 排序与透明度问题

### 问题：半透明层穿插错误

常见原因：
- Translucent 排序天然有限制
- 多层半透明交叠
- 发射器间深度关系复杂

建议：
- 尽量减少大面积半透明层互相穿插
- 关键视觉层尽量拆清前后关系
- 能用 Additive 的地方尽量别全都用 Translucent

### 问题：特效把角色完全盖住

常见原因：
- 大面积高亮和高 Alpha
- 没做中心留白
- 特效体积层太厚

建议：
- 保证中心视线区域更透
- 外轮廓亮，中间适度克制
- 控制屏幕占比和持续时间

## 5. 性能超预算

### 高风险来源

- 粒子数过多
- 透明 overdraw 过大
- 材质采样太多
- 指令数太高
- Emitter 数量太多
- GPU / CPU Sim 用错场景

### 排查思路

先分清楚贵在哪里：
- 是粒子数贵
- 还是材质贵
- 还是透明覆盖贵
- 还是系统数量贵

### 优化优先级

1. 先砍看不见的粒子
2. 再降透明覆盖面积
3. 再简化材质采样和节点
4. 再减少 emitter 数量
5. 最后再考虑更高级的技术替代

### 常见优化动作

- 减少 Spawn Rate / Burst
- 缩小粒子尺寸
- 缩短生命周期
- 降低材质层数
- 合并相似发射器
- 增加 LOD 和距离剔除

---

## 6. 平台差异问题

### 问题：PC 正常，Android 丢效果

常见原因：
- GPU Compute 在移动端不稳定或不支持
- 材质过复杂
- 纹理过大
- 折射、复杂透明或高级节点代价太高

建议：
- 优先切换到 CPUSim 版本验证
- 改用更简单的 Additive 材质
- 降低纹理分辨率
- 删除高成本效果，换成假效果

### 问题：不同设备表现不一致

常见原因：
- GPU 差异大
- Vulkan / OpenGL 路径不一致
- 性能预算设置不够保守

建议：
- 做清晰的高低配分层
- 设置保守的默认值
- 对移动端采用“先能稳定显示，再谈精致”的策略

## 7. 建议排查顺序

遇到问题时，推荐按这个顺序查：

1. 是否生成了粒子
2. Renderer 是否正确
3. 材质是否基础可见
4. 粒子尺寸 / Alpha / 生命周期是否合理
5. Bounds / Culling 是否错误
6. 是否存在排序或透明度问题
7. 是否是平台限制或性能降级导致

### 快速检查清单

- [ ] Spawn Rate / Burst 不是 0
- [ ] Lifetime 不是过短
- [ ] 粒子 Size 不是 0
- [ ] Renderer 已添加且类型正确
- [ ] 材质能在最简状态下显示
- [ ] Alpha 没被乘到接近 0
- [ ] Bounds 合理，没有被错误剔除
- [ ] 相机位置能看到发射区域
- [ ] 平台支持当前模拟方式和材质复杂度

### 材质异常检查清单

- [ ] Blend Mode 是否正确
- [ ] Emissive 是否足够亮
- [ ] 是否误用了过低 Alpha
- [ ] `Particle Color` 是否接反
- [ ] 纹理采样是否正常
- [ ] 是否有过强的 Clamp / Power 让结果失真

### 性能问题检查清单

- [ ] 粒子数是否超预算
- [ ] Overdraw 是否明显过大
- [ ] 材质采样次数是否过多
- [ ] 指令数是否过高
- [ ] Emitter 数量是否可以合并
- [ ] 是否已有 LOD / Distance Culling
- [ ] 是否该做移动端回退版

### Android / 移动端检查清单

- [ ] 优先验证 CPUSim 版本
- [ ] 材质是否控制在低复杂度
- [ ] 纹理是否降到合理分辨率
- [ ] 是否避免了高成本折射
- [ ] 是否避免了过多半透明层叠
- [ ] 是否在中低端机思路下设计预算

## 常用实战策略

### 做最小可见版本

先做一个“肯定能看到”的极简版本：
- 单一 emitter
- 单一材质
- 纯白高亮
- 大尺寸
- 简单 Additive

如果这个版本能工作，再逐层把复杂度加回来。

### 一次只改一个变量

排错时不要一次改很多设置。

更好的方式是：
- 先固定材质，只改 Niagara
- 再固定 Niagara，只改材质
- 再验证平台差异

### 保留低配回退方案

高质量方案之外，最好始终准备一个低成本回退版本，尤其是：
- Android
- 大场景群战
- 屏幕上多个特效同时出现

### 从“能看到”到“能用”再到“好看”

推荐按这个顺序迭代：

1. 先确认特效能稳定显示
2. 再确认节奏、可读性和命中位置正确
3. 最后再加细节、噪声、折射和更贵的表现

这样能避免在基础错误没解决前，把问题藏进复杂效果里。
