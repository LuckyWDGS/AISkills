# 特效验收与 QA 手册

## 用途

这份文档用于把“效果做完了没有”变成一套可执行的验收标准。

适合在这些场景读取：
- 效果已经完成第一版，需要系统验收
- 需要区分“能看”和“能交付”
- 需要建立统一 QA 标准
- 需要做平台和镜头条件下的最终确认

## 1. 验收目标

验收不是再做设计，而是确认：

1. 读得懂
2. 跑得动
3. 接得上
4. 平台能用
5. 低配可交付

如果这五条里有任何一条不成立，这个效果都不算真正完成。

---

## 2. 近景 / 中景 / 远景检查

### 近景

检查项：
- [ ] 细节是否成立
- [ ] 主层和辅层是否还分得开
- [ ] 是否有明显贴图感 / 黑边 / 破边问题

### 中景

检查项：
- [ ] 主信息是否最清楚
- [ ] 次级层是否还服务主信息
- [ ] 节奏是否还能读出来

### 远景

检查项：
- [ ] 一眼还能认出是什么效果
- [ ] 核心轮廓是否还存在
- [ ] 远看是不是只剩一团模糊亮点

### 结论规则

如果一个效果：
- 近景好看
- 远景读不懂

那它还不算通过。

---

## 3. 亮背景 / 暗背景检查

### 亮背景

检查项：
- [ ] 主轮廓仍可见
- [ ] 不会因为背景亮导致边界消失
- [ ] 颜色对比还够

### 暗背景

检查项：
- [ ] 不会整体过爆
- [ ] 高亮区域面积受控
- [ ] 不会糊成一片白 / 一片亮色

### 结论规则

至少要做：
- 一次亮背景检查
- 一次暗背景检查

否则验收不完整。

---

## 4. 同屏多特效检查

很多效果单独看没问题，但同屏就崩。

### 检查项

- [ ] 3 个同类效果同屏时是否仍清晰
- [ ] 5 个同类效果同屏时是否还能接受
- [ ] 会不会把角色和目标点完全盖住
- [ ] 多个效果叠加后是否失去主次

### 典型失败信号

- 单个效果高级，同屏一团乱
- 辅层数量太多
- 残留太长
- 透明覆盖过多

---

## 5. 平台版本检查

### PC 版

检查项：
- [ ] 质量版完整成立
- [ ] 英雄层和细节层都正常

### Android / 低端版

检查项：
- [ ] 已有减配版本
- [ ] 核心识别层仍保留
- [ ] 删减后不会变成“完全不是那个效果”
- [ ] 成本明显下降

### 结论规则

如果目标平台包含低端或移动端：
- 没有低配版，就不能算交付完成

---

## 6. 动画挂接检查

如果效果需要和角色动作、武器动作、技能释放配合，必须验这一项。

### 检查项

- [ ] 起始时机正确
- [ ] 峰值是否和动作最重帧对齐
- [ ] 结束是否拖尾过长
- [ ] 循环类效果启停是否自然

### 典型失败信号

- 动作已经结束，特效还在主输出
- 峰值早了或晚了
- 武器已经挥到位，特效才出现

---

## 7. 性能验收

### 检查项

- [ ] 粒子数量在预算内
- [ ] Emitter 数量合理
- [ ] 材质采样没有失控
- [ ] Overdraw 可接受
- [ ] LOD / Culling 已设置

### 额外规则

- 单个效果能跑不代表通过
- 必须看同屏情况

### 典型失败信号

- 近景还行，群战直接爆
- 视觉收益最低的层反而最贵

---

## 8. 可读性验收

### 检查项

- [ ] 第一眼能认出效果属性
- [ ] 主视觉点明确
- [ ] 不遮挡关键 UI / 角色轮廓
- [ ] 爆发 / 命中 / 结束节点清晰
- [ ] 远距离仍可识别

### 审核标准

把效果放进真实关卡后问：

- 玩家不暂停、不慢放，能看懂吗？

如果答案不稳定，就还没通过。

---

## 9. 最终通过标准

一个效果要算真正通过，至少要满足：

- [ ] 近景成立
- [ ] 远景仍可读
- [ ] 亮背景和暗背景都成立
- [ ] 同屏多个效果时不崩
- [ ] 目标平台可跑
- [ ] 动画 / 触发时机正确
- [ ] 有低配版时，低配仍保留核心识别

---

## 一句话原则

验收的本质不是“我自己觉得差不多了”，而是：

在真实镜头、真实场景、真实平台和真实同屏压力下，这个效果还能稳定地被读懂并且可交付。
