# Niagara VFX Android / 低端机落地清单

## 用途

这份文档专门用于 Android 和低端硬件上的 Niagara 特效落地检查。

适合在这些场景读取：
- 用户明确说目标平台是 Android / 移动端
- 需要把一个 PC 方案压缩成可上线的移动端版本
- 需要做上线前自检
- 需要快速判断一个效果“能不能上移动端”

这份文档不是讲视觉创意，而是讲“移动端能不能稳定、便宜、可读地跑起来”。

## 1. 目标原则

移动端特效要优先满足这几个目标：

1. 先稳定显示
2. 再保证可读性
3. 再控制性能预算
4. 最后才追求更多细节

简单说就是：

能看到 > 看得懂 > 跑得动 > 更华丽

如果一个效果在移动端必须靠高采样、高透明叠层、复杂折射才能成立，那通常就不适合直接照搬。

---

## 2. 上线前总检查

这是最推荐的上线前总清单：

- [ ] 目标设备档位已明确
- [ ] 已有移动端专用版本，不直接复用 PC 版
- [ ] 粒子数量在预算内
- [ ] Emitter 数量在预算内
- [ ] 材质复杂度在预算内
- [ ] 纹理分辨率合理
- [ ] 透明 Overdraw 没有明显失控
- [ ] 已配置 LOD 和距离剔除
- [ ] 同屏多个特效时仍可接受
- [ ] 低端机上也能保底显示

如果这里有 3 项以上打不了勾，通常说明这个效果还不适合直接上线移动端。

---

## 3. Niagara 系统检查

### 推荐做法

- [ ] 优先使用 `CPUSim`
- [ ] 每个效果尽量少 Emitter
- [ ] 粒子数从“够看”开始，不从“最好看”开始
- [ ] 生命周期不要过长
- [ ] Burst 规模控制在可读范围内
- [ ] Fixed Bounds 已启用
- [ ] 没有无意义的持续 Spawn

### 经验建议

**低端机**
- 粒子数: 300 - 1000
- Emitter 数: 1 - 2

**中端机**
- 粒子数: 1000 - 2500
- Emitter 数: 2 - 3

**高端机**
- 粒子数: 2500 - 5000
- Emitter 数: 3 - 4

### 优先删除什么

当性能不够时，建议优先删：

1. 点缀粒子
2. 次级烟雾层
3. 额外高光层
4. 非核心 Emitter

不要先删最核心的识别层。

## 4. 材质检查

### 推荐做法

- [ ] Shading Model 使用 `Unlit`
- [ ] 优先 `Additive`
- [ ] `Translucent` 使用克制
- [ ] 避免复杂 HLSL
- [ ] 避免动态分支
- [ ] 采样次数尽量少
- [ ] 同一材质里不要堆太多层效果

### 材质预算建议

**低端机**
- 指令数: < 30
- 纹理采样: 1 - 2

**中端机**
- 指令数: < 50
- 纹理采样: 2 - 3

**高端机**
- 指令数: < 80
- 纹理采样: 3 - 4

### 适合移动端的材质思路

- 单层 Additive 发光
- 单层灰度噪声扰动
- 单层 Fresnel
- 简单 Panner 流动
- 简化的径向渐变

### 不适合优先上的内容

- 高成本折射
- 多层透明叠加
- 多张纹理频繁采样
- 复杂 Flow Map 依赖
- 很重的屏幕空间效果

---

## 5. 纹理检查

### 推荐做法

- [ ] 尽量使用 512 或更低分辨率
- [ ] 纹理数量尽量少
- [ ] 一张纹理承担多个用途时优先考虑通道打包
- [ ] 无缝噪声优先灰度图
- [ ] 不要为了移动端效果使用超大贴图

### 分辨率建议

**低端机**
- 128 - 256 为主

**中端机**
- 256 - 512 为主

**高端机**
- 512 可接受，少量 1024 需谨慎

### 检查清单

- [ ] 是否有 1024 以上但视觉收益很小的纹理
- [ ] 是否能用一张噪声替代两张噪声
- [ ] 是否能做通道打包
- [ ] 是否能把彩色贴图改成灰度 + 参数着色

---

## 6. 透明度和 Overdraw 检查

移动端最容易被杀性能的通常不是“单个粒子复杂”，而是“大量半透明覆盖屏幕”。

### 检查清单

- [ ] 大面积烟雾没有长期覆盖屏幕中心
- [ ] 不存在多层大透明片反复叠加
- [ ] 核心特效区域之外没有过度铺满
- [ ] 屏幕上同时出现多个相似透明效果时仍可接受

### 优化建议

- 把大面积透明改成更小、更集中
- 减少烟雾层数
- 减少大尺寸粒子
- 缩短高覆盖阶段的持续时间
- 能用更硬一点的边缘时，不要过度追求超软透明

---

## 7. LOD / Culling 检查

### 必做项

- [ ] 已设置距离剔除
- [ ] 已设置低中高质量档位
- [ ] 远距离版本明显更轻
- [ ] 次要特效比核心特效更早剔除

### 推荐范围

**低端机**
- Max Distance: 800 - 1200

**中端机**
- Max Distance: 1200 - 1800

**高端机**
- Max Distance: 1800 - 2500

### LOD 设计建议

LOD 0:
- 保留核心层
- 删除次级装饰层

LOD 1:
- 粒子数减半
- 材质细节减半

LOD 2:
- 只保留最核心识别层

---

## 8. 多特效同屏检查

单个效果能跑，不代表“游戏里真实同屏”也能跑。

### 必查问题

- [ ] 3 个同类特效同屏是否稳定
- [ ] 5 个同类特效同屏是否还能接受
- [ ] 特效和 UI、角色、场景特效叠加时是否 still readable
- [ ] 群战时是否需要自动降级

### 推荐策略

- 群战时降低 Spawn Count
- 群战时关掉次级粒子层
- 群战时降低烟雾和拖尾持续时间
- 群战时优先保留命中识别，不保留装饰层

---

## 9. 不同档位建议

### 低端机

策略：
- 极简版本优先
- 以识别性为第一目标
- 粒子少、层数少、贴图小

建议：
- 1 - 2 个 Emitter
- 1 - 2 张小贴图
- 单层 Additive 优先
- 少烟雾、少拖尾、少残留

### 中端机

策略：
- 在可读性基础上增加少量细节

建议：
- 2 - 3 个 Emitter
- 2 - 3 张贴图
- 可以有少量次级粒子
- 烟雾和拖尾要有，但要克制

### 高端机

策略：
- 保留更多层次，但仍然不能直接照搬 PC

建议：
- 3 - 4 个 Emitter
- 可以有更好的流动和边缘细节
- 可以接受中等复杂度材质

---

## 10. 红线清单

下面这些情况通常说明这个效果还没准备好上 Android / 低端机：

- [ ] 只有 GPU Sim 版本，没有 CPUSim 备选
- [ ] 没有距离剔除
- [ ] 材质严重依赖复杂 HLSL
- [ ] 大量使用折射
- [ ] 大量大尺寸半透明粒子同时覆盖屏幕
- [ ] 没有低配回退版
- [ ] 单个效果好看，但多个同屏就爆
- [ ] 只有开发机测试，没有在目标档位设备上验证

---

## 一句话执行规则

如果你时间紧，只记住这一条：

先做一个移动端能稳定显示、看得懂、成本低的版本，
再决定哪些细节值得一点点加回来。
